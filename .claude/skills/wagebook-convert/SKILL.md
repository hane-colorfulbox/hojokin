# 賃金台帳変換スキル（CC＝Claude Code 用）

## 0. このスキルが扱うタスク

PDF（または既存JSON）の賃金台帳を、補助金書類作成ツールが読める **規格 Excel** に変換する。
出力ファイルは案件 Drive にアップロードされ、ツール側で R215/R216 の算定に使われる。

### 0.0 作業前チェック（前提条件・インストール健全性）

**着手前に必ず確認する。ここを飛ばすと「動いたが規格外の成果物」が出る。**

**パス解決（最初に確定する）**：この文書内の `{SKILL_DIR}` ＝ **この SKILL.md が置かれているフォルダ**。設置場所は3通りありうる：
- ① 引き継ぎパック同梱 `<補助金フォルダ>/.claude/skills/wagebook-convert/`（**現行の標準**。パック解凍で自動配置）
- ② グローバル `~/.claude/skills/wagebook-convert/`（パック外でも使う場合のみ）
- ③ 開発リポジトリ内

テンプレート・verify スクリプトのパスは必ず `{SKILL_DIR}` 起点の **絶対パス** に解決してから使う（cwd が案件サブフォルダだと相対パスは解決しない）。

1. **Python3 + openpyxl が必須**（xlsx の生成・検算に使用。フォールバック無し）。開始時に
   `python -c "import openpyxl"`（WSL 環境なら `wsl python3 -c "import openpyxl"`）で確認する。
   - 未導入なら `pip install openpyxl`（WSL は `pip3 install openpyxl --break-system-packages`）で導入してから進む。
   - **Python が全く無い環境では生成できない** → ユーザーに環境準備（Python 導入）を依頼して停止。
   - **PyMuPDF（fitz）は任意・推奨**：§4.1 例外の座標抽出フォールバック、§8 の画像PDF判定・TKC PX2 形式で必要。
     `python -c "import fitz"` で確認、無ければ `pip install pymupdf`。
     未導入でも標準経路（Read multimodal＋openpyxl）と xlsx 生成・verify は動く（必須は openpyxl のみ）。
2. **スキル同梱ファイルの存在確認**：`templates/賃金台帳テンプレート.xlsx` と `review/verify_wagebook.py`
   がスキルフォルダにあるか確認する。
   - **どちらかが無ければ導入が不完全**（古い/部分展開の ZIP）。この状態で **xlsx をスクラッチ自作してはいけない**
     （ヘッダー手書きで規格を外し、ツールが読めない成果物を出す事故が起きた）。
   - 対応：**停止して**復旧してから再実行する。スキルは引き継ぎパック（`hojokin-handoff.zip`）に同梱されているので、
     (a) Claude Code に「引き継ぎを最新に更新して」と依頼する（`scripts/update_handoff.py` が
     `.claude/skills/wagebook-convert/` を丸ごと最新に入れ替える）、または
     (b) `hojokin-handoff.zip` を再ダウンロードし、補助金フォルダ直下に上書き展開する。
     グローバル設置（`~/.claude/skills/`）の場合のみ `wagebook-convert.zip` での上書き展開。
   - どうしても今すぐ進める場合のみ、§1 の「🔴 ヘッダー注記禁止」を厳守し、§5.5 verify ゲートも必ず通す。

### 0.2 Skill が判断できない事項（ユーザー側で確定すべき）

以下は Skill 単体では確定できないので、ユーザー（顧客への確認含む）が判断する：

- **PDF 期間と事業年度の不整合**：PDF が暦年データだが事業年度が事業年度ベース（例：4月決算で PDF が令和7年=暦年）の場合、不足月を別 PDF で補うか、暦年データで代用するかの判断
- **履歴事項証明書の役員が賃金台帳に登載されないケース**：役員給与が別管理か無報酬か（B 列警告メモを残すので顧客確認）
- **手書き PDF の判読困難**：1〜2 ページ精読時点で読み取れないと判定したら **作業を停止して** ユーザーに代替ソース（給与計算ソフトの集計 CSV、高解像度スキャン、人手転記）を打診する（§4.4）
- **期中の空欄が「退社」か「休職」か**：PDF に退職年月日記載がない場合（§1 参照）
- **同姓・低額一定者の最終的な役員判定**：§2.1 ステップ 2 で警告メモを残すが、確定は顧客確認
- **賞与の年度帰属（非暦年決算で支給月が台帳に無い）**：どの回が事業年度の窓内かは Skill 単体では確定できない。**法人 R216 の正式ソースは勘定科目内訳明細書（人件費内訳）**。支給年月の指示 or 内訳明細書で確定する（会議 2026-06-04 決定：賞与支給月を AI に当てさせず、人が指示 or 決算書を参照）。詳細手順は §4.1.1-a の「非暦年決算の賞与帰属ガード」
- **対象となる全月在籍者が0名になるケース**：①役員のみの法人（非役員従業員0名）／②設立間もない等で全員が在籍12ヶ月未満。この場合は給与支給総額(R216)・従業員数(R215)が賃金台帳だけでは確定できない。**役員報酬・役員数ベースで算定するか**は公募要領 p.10 の特例（「従業員を雇用していない法人は…役員と読み替え…役員報酬と役員数に応じて算出」）の適用可否の判断であり、①は適用可、②は文言上グレー（事務局確認推奨）。Skill は xlsx を作れる範囲で作り、報告でこの旨を明示する（§9.1）。

## 1. 変換先テンプレート

`templates/賃金台帳テンプレート.xlsx`（このスキル同梱）をコピーして使う。

出力ブックの構成：「従業員別明細」（算定用の正本）＋「記入ルール」（テンプレ由来）＋「**原本転記**」シート群（表紙「原本転記」＋ページ別「原本転記_pN」。PDF **全ページ・全項目** 転記の確認用。§4.1.2 で必ず追加する。2026-07-21 決定／2026-07-26 全項目・ページ別化）。

### ヘッダー仕様（従業員別明細シート、5行目）

| 列 | セル | 項目 | 必須 | 値の例 |
|---|---|---|---|---|
| B | B5 | No | ◯ | 1, 2, 3, ... |
| C | C5 | 氏名 | ◯ | 山田太郎 |
| D | D5 | 雇用形態 | ◯ | 正社員 / パート・アルバイト / 役員 |
| E | E5 | 月間平均時間 | **★パート必須★** / 正社員・役員は任意 | 160（パート・アルバイトでは必須。R215 FTE換算用） |
| F | F5 | 時給 | **★パート必須★** / 正社員・役員は任意 | 1200（パート・アルバイトでは必須。最低賃金判定・FTE換算検証用） |
| G〜R | G5〜R5 | 1月〜12月（ツール出力は和暦年月で事業年度順）| ◯ | 各月の **課税支給合計（賞与は含めない）**（円、整数）|
| S | S5 | 年間通勤手当 | △ | 36000（非課税通勤手当の年間合計。**⚠ 月列に「課税支給合計」を入れた場合は空欄。埋めると二重控除で R216 過小。§3.1**）|
| T | T5 | 年間賞与 | △ | 700000（課税賞与の年間合計。**月セルには混ぜず**ここに。ツールがR216に算入。§4.1.1）|

データ行は **B6 以降**。支給がない月は **空欄**（0 は禁止、「中途入社/退社/休職」を意味する）。

> 🔴 **ヘッダー行（5行目 G〜R）の月見出しは絶対に注記しない**（最重要・非自明・実事故あり）。
> テンプレ既定の「1月」..「12月」、または和暦「令和N年M月」**だけ**にする。
> `1月\n(R7.1)` のような注記を付けると、ツール側の月ヘッダー解析（`parse_ym_header`）が月を
> 抽出できず、ツールが台帳を **0名と誤読** して R215/R216 が空になる（実案件で発生）。
> 事業年度の対応（どの列がどの年月か）は **B2/B3 の注記セルに書く**（ヘッダーセルには書かない）。
> テンプレを `load_workbook` でコピーすれば見出しはプレーンなまま → **§4 の書き込みで 5 行目は上書きしない**のが安全。

**E列・F列が「パート必須」の根拠**：デジタル化・AI導入補助金2026 通常枠 公募要領 p.10「パートタイム従業員については、正社員の就業時間に換算して人数を算出すること」+ 交付申請マニュアル p.86 算定例「週20時間勤務 ÷ 週40時間労働 = 0.5(人)」。E列が空欄のパートが含まれていると R215 が過大計上される（FTE = 1.0 サイレント昇格）。

**パート時間が取得できない場合の処理**：
1. **第一優先**：顧客に「パート・アルバイトの月平均労働時間と時給」を再依頼する（賃金台帳テンプレートの E列・F列を埋めてもらう）
2. **第二優先（やむを得ない場合）**：E列空欄のまま進める。ツールは FTE = 1.0 として算入し、変換メモシートに「⚠ パート時間欠落 N名、R215 過大計上の可能性」警告を残す。ユーザー（社内担当者）に注意喚起

**期中の空欄が「退社」か「休職」か判別する手順**：
1. PDF の各社員ページに **退職年月日** 欄があるか確認 → 記載があれば「中途退社」確定
2. 退職欄が空欄かつ期中の空欄期間がある場合は「休職復帰」の可能性 → ユーザーへの完了報告で要確認事項として明記
3. xlsx 上の扱いはどちらの場合も **空欄のまま**（0 ではない）。ツール側で支給>0でない月がある＝全月在籍でないと判定され R215/R216 から自動除外される（休職復帰者も含めるべき場合はユーザーが手動で修正）

### 1.1 月列の意味（**最重要・落とし穴 ①**）

> 注：12月決算（事業年度＝暦年 1〜12月）の会社では事業年度ズレが発生しない。それ以外の決算月（3月・4月・6月・9月等）でのみ注意。

G〜R 列の「1月〜12月」は **暦年の1月〜12月ではなく、対象会社の「直近事業年度」の12ヶ月** を入れる。
xlsx のセルラベルは **カレンダー月のまま**、値は **事業年度の各月の支給額** をカレンダー月の位置に入れる。

例：4月決算 → 直近事業年度＝2024年5月〜2025年4月

| xlsx 列 | 入れる値 |
|---|---|
| 1月 | **2025年1月** の支給額 |
| 4月 | **2025年4月** の支給額（事業年度の最終月） |
| 5月 | **2024年5月** の支給額（事業年度の開始月） |
| 12月 | **2024年12月** の支給額 |

**直近事業年度の判定**：申請時点で決算が確定済みの最新事業年度。決算月+2〜3ヶ月で確定するのが一般的。迷ったら **顧客 Drive に置かれている最新の決算書 PDF が対象する事業年度** が直近、と判定する。

#### 1.1.0 月の位置を絶対にずらさない（**落とし穴 ①の本体・最頻出事故**）

各月の支給額は、**必ずその支給月のカレンダー列に置く**。途中に支給のない月（空欄）が
あっても、**後続の月を詰めて左／右へずらしてはいけない**。PDF の並び順に左から詰めるのではなく、
「この行のこの月の値」を「xlsx のその月の列」へ **1セルずつ対応付けて** 転記する。

❌ 実案件で発生した事故パターン：ある月が空欄だと、それ以降の月を1つずつ詰めてしまい全部が
   1ヶ月ズレる。さらに末尾の2ヶ月を1セルに合算してしまう。

| | 1月 | 2月 | 3月 | 4月 | 5月 | 6月 |
|---|---|---|---|---|---|---|
| 正（PDF） | A | （空） | B | C | D | E |
| ❌誤（左詰めズレ） | A | B | C | D | **D+E合算** | （空） |

✅ 正しい置き方：2月に支給がなければ **2月セルは空欄のまま**、3月の値は3月セルへ。

**なぜ年間合計検算（§5-A）では捕まらないか**：月をずらしても **年間合計は変わらない**。
実案件で、正しい配置とズレた配置の年間合計が **完全に一致した**（どちらも同額）ため、
社員ごとの年間合計照合を素通りした。→ ズレ検出には **§5 の月単位検算が必須**（特に
途中に空欄月がある社員）。

#### 1.1.1 月列ラベルから決算月を逆算する（ユーザー指定が仮で不安なとき）

ユーザーから決算月を仮で渡されたが PDF と整合するか不安な場合、**PDF 最初のページに印字されている期間表記から決算月を逆算**できる：

- 賃金台帳 PDF の年間集計表の月列が「**令和6年12月 → 令和7年11月**」のように 12 ヶ月並んでいる場合
  → 先頭月 = 事業年度開始月（決算月 + 1）→ **決算月 = 11月**
- 期間表記が「**2024年4月1日 〜 2025年3月31日**」のような場合
  → 終了月 = **3月決算**

ユーザー指定の決算月と PDF 期間がズレている場合は、**xlsx を生成する前に** ユーザーに通知して確認を取る（例：TKC 形式は暦年データで出力されるため、6月決算等の事業年度後半 6 ヶ月が PDF に存在しない構造になる。xlsx 生成前にゲートすべきケース）。

#### 1.1.2 PDF 期間と事業年度の不整合（落とし穴）

PDF が **暦年単位**（令和7年 = 2025年1月〜12月）で出力されているが、事業年度が暦年でない（例：6月決算 = 事業年度 R6.7〜R7.6）の場合、PDF だけでは **事業年度の前半 6 ヶ月（2024年7〜12月）が取得できない**。

このケースで取り得る選択：

| 対応 | 説明 | 注意 |
|---|---|---|
| A. 不足月を別の暦年 PDF から補う | 令和6年分の暦年 PDF も入手して合体 | ユーザー側で別 PDF を準備する必要あり |
| B. 暦年データのまま入れる（事業年度ズレを許容）| ツール側で R216 が暦年ベース集計になる | **R216 算定が正確でなくなる**、報告に明記 |
| C. xlsx を作らず、ユーザーに事業年度に合致した PDF の再取得を依頼 | 最も精度が高い | ユーザー手間あり |

→ **デフォルトは C を推奨**。B で進める場合は B2 セルに大きく警告メモを残し、ユーザーに通知。

##### 1.1.3 「全月在籍だが台帳の窓が1ヶ月ズレて欠けた人」と「真の中途・退職者」を区別する（重要）

支給日ベースの台帳（「○月支給分」で並ぶ）だと、対象期間の端で **実際は全月在籍なのに1ヶ月分だけ窓から外れる** ことがある（例：3月決算で「3月支給分〜翌2月支給分」を取ると、当該年度に在籍していた人の最後の1ヶ月が落ちる）。この人は公募要領上「全月分の給与等の支給を受けた従業員」＝**算定対象に含めるべき人**であり、中途者として扱ってはいけない。

- 対応①（推奨）：**対象期間（12ヶ月の窓）を正しく取り直す**（§1.1.1 で決算月を確定し、対象月＝事業年度に合わせる）。これで全月そろうのが本筋。
- 対応②（次善策）：窓を正しく取っても1ヶ月分の記録がどうしても無い場合のみ、その人の不足月を他月と同額で補完（按分）して12ヶ月をそろえる。**この補完は「全月在籍者」に限る**。
- ❌ **真の中途採用・退職者**（その事業年度に全月分の給与を受けていない人）は、公募要領 p.10「全月分の給与等の支給を受けていない…**算出の対象から除く必要がある**」のとおり **除外（空欄のまま）**。按分して水増ししてはいけない（過大計上＝要領違反）。

> ツール側は「**12ヶ月すべて支給>0**」を全月在籍と判定する（v0.2.69/70、`is_full_year_paid`）。空欄・0円・負値はいずれも不支給月扱い。窓ズレで1ヶ月欠けた全月在籍者を放置すると中途扱いで除外され、最悪 **全員除外＝R216空欄＋「全月在籍者0名」警告（no_full_year_target）** になる。まず窓を正す。

### 1.2 出力ファイル名

```
{会社名}_賃金台帳一覧.xlsx
```

例：`株式会社サンプル建設_賃金台帳一覧.xlsx`

## 2. 雇用形態ラベルの正規化（**最重要・落とし穴**）

ツール側の役員判定は **「役員」という文字列を含むかどうか** で行われる（`hojokin/wage_reader.py`）。
よって以下の表記は **そのまま転記すると役員除外されず R216 に算入されてしまう**：

| 元 PDF の表記 | 正しい正規化 |
|---|---|
| 代表取締役 | **役員** |
| 取締役 | **役員** |
| 監査役 | **役員** |
| 理事長 / 理事 / 監事（医療法人等） | **役員** |
| 事業主 / 個人事業主（個人事業主テンプレ選択時） | **役員**（R216 から除外） |

### 正規化ルール

```
元の雇用形態に「代表取締役 / 取締役 / 監査役 / 監事 / 理事長 / 理事」が含まれる → 「役員」
個人事業主の場合のみ「事業主 / 個人事業主」も → 「役員」（R216 除外）
個人事業主の「専従者 / 青色事業専従者」→ 「正社員」（R216 算入）
「パート / アルバイト / 非常勤」を含む → 「パート・アルバイト」
それ以外（職位名「現場代理人」「主任」「営業」等も） → 「正社員」
```

職位名は雇用形態列ではないので、「正社員」に正規化する。

### 2.0 雇用形態欄が **無い** 給与ソフト形式でのパート判定（重要）

給与ソフト出力には **雇用形態（正社員/パート）の列自体が無い** ものがある（実テストで観測：建設業の月次台帳で雇用形態欄なし）。
この場合、全員を機械的に「正社員」にすると、**実際はパートの人が FTE=1.0 で算入され R215 が過大計上**される。以下の手掛かりで **パート候補** を推定し、確定は顧客確認に委ねる：

- **給与体系 / 基本給区分が「時給」**（「月給」「日給」以外）→ パートの可能性大。E列（月平均時間）を勤怠欄の「労働時間」から埋める
- **月間労働時間が所定（160h前後）より明確に短い**（例：80〜120h で安定）→ パート候補
- **支給額が月により大きく変動し低額**（時給×実働のパターン）→ パート候補
- 逆に **時給制でも月150h前後フルに近い** 場合は、パートでも FTE≒0.85 等になるので **E列の月平均時間を必ず入れる**（FTE換算は時間ベースで決まる。雇用形態ラベルより E列が効く）

→ パート候補が居たら、雇用形態を「パート・アルバイト」にし **E列（月平均時間）を必ず埋める**。判定に迷う場合は B2 セルに「雇用形態欄なし。◯◯はパート候補、要顧客確認」と警告メモを残す。
**最終的な正社員/パートの確定は顧客確認**（§0.2）。

### 2.1 PDF 役職欄が **全員空欄** のときの判定手順（重要）

給与計算ソフト出力の PDF では役職欄が空欄なケースが多い。この場合は以下を順に試す：

**ステップ 1: 履歴事項全部証明書 PDF があるか確認**
- 案件フォルダに `履歴事項全部証明書_*.pdf` があれば、それを Read して **代表取締役 / 取締役 / 監査役** の氏名を取得
- 賃金台帳の氏名と照合（NFKC 正規化、姓名の半角全角・スペース吸収）し、一致した人を **「役員」** に置換
- これは本物のツール（hojokin v0.2.10）と同等のロジック

**ステップ 1-a: 辞任役員の除外（重要）**

履歴事項全部証明書には **辞任済み・退任済みの役員も記載される**（抹消線・「辞任」「退任」日付付き）。
これらは **現役役員ではない**ので除外する：

- 抹消線（取消線）が引かれている氏名 → **除外**（現在は役員ではない、賃金台帳に登載されているなら一般従業員として処理）
- 「辞任 令和N年M月D日」のような日付付き → **除外**
- 「重任」「再任」は **継続中**（除外しない）
- 「就任 令和N年M月D日」が記載され、辞任記載がない → **現役**

例：履歴事項の取締役欄に「令和N年M月D日 辞任」と日付付きで記載されているケース → 現役員ではないので、賃金台帳側では「正社員」として処理。

**ステップ 1-b: 医療法人の登記スタイル（重要）**

医療法人では、履歴事項証明書に **理事長のみが登記され、他の理事・監事は登記されないケースがある**（実テストで観測）。
この場合：

- 履歴事項に「理事長 ◯◯」だけしか出てこなくても、それ自体は有効な役員情報として扱う
- 「他の理事・監事が登記されていない」=「いない」ではなく「登記されていないだけ」
- 賃金台帳に同姓の他従業員がいれば、§2.1 ステップ 2 の役員候補警告ロジックを併用する

**ステップ 1-c: 履歴事項に役員はいるが賃金台帳に登載されないケース**

代表取締役・取締役が履歴事項証明書に記載されているが、**賃金台帳の氏名一覧に該当者が一人もいない**ことがある（実テストで複数件観測）。
この場合：

- 役員給与は **賃金台帳の対象外（別管理 or 無報酬）** と判定
- 賃金台帳の全員を「正社員」として処理（履歴事項役員はそもそも台帳に存在しないので正規化対象外）
- B2 セルに **「履歴事項証明書の役員 ◯◯・◯◯ は賃金台帳に登載なし → 役員給与は別管理 or 無報酬の可能性。要顧客確認」** と警告メモを残す

**ステップ 2: 履歴事項証明書がない場合の役員候補警告**

以下を満たす従業員は **役員候補** として B2 セルに **赤字の警告メモ** を残し、最終判定はユーザー（顧客への確認）に委ねる：
- **会社名と同姓** の従業員（例：「有限会社サンプル工業」で姓「サンプル」「○○」が同一）
- 月額が **極端に低い** or **完全に一定**（賞与なし・残業なし）→ 役員報酬の最低保証額の典型パターン
- 月額が他従業員に対して **極端に高い**（例：500K 超の月給制で残業手当一切なし）
- **社員番号体系の不連続**（例：他従業員が 0102, 0103, ... と 4 桁採番のなか 1 名だけ 0011 のような若番）→ 役員は別建ての番号体系を持つ傾向

これらの条件は **AND ではなく OR**。1 つでも該当すれば役員候補として記録する。同姓＋低額一定＋若番 のように複数該当すれば確度が高い。

警告メモのフォーマット例（B2 セル）：
```
⚠️ 役員判定は履歴事項全部証明書がなかったため自動判定不可。
   役員候補（要顧客確認）:
   - 氏名 A（会社名と同姓・月額完全一定・賞与残業なし）
   - 氏名 B（会社名と同姓・低額一定）
   - 氏名 C（社員番号体系が他従業員と不連続）
```

**ステップ 3: 完全に判定不可なら全員「正社員」**

役職欄空欄＋履歴事項なし＋役員候補も特定できない場合、全員「正社員」として転記し、B2 セルに「役員判定不可・要顧客確認」を明記。

詳細パターン・落とし穴の根拠は [reference/役員正規化と落とし穴.md](reference/役員正規化と落とし穴.md) を参照。

## 3. 採用する金額（公募要領準拠）

| 採否 | 列名 | 理由 |
|---|---|---|
| ✅ | **課税支給合計**（または「課税給与」） | 公募要領 p.10「給与所得として課税対象となる経費」 |
| ❌ | 支給合計（通勤費込み）／総支給額 | 非課税通勤費が混入 → 過大計上で公募要領違反 |
| ❌ | 差引支給額 | 社保・税控除後で過小計上 |

> ⚠ 現場では「総支給／差引／課税対象」が混同されやすい（申請MTGでも担当者が「課税対象額」→「総支給額」と言い直す場面あり）。採用は **課税支給合計** で固定。**非課税通勤手当が無い従業員では「総支給額」＝「課税支給合計」で一致する**ため担当者が口語で「総支給」と呼ぶことがあるが、台帳に非課税通勤手当がある人では差が出る（その分を除外する）。迷ったら「給与所得として課税対象か？」で判断。

### 3.1 通勤手当の扱い（S列「年間通勤手当」）

> 🔴 **最頻出事故：S列の二重控除**。月列（G〜R）に「**課税支給合計**」を入れたら、**S列は絶対に空欄**にする。
> 課税支給合計は通勤手当（非課税分）を**既に除外済み**なので、さらにS列を埋めるとツールが通勤を
> **もう一度**減算し、R216（給与支給総額）が通勤額ぶん**過小**になる（配布テスト3案件すべてで発生）。
> S列を埋めるのは「**合計（通勤費込み）**」しか列が無く、それを月列に入れた時**だけ**。

| ケース | G〜R 列 | S 列 |
|---|---|---|
| 台帳に「課税支給合計」列がある | その値を転記 | **空欄（厳守）** |
| 「合計（通勤費込み）」列しか無い | 合計列をそのまま転記 | **非課税通勤手当の年間合計** を入れる → ツールが在籍月数で均等割減算 |

R216 の給与支給総額は **非課税通勤分を除いた課税対象額**（公募要領 p.10 / 申請MTG 2026-06-02 で確定）。課税支給合計＝既に通勤除外済み、を S列でもう一度引かないこと（検算は §5-F）。

賞与は **R216 に含める**が、**月セル（G〜R）には混ぜず T列「年間賞与」に年間合計を入れる**（月セルに混ぜると最低賃金判定・直近3ヶ月の月額が歪む）。対象事業年度内に支給された賞与のみ合算する（年度をまたぐ賞与は除外）。詳細は §4.1.1。

詳細・採用根拠は [reference/公募要領要点.md](reference/公募要領要点.md) を参照。

## 4. 抽出方法

### 4.1 推奨：Read ツールで PDF を直接読む（multimodal）

**重要：Bash で PyMuPDF / PIL / convert / pdfimages 等を使った画像処理に逃げないこと**（最初の試行で）。 Read ツール本体が PDF を multimodal（画像）として直接認識できる。Bash 画像化ルートは時間ばかりかかって精度も落ちる。

> **例外（multimodal Read 失敗時のフォールバック）**：Read の multimodal で PDF が「罫線しか見えない」「文字が薄くて読めない」場合は、`fitz.get_text("words")` で **座標付きテキスト抽出** に切り替えてよい。フォント埋め込みがない PDF（TKC PX2 形式など）は `page.get_text("rawdict")["blocks"][i]["lines"][j]["spans"][k]["chars"][m]["c"]` で **個別文字単位の Unicode 取得** が可能（実テストで TKC 形式の文字化けを回避した実例あり）。これらは「最初から画像処理に逃げる」ではなく「multimodal で読めないと判定後のフォールバック」。

#### 手順

1. **最初に 1 ページ目だけ Read して PDF の構造を確認**：

   ```
   Read(file_path="令和7年_賃金台帳.pdf", pages="1")
   ```

   ここで「1人1ページ型」「全社員1表型」「2ブロック印字型」のどれかを判定する（§8 参照）。

2. **ページ数を見積もる**：
   - PDF が大きい場合（数 MB 以上、多ページ想定）は、まず `pages="1-2"` で頭を確認し、必要に応じて範囲を拡張
   - **10 ページ超の PDF は `pages` 引数が必須**（Read tool の制約：pages 指定なしだとエラー）
   - **1 リクエストの上限は 20 ページ**

3. **全ページを順番に読む**：

   ```
   Read(file_path="...", pages="1-10")
   Read(file_path="...", pages="11-20")
   Read(file_path="...", pages="21-N")
   ```

   ページごとに「氏名・雇用形態・各月の課税支給合計」を抽出して内部メモに溜める。
   併せて §4.1.2 の**原本転記シート用に、ページ丸ごと（印字されている全行＝支給の各項目・控除の各項目・勤怠・合計行）をページ単位の行列のまま**同じメモに溜める（採用する行だけを選別しない。転記シートのために後から PDF を読み直して二重抽出しない）。

4. **openpyxl で templates/賃金台帳テンプレート.xlsx をコピーして書き込む**：

   ```python
   from openpyxl import load_workbook
   # {SKILL_DIR} は §0.0 で解決済みの絶対パス（スキルフォルダ）
   wb = load_workbook("{SKILL_DIR}/templates/賃金台帳テンプレート.xlsx")
   ws = wb["従業員別明細"]

   # データ書き込み（N 名分）
   for i, emp in enumerate(employees):
       row = 6 + i
       ws.cell(row=row, column=2, value=i + 1)               # B: No
       ws.cell(row=row, column=3, value=emp["name"])         # C: 氏名
       ws.cell(row=row, column=4, value=emp["type"])         # D: 雇用形態
       ws.cell(row=row, column=5, value=emp.get("avg_hr"))   # E: 月平均時間
       ws.cell(row=row, column=6, value=emp.get("hourly"))   # F: 時給
       for m, v in enumerate(emp["months"]):                  # G〜R: 月次（賞与は含めない）
           ws.cell(row=row, column=7 + m, value=v)
       ws.cell(row=row, column=19, value=emp.get("commute")) # S: 年間通勤手当
       ws.cell(row=row, column=20, value=emp.get("bonus"))   # T: 年間賞与（月次に混ぜない）

   # 重要：テンプレ既存のプレースホルダ行（B7-B15 に No=2〜10 が入っている）を、
   # 従業員数 < 10 名のとき余分行が残らないように明示的にクリアする
   n = len(employees)
   for row in range(6 + n, 16):  # 16 = B15+1
       for col in range(2, 20):  # B〜S 列
           ws.cell(row=row, column=col, value=None)

   wb.save(f"{会社名}_賃金台帳一覧.xlsx")
   ```

   **5行目（ヘッダー）は上書きしない**：テンプレ既定の「1月」..「12月」のまま使う。
   月見出しに `(R7.1)` 等の注記を足さない（§1 の🔴。注記はツールが0名誤読）。事業年度の対応は下記 B 注記へ。

   **ヘッダー注記（B1〜B3）には必ず決算月トークンを含める**：B1 または B3 に
   「対象事業年度: 令和X年A月〜令和Y年B月（**N月決算**）」の形で記載し、**「（N月決算）」を必ず入れる**
   （`review/verify_wagebook.py` が決算月を解析して非暦年決算の賞与帰属チェック＝FLAG-T を出すため）。
   事業年度のマッピング（例: 「G〜N列=R7年1〜8月分, O〜R列=R6年9〜12月分」）も B 注記に書く（ヘッダーセルではなく）。

   **保存（`wb.save`）の前に、§4.1.2 の原本転記シート群（表紙「原本転記」＋ページ別「原本転記_pN」）を同じ wb に必ず追加する**（従業員別明細と同じ抽出メモから書く）。

5. **全件転記後、年間合計を逆算して OCR 誤読チェック**（**必須・最重要のセルフチェック**）：

   ##### 5-A. 社員ごとの年間合計検算（必須・ただし単独では不十分）

   - PDF 各ページの右端列「合計」欄の年間合計と、xlsx の G〜R 列（12 ヶ月分）の和を **社員ごとに照合**
   - 1 円でも合わない社員がいたら、該当ページを `Read(pages="N")` で再読み込みして OCR 誤読を発見・修正
   - 全員分一致するまで反復する（過去例：ある社員の 11 月で X 円と読み取ったが PDF 原本では Y 円 → 再 Read で修正）

   > ⚠️ **年間合計が合っても月配置のズレは残り得る**（§1.1.0）。月をずらしても年間合計は
   > 不変なので、年間合計検算だけでは「2月空欄→3月以降が1つズレ→末尾を合算」型の事故を
   > 見逃す。**5-A を通過しても 5-B/5-C/5-M を必ず実施すること。**

   ##### 5-B. 月別全社計の横断検算（**必須・月ズレ検出の主力**）

   - PDF の各月ページに「月別全社計」が印字されている場合、xlsx の月別総和（全員分の G〜R 列各月）と照合する
   - 1 セル誤読でも月別総和に響くので、社員ごと検算より発見効率が高い（実テストで月別全社計とのズレから OCR 誤読を即時発見した実例あり）
   - **月配置ズレは「年間合計は合うが月別全社計が合わない」形で現れる**。これを検出する主力チェック。

   ##### 5-M. 月単位の対応付け検証（**必須**・空欄月のある社員は全月、それ以外は最低3名抽出）

   §5-B の月別全社計が PDF に無い案件でもズレを潰すため、以下を必ず実施する：

   - **途中に空欄月がある社員は全員**、各月の値を `Read(pages="N")` の PDF 原本と
     **月ごとに1セルずつ突き合わせる**（その月の列に正しい月の値が入っているか）。
     空欄月の左詰めズレ（§1.1.0）はこの社員群で最も起きやすい。
   - 空欄月のない社員からも **最低3名** を抽出し、賞与月（他月比1.5倍以上の月）が
     正しい月に乗っているかを含め月単位で照合する。
   - 1 セルでもズレ・取り違えがあれば該当ページを再 Read して修正し、全員分の月配置が
     PDF と一致するまで反復する。

   ##### 5-C. PDF 総合計シートとの突合（あれば）

   - PDF 最終ページに「総合計」「賃金支給合計」シートがあれば、その「課税支給額」と、全員の **月次12ヶ月（G〜R）＋ T列「年間賞与」** の総和が完全一致するか確認（賞与は T列側に入っている点に注意）
   - 完全一致 = OCR 誤読ゼロを担保

   ##### 5-D. 総合計シートがない場合のフォールバック

   PDF に総合計シートが存在しない案件（個別社員ページのみ）も多い（実テストで 11 件中 5 件で観測）。
   その場合は **5-A の各社員合計の総和** を「PDF ベースの年間合計」とみなし、xlsx の G〜R 列の総和と照合する。

   ##### 5-E. OCR 1 円誤差の正規化ルール

   各月値が全項目（基本給・各種手当・通勤手当）を分解集計するタイプの PDF では、表示の集計列と各項目の和に **微差（数百円以内）** が生じることがある（PDF の集計列側の表示誤差）。

   - 差が **±500 円以内**：PDF 各月値（明細）の和を採用し、最終月（または最初の月）で吸収して PDF の合計と整合させる。要確認メモを残す
   - 差が **±500 円超**：OCR 誤読の可能性が高い、`Read(pages="N")` で再読み込みして該当セルを修正
   - 差が **数千円〜数万円**：転記漏れの疑い（賞与未加算、ある月の値が抜けている等）→ 必ず修正

   ##### 5-F. 通勤手当S列の二重控除チェック（**必須**）

   月列（G〜R）に「課税支給合計」を採用した場合、`Σ(G〜R) + T列「年間賞与」 = PDF の課税年間合計`
   が成り立つ（通勤は既に除外済み）。**この式が成り立つのに S列にも値が入っていたら二重控除**
   （ツールが通勤をもう一度減算し R216 が過小になる）→ **S列を空欄にする**。S列を埋めてよいのは
   「合計（通勤費込み）」を月列に入れた時だけ（§3.1）。

### 4.1.1 賞与の取込み（**最重要・落とし穴 = §1.1 と同等の優先度**）

PDF の最終ページ（総合計シート）には通常以下が **分離計上** されている：

```
給与支給合計          ¥30,000,000  ← 月給だけの合計
賞与計（賞与支給合計） ¥   600,000  ← 賞与の合計（夏季/冬季の2回が典型）
総合計                ¥30,600,000  ← 給与＋賞与
```

**Skill としては「賞与計」を T列「年間賞与」に入れる（G〜R の月セルには加算しない）**。月セルに賞与を混ぜると最低賃金判定・直近3ヶ月の月額が歪むため。対象事業年度内に支給された賞与のみを合算する（§4.1.1-a で年度判定）。ツールが T列を R216（給与支給総額）に算入するので、**月給12ヶ月合計 ＋ T列年間賞与 ＝ PDF 総合計** が一致する。

確認ポイント：
- PDF 各社員ページの右下に「賞与 1 回分 / 2 回分」の欄があるか確認
- 賞与計が別ページ（PDF 末尾の集計シート）にしかない場合もある（給与計算ソフトの仕様）
- **賞与月は会社により異なる**。「6月 or 12月の 2 倍前後」だけを基準にすると、決算月にインセンティブを支給する会社や、夏季賞与なし会社（12月のみ賞与）を取りこぼす。**PDF 全期間で他月比 1.5 倍以上の月があれば賞与の可能性大**。見当たらなければ「賞与なし会社」として記録し報告に明記する

#### 4.1.1-a 賞与は T列に集約（支給月セルには入れない）／支給日は年度判定にだけ使う

賞与は支給月に関わらず **T列「年間賞与」に年間合計** で入れる。支給日（年月）は **「対象事業年度内か」の判定だけ** に使う：

- 対象事業年度内に支給された賞与 → T列の年間合計に算入
- 対象事業年度の **外**（翌期・前期）に支給された賞与 → 算入しない（例：7月決算で 8月支給の夏季賞与は翌期分）
- 支給日が読めない賞与 → 下記**【非暦年決算の賞与帰属ガード】**に従う（**安易に「算入しつつ要確認」で確定しない**）

（賞与の「支給月の細かい位置」は R216 では不問。年間合計に入っていれば月は問わない。最低賃金法上も賞与は最賃の算入対象外なので、月セルから分離するのが正しい。）

##### 【非暦年決算の賞与帰属ガード】（最重要・実事故あり：推測確定を禁止）

> 🔴 次の **3条件が揃ったら、回数→支給月のマッピングを推測で確定してはいけない**：
> ① **決算月 ≠ 12月**（＝事業年度の窓が暦年とズレる）、かつ
> ② 台帳に賞与の **支給年月日が無い**（「令和N年X回」など年度＋回数表記のみ）、かつ
> ③ ユーザーから **支給月の指定も無い**（§0.1 項目7 未取得）。

このとき事業年度の窓（決算月の翌月〜決算月）に「令和N年のどの回」が入るかは支給月なしには確定できない。
**「令和6年3回目＝冬＝窓内／令和7年1回目＝夏＝窓内」のように決めつけない**（実案件＝8月決算で発生した事故：回数→月を推測確定し B2 に断定記載 → 別経路の算定と ±数十万円/人 の食い違い）。

**取るべき挙動：**
1. T列は **最も妥当な暫定セット**（一般に「直近の冬賞与＋直近の夏賞与」など年2回想定）で埋める。**T列の該当セルは黄色**にする（§4.4.2 の低信頼マーカーを流用）。
2. **B2 セルと完了報告「要顧客確認事項」に目立つ形で**次を明記：
   ```
   ⚠ 賞与の支給月が台帳に未記載。事業年度（M月決算 → 令和X年A月〜令和Y年B月）内の賞与を
      確定するため、以下のいずれかを提供してください：
      (a) 各賞与回の支給年月（例: 夏=令和7年7月 / 冬=令和6年12月）
      (b) 勘定科目内訳明細書（人件費内訳）＝法人 R216 の正式ソース
   現状 T列は暫定（含めた回＝[…]／除外した回＝[…]）。支給月確定後に再調整要。
   ```
3. 変換メモシートに、各人の T列について **含めた回・除外した回・暫定である旨** の内訳を残す。
4. **断定的に「他回は対象外」と書かない。** 確定したのは「暫定値を入れた」ことだけ、と分かる書き方にする。

逆に上記①②③のいずれかが崩れれば、このガードは外れて確定してよい：
- **決算月 ＝ 12月**（事業年度＝暦年）→ 令和N年の回はそのまま当年度の賞与として算入（窓ズレなし）。
- **支給年月日が台帳に明記**／**ユーザーが支給月を指定** → その月で窓内/窓外を確定計算。

#### 4.1.1-b 年度＋回数表記（支給月不明）の解釈

給与計算ソフトによっては「**令和N年2回**」「**令和N+1年1回**」のような **年度＋回数表記** で、支給月の明示がないことがある（実テストで観測）。
解釈ルール（**§4.1.1-a の「非暦年決算の賞与帰属ガード」に従属**）：

- **決算月 ＝ 12月**（事業年度＝暦年）→ 令和N年の回はそのまま当年度扱いで算入してよい（窓ズレなし）。
- **決算月 ≠ 12月**で支給月が不明 → **回数だけから窓内/窓外を断定しない**。§4.1.1-a のガードどおり、暫定セットで埋めた上で B2＋完了報告に「支給年月 or 勘定科目内訳明細書を提供」と要求し、含/除の回を明記する（推測確定禁止）。
- ユーザーが支給月を指定した／台帳に支給年月日がある → その月で窓内/窓外を確定計算。

支給月が取れず非暦年決算の場合は、作業前に §0.1 項目7 で「各賞与回の支給月は何月ですか（夏/冬など）」とユーザーへ確認するのが最善。取れなければ上記ガードへ。

### 4.1.2 原本転記シート（PDF丸ごと転記・必須／2026-07-21 決定、2026-07-26 全項目・ページ別化）

**目的**：確認者が Excel⇄PDF を往復せずに原本の値を参照し、**Excel の関数でそのまま計算できる**ようにする。
実例：通勤手当が「課税支給額」に含まれて印字される台帳で、確認者が `=課税支給額セル−通勤手当セル` を関数で出す（転記が集計行だけだと電卓で引き直す羽目になる＝実際に配布先で起きた不満）。加点判定（katen-judge）も同じ転記から基本給・労働時間を転用できる。スクショ（画像貼り）は不可＝**数値セルでの転記**。複数 PDF 案件で「この月はどの PDF」の探索をなくす狙いも含む。

> 🔴 **全項目転記——「課税支給額」など集計行だけの転記は仕様違反（実事故あり）**
> PDF に印字されている行は**すべて**転記する。「算定に使わない行だから」という選別をしない
> （転記シートの価値は選別しないことにある）：
> - 支給の各項目行（基本給・各種手当・**通勤手当**・時間外手当 …）
> - 控除の各項目行（健康保険・厚生年金・雇用保険・所得税・住民税 …）
> - 勤怠行（出勤日数・労働時間・有給 …）
> - 集計行（課税支給額・非課税支給額・総支給額・控除合計・差引支給額）
> `verify_wagebook.py` が「基本給・手当・控除系の項目名が見当たらない転記」を **FLAG-R**（集計行のみ転記の疑い）として検知する。

**シート構成（1 PDFページ ≒ 1シート）**：

| シート | 内容 |
|---|---|
| 表紙「**原本転記**」 | A1=固定注記（下記コード参照）、A2=対象期間・決算月。3行目以降に対象 PDF 一覧、ページ⇄シート対応、書式の説明（例: p.1-23=旧書式・p.24-37=新書式）、判読困難箇所の一覧 |
| データ「**原本転記_p{N}**」 | **1 PDF ページ＝1シートが標準**。A1=出典行（`原本: {PDFファイル名} p.{N} {ページ見出し}`）、行2=PDF印字の合計（隣に `=SUM(...)` の検算式を置いてよい）、行3以降=**原本の行列をそのまま**（行=項目×列=従業員でも、行=従業員×列=項目でも、原本の向きのまま） |

- 1つの表が複数ページに続く場合は `原本転記_p1-2` のように結合してよい。複数 PDF は `原本転記_{略称}p{N}`（いずれも Excel の31文字制限内）
- ページが小さい台帳（1人1ページの個人台帳型など）は複数ページを1シートに縦積みしてよい。その場合も**各ブロック先頭に出典行** `▼ {PDFファイル名} p.{N} {氏名}` を必ず置く

**シート名のルール（🔴 最重要）**：表紙もデータも、シート名は必ず「**原本転記**」で始める。
ツール側リーダーは**このプレフィックスの可視シートを全経路（決定論・AI）で読み飛ばすガード**を実装済み（v0.2.91〜）。`pA01_1-2` のような**独自名にするとツールが表として誤読し R215/R216 を壊す**（`verify_wagebook.py` が規格外シート名を FAIL で検知する）。**受領者側でのリネームも禁止**（受け渡し時に一言添える）。

**転記の範囲**：提供された賃金台帳 PDF の**全ページが標準**（対象事業年度外＝前年度分のページも転記する。前年比較・加点判定への転用に使う）。例外は対象外年度のページが大量（3年分超など）の場合のみ：対象事業年度＋加点判定窓（令和6年10月〜令和7年9月＋交付申請直近月）のページを必須とし、**省略した範囲を表紙シートと §9 報告に明記**する。

**転記の原則**：
- PDF の**項目名・並び・値をそのまま**転記する（正規化・並べ替え・欠損補完をしない）
- 値は**数値セル**で入れる（文字列にしない。判読不能セルだけ空欄＋黄色。手書きの自由記述などどうしても数値にできないものだけ備考列に文字で）
- **同一ブック内に置く**（転記だけの別ファイルに分けない。ファイル名に「賃金台帳」を含む別ファイルはツールが台帳として誤分類し、二重計上の恐れがある）

```python
ws_cover = wb.create_sheet('原本転記')   # 表紙（可視のまま。確認者が最初に見るシート）
ws_cover.cell(row=1, column=1, value='このシート群（原本転記*）は賃金台帳PDF原本の転記です。'
              'ツールは読み取りません（シート名「原本転記」ガード）。算定の正本は「従業員別明細」シート、真はPDF原本。')
ws_cover.cell(row=2, column=1, value='対象期間: YYYY年M月〜YYYY年M月（N月決算）／対象PDF: {ファイル名}（全Pページ）')
# 3行目以降: ページ⇄シート対応・書式説明・判読困難箇所の一覧

for page in transcript_pages:            # 手順3で溜めた「ページ丸ごと」の行列
    ws = wb.create_sheet(f"原本転記_p{page['no']}")   # 🔴 必ず「原本転記」で始める
    ws.cell(row=1, column=1, value=f"原本: {page['file']} p.{page['no']} {page['title']}")
    ws.cell(row=2, column=1, value=f"原本印字の合計: {page['printed_total']}")
    for r, line in enumerate(page['rows'], start=3):  # line = [項目名, 値, 値, ...] 原本の並びのまま
        for c, v in enumerate(line, start=1):
            ws.cell(row=r, column=c, value=v)
    ws.column_dimensions['A'].width = 22
```

**従業員別明細との関係**：G〜R・T 列に採用した金額は、原本転記シートの該当行（課税支給合計等）と各員・各月で一致していること（checklist の 5-R で突合。全項目転記なら 5-C/5-D の総合計突合も同シート経由で機械化できる）。ただし**真は PDF**（転記シートも AI 産物）——5-R は §5-A〜§5-M の PDF 検算の**代替にはならない**。確認者の照合は全数でなくピンポイント（気になる金額・勤務時間だけ）でよい、が運用合意。

**例外**：§4.3（既存 JSON 流用で PDF 原本が手元に無い）場合は省略可・§9 報告に理由を明記。§4.4（手書き）は読み取れた範囲のベストエフォートで転記し、不明瞭セルは空欄＋黄色。

#### よくある失敗パターン（このスキルでは禁止）

| ❌ 失敗パターン | ✅ 正しい方法 |
|---|---|
| Bash で `fitz` (PyMuPDF) / `PIL` を使って PDF を画像化してから画像を Read | Read に PDF パスを直接渡す（`pages` 指定）|
| 画像のトリミング・解像度調整に時間を費やす | 元の PDF を Read のまま渡せば内部で適切に処理される |
| 全ページを一度に Read（10ページ超で失敗）| `pages="1-10"`、`pages="11-20"` のように分割 |
| PDF が読めない時に画像処理ルートへ逃げる | 読めない時は `pages="N"` で 1 ページずつ試す |

### 4.2 非推奨：サブエージェントへ PDF 抽出を丸投げ

PDF 抽出をさらに別のサブエージェントに渡すと Read 経由のループになり、本番経路より精度が落ちる。
→ **5名以下なら自分で全件 Read。10名以上の大規模でも、自分が直接 Read して順次抽出する**。

> 注：これは「抽出」の話。**レビュー（§5.5）は別物**で、同一エージェントが別人格のレビュアーに切り替えて独立観点で通すことを推奨する。新規エージェント spawn や Anthropic API 呼び出しは不要（同一ターン内のロール切替＋openpyxl 機械検算で完結＝課金ゼロ）。

### 4.3 既存 JSON 流用

過去に抽出済みの構造化 JSON（氏名・雇用形態・月次データを持つもの）が手元にあれば、PDF を読み直さず流用してよい。流用する場合は：

1. JSON を読み込んで、雇用形態を §2 のルールで正規化
2. 全員分の年間合計を表示して、ユーザーに **「最大3名の数値が原本と合うか目視確認」** を依頼
3. 12月分が `None` の社員は「中途入退社」扱いで R216 から自動除外される（仕様）

### 4.4 手書き / 画像PDF の場合

#### 4.4.1 精度判定の事前ゲート（必須・最初に実施）

**1〜2 ページ精読時点で以下を判定する**：

- セル内に **5 段以上の手書き数字** が圧縮されていて読み取り困難か？
- 字体が **著しく判読困難**（殴り書き・薄字・かすれ）か？
- ページ全体が **手書き＆罫線のみ**（テキスト層 0 文字）か？

**判定結果が「読み取り困難」なら、その時点で作業を停止して ユーザーに代替ソースを打診する**：

| 優先度 | 代替ソース | 効果 |
|---|---|---|
| 最推奨 | 給与計算ソフトの **集計 CSV / Excel** を顧客から取得 | 自動化精度が一気に上がる、API課金ゼロで処理可能 |
| 次善 | PDF を **高解像度スキャン**で再取得 | OCR 精度が上がる可能性 |
| 最後の手段 | 人手転記 | 時間とコストかかるが確実 |

→ **「最低限動く」より「プロダクション品質」を優先**（CLAUDE.md 全プロジェクト共通ルール）。低品質データを成果物として出すと、後段の R215/R216 算定全体が信用できなくなる。

#### 4.4.2 読み取り可能と判定した場合の手順

1. 作業は通常通り進める。読み取れる範囲で全数値を抽出
2. 出力 xlsx の上部（B1〜B3 セルあたり）に **赤字で大きく** 警告を明記：
   ```
   ⚠️ 手書きPDFからの抽出のため、数値の精度が低い可能性があります。
   PDF原本と全数値を必ず照合してください（特に金額の桁数・賞与月）。
   ```
3. 信頼度が低いと判断したセルは **セル色を黄色** にして強調
4. 「変換メモ」シートに、不明瞭だったページ番号と該当セル一覧を残す

```
python "{SKILL_DIR}/review/verify_wagebook.py" "{会社名}_賃金台帳一覧.xlsx"
```
（`{SKILL_DIR}` は §0.0 で解決済みの絶対パス＝cwd が案件フォルダでも迷わない。openpyxl 未導入でエラーなら機械検算をスキップし §5-A〜§5-M を全件人手で実施＝**ゲートは飛ばさない**）

このスクリプトは **R216 を再計算しない**（ツール `wage_calculator.py` と式がドリフトして誤PASSを出すのを避けるため、不変量の観測と FLAG 列挙だけ）。出力をそのまま §9 に貼り、下記を解消するまで完了報告に進まない：
- **FAIL（修正必須）**：役員ラベル未正規化（④）／パートでE列空（④）／全月在籍非役員0名 → xlsx を直して再実行。
- **要確認（PDFで素性確認し §9 に判断を明記）**：FLAG-S（①S列）／賞与混入候補（③）／月セルの0。

### 5.5-3 PDFとの白紙突合（スクリプトでは決められない意味照合）
スクリプトの出力を手掛かりに、作業メモを見ず PDF を真として照合する：
- **【①二重控除】** FLAG-S が出た行は、月列が「課税支給合計」由来か（=通勤除外済み）を PDF で確認。そうなら **S列を空に**。月列が「合計（通勤費込み）」なら S列保持が正（§3.1）。判断を §9 に明記。
- **【②月配置ズレ】最重要・機械では確定できない**：月別縦計が出ても OK ではない（左詰めズレは年間合計を素通りする §1.1.0）。**途中に空欄月のある社員は全員＋無作為3名**を `Read(pages="N")` の PDF と各月1セルずつ突合し、突合した実数を §9 に列挙する。PDF に月別全社計があれば縦計と機械照合。
- **【③賞与混入】** 賞与候補の山は T列へ分離したか、繁忙期残業/歩合で月セルのままが正か、PDF で確認。

### 5.5-4 ゲート判定
FAIL は修正して 5.5-2 を再実行。要確認は PDF 確認の上で §9 に解決を明記。全て解消してから §6・§9 へ進む。
（このリポジトリ/Streamlit 側では、追加で本物の `read_wage_ledger`＝「一人当たり給与支給総額」タスクに通し R216 を逆算する最終ゲートが使える。配布先＝自前 verify、本拠地＝R216逆算 の二段構え）

## 6. 変換後の検証

[checklists/validation_checklist.md](checklists/validation_checklist.md) を必ず通す。
最低限ここだけは目視（要点）：

1. **L列(6月)** または **R列(12月)** の値が、他月の2倍前後になっているか（賞与月の確認）
2. 全員のG〜R列（12ヶ月）合計が、決算書「販管費＋製造原価」の人件費総額と概ね一致するか
3. 役員（代表取締役・取締役・監査役）の行が、雇用形態「役員」になっているか
4. 中途退社者の退社後の月が **0 ではなく空欄** になっているか
5. ファイル名が `{会社名}_賃金台帳一覧.xlsx` になっているか
6. 対象期間が **直近事業年度の12ヶ月** と一致しているか（§1.1）
7. **途中に空欄月がある社員の各月値が、左詰めズレなく正しい月列に入っているか**（§1.1.0／§5-M）。
   年間合計が合っていても月配置はズレ得るので、§5-A だけで済ませず §5-B/§5-M を通すこと
8. **「全月在籍だが台帳窓ズレで1ヶ月欠けた人」を中途者と取り違えていないか**（§1.1.3）。
   窓を正せば全月そろう人を空欄放置していないか。逆に **真の中途・退職者を按分で水増ししていないか**
9. **全月在籍者（12ヶ月そろう非役員）が0名になっていないか**。0名なら役員のみの法人か全員12ヶ月未満で、
   R216/R215 が賃金台帳だけでは確定不能 → §0.2・§9.1 のとおり役員報酬ベース算定の要否を報告すること

## 8. 案件ごとの典型パターン

| パターン | 抽出難易度 | 対処 |
|---|---|---|
| 1人1ページの個人台帳型 | 中 | 1ページずつ Read。各社員の合計欄で検算 |
| **1人2ページ型（支給明細＋控除明細）** | 中 | 奇数ページ=支給明細、偶数ページ=控除明細。Read で **支給明細ページのみ** を読む |
| 全社員1表型（月別大判） | 低（テキスト）〜高（スキャン画像） | テキストPDFなら multimodal Read、画像なら座標付きフォールバック |
| 2ブロック印字型（一般＋役員別） | 中 | ブロック判定が必要（reference 参照）|
| **全社員1行表 × 月別ページ** | 低 | 1ページに全員1行ずつ。月別全社計の横断検算が効く |
| 従業員別 Excel/CSV 分割 | 低 | 既に構造化済み、転記のみ |
| テキストPDF 年度別 | 低 | multimodal Read で抽出可 |
| **設立間もない/全員が在籍12ヶ月未満（役員のみ含む）** | 中 | 全月在籍者0名→R216/R215が台帳だけで確定不能。xlsxは作れる範囲で作り、役員報酬ベース算定の要否を報告（§0.2・§6-9・§9.1）。真の中途者を按分で水増ししない |
| **TKC PX2 形式（フォント埋込みなし）** | 高 | multimodal で読めない。`fitz` の `rawdict.chars[].c` で個別文字単位の Unicode 取得 |
| **複数 PDF に分割（月別 / 個人別 / 年度別）** | 中 | **対応可**。各PDFを読み、決算月に基づき直近事業年度の12ヶ月を組み立てる（§1.1）。ツールも統合(Nファイル)対応済み。暦年PDF複数→事業年度窓の組立は配布テストで実証。手書き/超大量は引き続き要注意 |

PDF が画像か否かの判定（PyMuPDF が必要。§0.0 参照）：

```bash
python -c "import fitz; doc=fitz.open('x.pdf'); print(len(doc[0].get_text('text')))"
```

0 や数十文字なら画像PDF → CC の Read（multimodal）で対応。
