- [ ] **月配置ズレ②**：縦計だけで済ませず、途中に空欄月のある社員 **全員＋無作為3名** を PDF と1セル突合したか（§1.1.0。縦計が出た≠OK）

- [ ] 上記を全て解消してから完了報告に進んだか

## A. 対象期間（最優先・事故率高）

- [ ] xlsx の「1月」列の値が、決算月+1〜決算月の **直近事業年度** の範囲内の月の支給額か
- [ ] 「5月」「6月」など事業年度開始月にあたる列の値が、**前年** の同月の支給額になっているか（決算月が1月始まりでない場合）
- [ ] 暦年データをそのまま入れていないか
- [ ] ファイル名 / xlsx 最上部に「対象期間: YYYY年M月〜YYYY年M月」のメモを残したか
- [ ] **PDF の期間表記と事業年度が整合しているか**（PDF が暦年データで事業年度が事業年度の場合、不足月の対処を B2 セルに明記したか）— §1.1.2 参照

## B. 雇用形態ラベル

- [ ] 「代表取締役」「取締役」「監査役」「監事」「理事長」「理事」が **「役員」** に置換されているか
- [ ] 「現場代理人」「主任」「営業」など職位名が **「正社員」** に正規化されているか
- [ ] パート・アルバイト・非常勤が **「パート・アルバイト」** に統一されているか
- [ ] 個人事業主テンプレの場合、「事業主」「個人事業主」が **「役員」** に、「専従者」「青色事業専従者」が **「正社員」** になっているか
- [ ] **履歴事項証明書の「辞任」役員を除外しているか**（抹消線・辞任日付付きは現役除外） — SKILL.md §2.1 ステップ 1-a
- [ ] **履歴事項に役員いるが賃金台帳に登載なしのケース**：B2 セルに「役員給与は別管理 or 無報酬の可能性、要顧客確認」を明記したか — §2.1 ステップ 1-c
- [ ] **PDF 役職欄空欄＋履歴事項なし**で §2.1 ステップ 2 を適用した場合、判定基準（同姓・低額一定・高額一定・社員番号体系不連続）の OR で抽出して B2 警告を残したか

## C. 金額（採用列の妥当性）

- [ ] G〜R 列の値が **「課税支給合計」**（または相当列）から取られているか（**賞与は含めない**）
- [ ] 「差引支給額」（社保・税控除後）を誤採用していないか
- [ ] 賞与を検出したか（他月比1.5倍以上の月／賞与計シート）。**月セルには加算せず T列「年間賞与」に年間合計**で入れているか（§4.1.1）
- [ ] T列の賞与は **対象事業年度内に支給されたもののみ**か（年度をまたぐ賞与を含めていないか）
- [ ] **決算月が12月以外**で賞与の支給月が台帳に無い場合、回数→月を **推測確定していない** か。暫定として B2＋完了報告に「含めた回/除外した回」と要確認（支給年月 or 勘定科目内訳明細書）を明記したか（§4.1.1-a 非暦年決算の賞与帰属ガード）。**「他回は対象外」と断定していないか**
- [ ] 全員の **G〜R（12ヶ月）＋ T列（年間賞与）** の合計が、決算書「販管費＋製造原価」の人件費総額や PDF 総合計と概ね一致するか

## D. 通勤手当（S 列）

- [ ] 🔴 **月列に「課税支給合計」を採用したか？ → YES なら S 列は必ず空欄**。S 列に値があれば二重控除エラー（ツールが通勤をもう一度減算し R216 が通勤額ぶん過小）→ S 列を空にする（§3.1／§5-F）
- [ ] 賃金台帳に「課税支給合計」列がある場合、S 列は **空欄** か
- [ ] 「合計（通勤費込み）」しか無い場合、S 列に **非課税通勤手当の年間合計** が入っているか
- [ ] S 列の値が **非課税分のみ**（月15万円超の課税分を引いていない値）か

## E. 中途入退社者・対象者

- [ ] 退社月以降の月セルが **空欄**（0 ではなく）になっているか
- [ ] 入社前の月セルが **空欄** になっているか
- [ ] 中途者の S 列に値を入れる場合、年間総額を入れている（在籍月で均等割するのはツール側の責務）
- [ ] **「全月在籍だが台帳窓ズレで1ヶ月欠けた人」を中途扱いで空欄放置していないか**（§1.1.3）。窓を正せば全月そろう人は算定対象。逆に **真の中途・退職者を按分で水増ししていないか**（過大計上＝要領違反）
- [ ] **全月在籍者（12ヶ月そろう非役員）が0名になっていないか**。0名なら役員のみ法人 or 全員12ヶ月未満 → R216/R215 は台帳だけで確定不能。**役員報酬ベース算定の要否を完了報告で明記**（§0.2／公募要領 p.10 特例の適用可否）

## F. ファイル名・体裁

- [ ] ファイル名が `{会社名}_賃金台帳一覧.xlsx` 形式になっているか
- [ ] シート名が **「従業員別明細」** になっているか（ツール側が探す名前）
- [ ] ヘッダー行が **5行目（B5〜S5）** に来ているか
- [ ] データ行が **B6 から** 始まっているか
- [ ] 数字セルが文字列扱いになっていないか（書式「標準」or「数値」）
- [ ] セル先頭に `=` が入っていないか（数式と誤認される）
- [ ] **テンプレ既存のプレースホルダ行（B7-B15 の No=2〜10）が、従業員数 < 10 名のとき余分に残っていないか**（SKILL.md §4 手順 4 のクリーンアップ処理を実行したか）

## H. 検算（複数アプローチ、必須）

> ⚠️ **5-A（年間合計）だけで終わらせない**。月配置がズレても年間合計は不変なので、
> 「2月空欄→3月以降が1つズレ→末尾合算」型の事故を年間合計検算は素通りする（§1.1.0）。
> 必ず 5-B または 5-M で **月単位** まで照合すること。

- [ ] **5-A 社員ごとの年間合計検算**：PDF 各社員ページの右端「合計」と xlsx 各人の G〜R 列の和が一致するか（全員分）。※ただし単独では月ズレを検出できない
- [ ] **5-B 月別全社計の横断検算**：PDF の各月「全社計」と xlsx の月別総和が一致するか（あれば。月ズレ検出の主力）
- [ ] **5-M 月単位の対応付け検証**：途中に空欄月がある社員は **全員**、各月の値を PDF 原本と月ごとに1セルずつ突合（左詰めズレなし）。空欄月なしの社員からも最低3名抽出して照合
- [ ] **5-C PDF 総合計シートとの突合**：PDF 最終ページの「総合計」と xlsx 全体総和が完全一致するか（あれば）
- [ ] **5-D 総合計シートがない場合のフォールバック**：5-A の各社員合計を総和して PDF ベース年間合計を計算、xlsx 総和と照合
- [ ] **5-E OCR 1 円誤差の正規化**：±500 円以内は最終月で吸収、±500 円超は再 Read で修正
- [ ] **5-F 通勤手当S列の二重控除チェック**：月列に課税支給合計を採用したなら `Σ(G〜R)+T列 = PDF課税年間合計` が成立。成立するのに S列にも値があれば二重控除 → S列を空に（§3.1／§D節）

## G. 手書き / 画像PDF の場合の追加チェック

- [ ] 出力 xlsx の B1〜B3 セルに **赤字の警告** が入っているか
- [ ] 信頼度低のセルが **黄色** で強調されているか
- [ ] 「変換メモ」シートに、不明瞭だったページ番号と該当セル一覧が残っているか
- [ ] ユーザーへの完了報告に「人による全数値照合が必須」と明記したか

## H. 完了報告

ユーザーに以下を報告する：

- 出力ファイル名とパス
- 対象期間と決算月
- 従業員数（役員 / パート / 中途者 の内訳）
- 全員年間合計の合計（決算書照合用）
- 検証チェックリストの結果（全項目 OK か、要確認項目があるか）
- 注意点（手書き警告・信頼度低セル等）

ユーザー側は次に「Streamlit Cloud で『一人当たり給与支給総額』タスクを実行して R216 を逆算検証」する流れになる（旧『給与計算のみ』タスクは UI から廃止）。

## 検算（ツールに通す）

Streamlit Cloud にアップして「一人当たり給与支給総額」モードで実行 → 出力 `{会社名}_一人当たり給与支給総額.xlsx` を確認（賃金台帳のみ・決算書PL人件費は非参照）。
決算書PL人件費との内訳照合まで行いたい場合はローカルで `python run.py --task wage` を回し `{会社名}_給与支給総額計算.xlsx` を確認：

- シート1「給与支給総額計算」の R216 値（`--task wage` 時は販管費＋製造原価の人件費 内訳付き）
- シート2「従業員別明細」の人数・氏名・年間合計が転記元と一致
- 「算定根拠」シートで役員除外の対象人数が想定通り
