## 1. 月列の意味と事業年度ズレ（最重要・落とし穴 ①）

### 1.1 なぜ「暦年」で入れると事故るか

ツール側（`hojokin/pipeline.py` の `_fiscal_month_order`）は、xlsx の月列を **事業年度開始月（決算月+1）から並べ替え** て R215/R216 集計に使う。
よって暦年データを入れると、**事業年度と半年〜数ヶ月ズレた金額** で集計されてしまう。

| 決算月 | xlsx の各列に入れるべき期間 |
|---|---|
| 12月 | 暦年と一致（2024年1月〜12月でOK）|
| 4月 | 2024年5月〜2025年4月（直近事業年度）|
| 3月 | 2024年4月〜2025年3月 |
| 9月 | 2024年10月〜2025年9月 |
| 6月 | 2024年7月〜2025年6月 |

### 1.2 PDF を跨いで抽出する手順

顧客から賃金台帳が **暦年区切り** で提供されているケースが多い（給与計算ソフト出力の都合）。
事業年度がカレンダー1月始まり以外の会社では、**2つの暦年PDFを跨いで12ヶ月を抜き出す** 必要がある。

例：4月決算 → 直近事業年度は 2024年5月〜2025年4月

```
事業年度: 2024年5月 6月 … 12月 | 2025年1月 2月 3月 4月
取得元PDF: ── 2024年1〜12月分PDF の後半 ── | ─ 2025年1〜12月分PDF の前半 ─
```

xlsx 上での配置（**月セルにはカレンダー月の支給額をそのまま入れる**）：

| xlsx列 | 入れる値（4月決算の例） | 事業年度内での位置 |
|---|---|---|
| 1月 | 2025年1月の支給額 | 9ヶ月目 |
| 2月 | 2025年2月の支給額 | 10ヶ月目 |
| 3月 | 2025年3月の支給額 | 11ヶ月目 |
| 4月 | 2025年4月の支給額 | 12ヶ月目（最終月）|
| 5月 | **2024年5月**の支給額（翌年5月ではない）| 1ヶ月目 |
| 12月 | 2024年12月の支給額 | 8ヶ月目 |

ツール側で並べ替えてくれるので、**xlsx のセルラベル（1月〜12月）はカレンダー月のラベルのまま** で良い。

### 1.3 直近事業年度の判定（再掲）

- 決算月から2〜3ヶ月後に確定するのが一般的（株主総会＋税務申告）
- 4月決算の会社の場合：
  - 5〜6月時点 → 直前の4月決算はまだ未確定 → **その前の事業年度** が直近
  - 7月以降 → 直前の4月決算が確定 → **その事業年度** が直近
- 迷ったら **Drive に置かれている最新の決算書 PDF が対象する事業年度** = 直近、と判定して良い

### 1.4 xlsx 注記の推奨

事故防止のため：
- ファイル名に対象期間を含める：`{会社名}_賃金台帳_2024-05_2025-04.xlsx`
- xlsx 最上部行に「対象期間: 2024年5月〜2025年4月」のメモ書きを残す（ツールは読まないが目視チェック用）
- セルフチェックの **最初の項目** として「対象期間が直近事業年度と一致しているか」を確認

## 2. 雇用形態ラベルの正規化（最重要・落とし穴 ②）

### 2.1 ツール側のロジック

`hojokin/wage_reader.py` の `_is_excluded_from_wage_total`：

```python
def _is_excluded_from_wage_total(emp):
    if '役員' in (emp.employment_type or ''):
        return True   # R216 集計から除外
    if not emp.is_full_year:
        return True   # 中途入退社（全月支給でない）も除外
    return False
```

**「役員」という文字列を含むかどうか** で判定している。

### 2.2 正規化が必要な表記

| 元 PDF の表記 | そのまま転記 | 正しい変換 |
|---|---|---|
| 代表取締役 | ❌ R216 に算入される | ✅ **役員** に置換 |
| 取締役 | ❌ 算入される | ✅ **役員** に置換 |
| 監査役 | ❌ 算入される | ✅ **役員** に置換 |
| 理事長 / 理事 / 監事（医療法人等）| ❌ 算入される | ✅ **役員** に置換 |
| 現場代理人 / 主任 / 営業（職位名） | △ | ✅ **正社員** に正規化 |
| 契約社員 | △ | ✅ **正社員**（フルタイム前提）|
| パート / アルバイト / 非常勤 | △ | ✅ **パート・アルバイト** |

### 2.3 個人事業主テンプレ選択時

個人事業主の場合、以下の追加ルール：

| 元 PDF の表記 | 正しい変換 | R216 への扱い |
|---|---|---|
| 事業主 / 個人事業主 | **役員** に置換 | 除外 |
| 専従者 / 青色事業専従者 | **正社員** に置換 | 算入 |

## 3. 通勤手当の扱い（落とし穴 ③）

### 3.1 採用列の判定

賃金台帳の列構成によって採用列が変わる：

| 賃金台帳の列構成 | G〜R 列に入れる値 | S 列「年間通勤手当」 |
|---|---|---|
| 「課税支給合計」列がある | その値をそのまま転記 | **空欄**（補正不要） |
| 「合計（通勤費込み）」列しか無い（一部の給与計算ソフト出力に多い） | 合計列をそのまま転記してOK | **非課税通勤手当の年間合計**を入れる → ツールが在籍月数で均等割減算 |

### 3.2 S列を使うメリット

- 月別に「合計 − 通勤手当」を手計算する手間が消える（22名×12ヶ月=264セルの計算が1値で済む）
- 中途者は **在籍月数で均等割** されるので、年間総額を入れるだけで月別に正しく分散される

### 3.3 注意事項

- 入れる値は **「非課税分のみ」**。月15万円超で課税扱いになった通勤手当があれば、その分は引かない
- 賃金台帳の「通勤手当」列を年間で合計するのが基本
- 通勤手当が変動する場合（電車通勤の運賃改定等）も、年間合計値で十分（厳密な月別控除が必要な案件はまずない）

### 3.4 動作例

- 山田次郎：12ヶ月在籍、年間通勤手当 36,000円 → 各月から 3,000円ずつ減算
- 佐藤三郎：6ヶ月在籍（中途）、年間通勤手当 18,000円 → 在籍6ヶ月から 3,000円ずつ減算
- 通勤手当列空欄 → 減算なし（既存動作と同じ）

## 4. 賞与の扱い

- 賞与は **R216 に含める**（IT導入補助金 2026 通常枠 公募要領 p.10「給料、賃金、賞与、各種手当…」と明記）
- 賞与シートが別 PDF / シートで分かれている場合は、該当月の金額に **加算** する
- 例：6月給与 25万 + 6月賞与 30万 → G列の6月セルに **55万** と記入
- 検証：賞与月（6月/12月など）の金額が他月の2倍以上になっていれば賞与込みで正しく入っている

## 5. 2ブロック印字型（医療法人等で頻出）

賃金台帳PDFが「従業員群を2ブロックに分けて印字」しているケース。
1ファイル = 1ヶ月分、横向き A3 スキャン画像。

```
┌─────────────────────────────────┐
│ 第1ブロック: 一般従業員（=役員除く）          │
│   個別行 × N人                              │
│   集計行（一般合計）                         │
├─────────────────────────────────┤
│ 第2ブロック: 役員                            │
│   個別行 × M人                              │
│   集計行（役員合計）                         │
├─────────────────────────────────┤
│ 全体合計行                                   │
└─────────────────────────────────┘
```

**ブロック識別の手がかり**：
- 「合計」「小計」「（一般）」「（役員）」のラベル
- 全体合計 = 一般集計 + 役員集計 のことが多い
- 個別行と集計行の見分けが OCR で曖昧な場合は、合計値で逆算検証する

## 6. ヘッダー認識でよくある障害

| 症状 | 原因 | 対処 |
|---|---|---|
| Streamlit で「必須ファイルが不足: 賃金台帳」 | Drive 上にファイル無し or 命名がマーカーから外れた | ファイル名末尾を `_賃金台帳.xlsx` または `賃金台帳一覧.xlsx` に |
| 役員が R216 に算入されている | 雇用形態が「代表取締役」等のまま | §2 の正規化ルールで「役員」に置換 |
| 中途者まで R216 に算入された | 退社月以降に 0 を入れた | 0 ではなく **空欄** にする |
| ヘッダーが認識されない | 「氏名」「1月」等の表記揺れ | 半角全角・スペース注意。テンプレを **コピーして使う** |
| 数字が文字列扱いになる | セル書式が「文字列」 | セル書式を「標準」または「数値」に |

ヘッダー別名辞書は `hojokin/wage_reader.py:122-133` 付近で定義。新フォーマットを足したくなったらここを編集対象として提案する。

## 7. 実テスト結果から得られたケーススタディ集（抽象化）

実案件 11 件の再現性テスト結果を、顧客情報を抽象化した形でパターン整理。SKILL.md §2.1 を補完する：

### 7.1 履歴事項証明書に役員あり、賃金台帳にも氏名あり（理想ケース）

- 観測例: 法人 4 件（中小法人・暦年決算 / 非暦年決算ともに）
- 代表取締役・取締役の氏名を履歴事項から取得 → 賃金台帳の氏名と NFKC 一致照合 → 該当者を「役員」に正規化
- 履歴事項の就任日と賃金台帳の支給開始月が時系列整合しているか確認（例: 5月就任 → 6月度から支給は妥当）

### 7.2 履歴事項証明書に「辞任」役員あり（除外パターン）

- 観測例: 1 件
- 履歴事項に「令和N年M月D日 辞任」記載の役員が、賃金台帳には在籍中として登載されている
- **現役の役員ではない**ため、賃金台帳側では「正社員」として処理（辞任後は一般従業員）
- 教訓：履歴事項証明書には辞任済み役員も記載される（抹消線・辞任日付付き）。**現役のみ抽出**する

### 7.3 履歴事項証明書に役員あり、賃金台帳に登載なし（別管理）

- 観測例: 2 件
- 代表取締役・取締役の氏名が履歴事項にあるが、賃金台帳の従業員リストに一人も該当しない
- 役員給与は別管理 or 無報酬の可能性 → 賃金台帳の全員「正社員」、B2 警告で要顧客確認
- 教訓：履歴事項に役員がいる ≠ 賃金台帳に必ず登載されている。**役員給与が別管理の可能性**

### 7.4 医療法人の登記スタイル（理事長のみ登記）

- 観測例: 1 件（医療法人）
- 履歴事項証明書に理事長 1 名のみ記載、他の理事・監事の登記なし
- 賃金台帳に理事長と同姓の従業員複数 → 理事長は確定「役員」、他の同姓者は §2.1 ステップ 2「同姓・低額一定」で役員候補警告
- 出勤日数変動のある同姓者はパートと判定（時給制の証拠）
- 教訓：医療法人では登記スタイルが特殊。**履歴事項取得済み = 全役員把握済み、ではない**。同姓者の §2.1 ステップ2 を併用する

### 7.5 履歴事項証明書なし＋PDF 役職欄空欄（最難ケース）

- 観測例: 2 件
- 履歴事項 PDF が案件フォルダに存在せず、PDF 役職欄も空欄
- §2.1 ステップ 2 を完全適用：
  - 会社名と同姓 + 月額完全一定 + 賞与残業なし + 社員番号体系不連続（他は 4 桁採番、対象は 2 桁若番） → 「役員候補（最有力）」として「役員」暫定転記＋ B2 警告
  - 同姓だが出勤や支給に変動がある場合は「正社員」or「パート・アルバイト」と判定
- 教訓：履歴事項なしでも §2.1 ステップ 2 の **4 条件（同姓 / 低額一定 / 高額一定 / 社員番号体系不連続）** を AND ではなく OR で適用すれば、役員候補の精度はかなり出る。最終確定はユーザー（顧客確認）に委ねる
