# 中身チェック手順（CC が Read で確認する項目）

## 第7次以降の適用（2026-11-04）

[変更点と使い方](../docs/第7次申請_変更点と使い方.md) と [確認待ち事項](../docs/第7次申請_確認待ち事項.md)、[公式資料で判断できることと確認の範囲](../docs/第7次申請_公式資料で判断できることと確認の範囲.md) を先に確認する。給与0年度目は見込み値（窓口担当が事務局に照会して確認済み）。給与の当期見込みと生産性の前事業年度実績を分け、過去交付歴・表明・対象人数・根拠の未確認をAIで埋めない。効果報告の比較基準は未確定で、今回は申請向け対応まで。

以下の加点条件は第7次以降用。第1〜6次の訂正・再出力には旧版を使い、公募回・実申請月・原本版を明示する。過去の検証日・会議発言・実装経緯は当時の記録であり、新要件の裏取りとして流用しない。

check_docs.py（決定論）が終わった後、`content_check_targets` の各ファイルについて
CC 自身が中身を確認する際のチェックリスト。判定は SKILL.md §5.1 の4値
（✅ / ❌ / ⚠️ / ❓）に落とす。**読めないものを推測で断定しない**（❓に降格）。

要件の根拠・原文は [../reference/必要書類マトリクス.md](../reference/必要書類マトリクス.md) を参照。

## 履歴事項全部証明書（registry）

- [ ] 表題が「**履歴事項全部証明書**」である（「現在事項全部証明書」「一部事項」「閉鎖事項」
      「登記情報提供サービス」の出力は❌＝再取得依頼）
- [ ] 末尾の証明文「…証明した書面である。令和◯年◯月◯日 ◯◯法務局」の**証明日**が、
      交付申請日（未確定ならチェック実行日で仮判定と明記）から遡って**3か月以内**
      （境界±7日は⚠️「申請日次第で失効」）
- [ ] **全ページ**そろっている（証明文＋登記官押印ページがある／ページ表記が連番／
      「以下余白」前の切断がない）
- [ ] 現役役員を列挙して報告に載せる（下線＝抹消・辞任/退任は除外、重任は継続。
      賃金台帳の役員行・ヒアリング役員数との突合材料）
  - 医療法人・一般社団・NPO 等は役員が登記されないことがある → 不在でも❌にせず⚠️
- [ ] リマインダ: 申請までに現役役員の**フリガナ**確認が必要（登記に無い）→ 常に報告へ

## 納税証明書（tax）

- [ ] 様式表題が「納税証明書（**その1**）」又は「（**その2**）」（その3/その4/領収書は❌）
- [ ] 税目: 法人=**法人税** ／ 個人=**所得税**（消費税等は❌）
- [ ] **対象事業年度が直近決算期と一致**する（決算書の期末日と突合。2年前のもの等は❌＝再取得依頼）
- [ ] **税務署発行**である（都道府県税事務所の法人事業税等は⚠️要確認）
- [ ] 電子納税証明書の場合、PDF形式発行のフォーマットである（XML の納税証明データシートは❌）
- [ ] 納税額 0円は **OK**（❌にしない。確認事項シート・マニュアルに明記）
- [ ] 発行日が古いだけ（年度は直近）の場合は❌にしない（有効期限の一次規定なし → 年度のみ見る）

## 決算書（pl）

- [ ] 期末日（「自◯年◯月◯日 至◯年◯月◯日」）を読み、**決算月と整合**するか
      （不一致は W-FISCAL-001 相当の⚠️。台帳・納税証明との三つ巴で矛盾があれば根本原因1件に束ねる）
- [ ] 複数PDFがある場合、**どれが直近期か**を各PDFの期表示で実測して報告
      （2期併記PDF＋単期PDF混在は前期誤選択の既知リスク）
- [ ] **直近2期分**あるか（社内運用。1期しか無ければ回収依頼へ）
- [ ] ページ構成: **貸借対照表・損益計算書・販管費明細書**（製造/建設業は原価明細も）が含まれるか
      （販管費明細が無いと給料手当・減価償却費の抽出精度が落ちる → ⚠️）
- [ ] 個人: 青色申告決算書（青色）/収支内訳書（白色）か。検算 ①売上−⑥差引原価=⑦差引金額
      が合わない場合は⚠️（原本目視へ）
- [ ] 粗利マイナス・括弧書き等の曖昧表記は❓（目視へ）。スキャン品質で読めない欄も❓

## ヒアリングシート（hearing）

様式判定・必須セル未記入・SECURITY ACTION「40」始まりは check_docs.py が機械判定済み。
CC が上乗せで見るのは:

- [ ] 「確認事項」シートの**『確認済』欄**の記入状況（GbizID/SECURITY ACTION/デジwith/
      成長加速/省力化ナビ）→ 未確認項目は⚠️
- [ ] 未記入とされた行の妥当性（「無」が正解の欄を無理に埋めさせない。
      例: 過去交付「無」なら申請年度以下は空欄で正常）
- [ ] 前期従業員数と賃金台帳の人数感が大きく乖離していないか（役員込み・中途除外の混同注意 → ⚠️）
- [ ] 通常枠: 「申請ツール名」と見積書のツール名の一致（→見積書の節）

## 賃金台帳（wage_ledger・テンプレ規格Excel）

ヘッダー規格は check_docs.py が機械判定済み（月の見出しはプレーンの「1月」〜「12月」か、連続する12か月の年付き「令和7年1月」「R7.1」「2025年1月」「2025/01」など（空白・改行は無視、末尾の「月」は任意。wagebook-convert の検算と同じ形）のどちらかにそろっていれば規格どおり。注記入り（「1月(R7.1)」など）・年付きとプレーンの混在・連続しない年月は TPL-WAGE-HEADER の FAIL。第7次以降の通常枠でプレーンの見出しは WAGE-HEADER-NO-YEAR の WARN＝年がないとツールが止まる）。CC が見るのは:

- [ ] B1〜B3 の注記等から、対象12ヶ月が**実績台帳として指定した事業年度**（案件の前提で決めた
      事業年度。決算月から導出）と一致するか（暦年1〜12月ではない）。食い違いは❌＝W-FISCAL-002
      相当で財務転記が停止する。どの事業年度を実績台帳に使うかの指定が無ければ、
      「直近事業年度」と決めつけず❓「未確定のため要指定」に回す
      - この判定は**実績台帳の用途に限る**。給与0年度目の当期見込みの根拠資料（期中の台帳）、
        生産性の基準（前事業年度の実績）、加点用の台帳（固定窓＋②基準月＋申請前月）は、
        それぞれの用途の対象年月で別に見る（必要書類マトリクス §2「賃金台帳・見込みの用途別対象期間」）。
        期中の台帳や加点用の台帳を「年度違い」として❌にしない
- [ ] 全員12ヶ月分あるか。空欄/0円/「非在籍」の月がある従業員を列挙（自動的に算定対象外になる旨と、
      支給日ベースの窓ズレで全月在籍者が欠けていないかの確認を促す → ⚠️）
- [ ] 月の欄（G〜R列）の文字列は「非在籍」だけか（「退職」「200,000」などの文字列はツールが空欄として読み、
      給与が黙って消える → ⚠️）。「非在籍」は名簿・入退社日で在籍していないと確認できた月（入社前・退職後）だけで、
      休職・産休・育休など在籍していて給与のない月は空欄のままか。第7次の通常枠では、非在籍でない空欄の月がある
      役員以外の従業員と、E列が空の役員以外の従業員でツールが止まる（⚠️）
- [ ] S列（年間通勤手当）は採用した旧実績台帳方式・原本内訳と照合し、既に除外済みの非課税分を二重控除していないか。旧全額控除と公式の課税給与定義による新規見込みを区別し、課税通勤を旧方式で控除した結果を新規見込みへ自動流用しない
- [ ] T列（年間賞与）: 賞与が月セルに混入していないか（他月比1.5倍超の月は⚠️）
- [ ] D列の役員ラベルが正規化されているか（「代表取締役」「理事長」等の生ラベルは⚠️）、
      パート行の E列（月間平均時間）・F列（時給）空欄は❌（FTE=1.0 サイレント昇格でR215過大）

## 賃金台帳（生台帳・給与ソフト出力）

- [ ] 生産性の基準（0年度目）は前事業年度実績、給与0年度目は申請当年度見込み。計画1〜3年度目は両指標とも申請翌事業年度・翌々事業年度・3期後で同じ期間となる。違うのは基準年度であり、計画1年度目を申請当年度にしない。対象資料を年度番号だけで取り違えていないか
- [ ] 通常枠の生産性は前事業年度実績と、計画1年度目＝申請翌事業年度から3年度目＝申請3期後までの確認済み計画（営業利益・人件費・減価償却費・総労働時間・根拠・確認状態）がそろっているか。通常枠150万円未満・任意賃上げなしでも省略せず、給与0年度目見込みと別に確認する
- [ ] 生産性の初年度・3年平均の3%／過去指定枠交付あり4%を検算したか。旧B42のOK表示だけを採用せず、未確認計画が残れば該当申請書の提出用確定出力を止める

- [ ] 期間表記が、**用途ごとの対象年月**をカバーしているか。実績台帳に使うなら指定した事業年度の
      12ヶ月、加点に使うなら固定窓＋②基準月＋申請前月（下の「加点判定用賃金台帳」の節）。
      指定した用途の年月と食い違う場合だけ❌。用途や対象の事業年度が未指定なら❓（未確定のため要指定）
- [ ] 変換が必要な旨を報告（ツール「賃金台帳の作成」タスク or wagebook-convert スキル）

## 加点判定用賃金台帳（シート『加点判定用明細』）

ヘッダー暦月固定・C2/C3 は check_docs.py が機械判定済み（AH〜AT列の見出しの年月違いは TPL-BONUS-BASIS-HEADER、AH〜AT列がない第7次台帳は BONUS-BASIS-LEGACY）。CC が見るのは:

- [ ] R列（交付申請直近月）にデータが入っているか（直近月＝交付申請月の**前月**）
- [ ] F〜R列が基本給（本給）だけで、AH〜AT列（時間換算の対象月額）が、その月の賃金から最低賃金の確認で除く6種類（臨時に支払われる賃金、1か月を超える期間ごとに支払われる賃金、時間外・休日・深夜の割増賃金、精皆勤手当、通勤手当、家族手当）を除いた額になっているか。基本給と職務手当・役職手当・資格手当などの手当は含め、基本給に固定残業代（みなし残業代）が入っていればその分は除く
- [ ] 歩合給・出来高給のある人は、AH〜AT列が「歩合・出来高以外の対象額 ＋ 歩合・出来高分 ×（その月の台帳の労働時間 ÷ その月の総労働時間）」になっているか。総労働時間を確かめられない月は空欄（未確定）のままで、原本で確かめる（⚠️）
- [ ] 在籍月に対象月額・基本給の空欄・0円があれば、加点の判定が未確定になる（⚠️）。対象月額が基本給より少ない月は判定を止めないが、固定残業代（みなし残業代）・欠勤控除・列の取り違えのどれに当たるかを雇用契約・賃金規程・原本で確かめる（⚠️。取り違えなら直し、それ以外は理由を報告に残す。対象月額を基本給に合わせて引き上げない）
- [ ] BONUS-BASIS-LEGACY の台帳で手当・歩合給・出来高給がある人、または基本給に固定残業代（みなし残業代）が含まれる人がいれば、最新の台帳テンプレートへの移し替えが要る（⚠️）
- [ ] 時給制・日給制・月変動者で S〜AE列（月別労働時間）が未入力なら、確認値が得られるまで加点の提出用確定出力を止める。E列の固定値・AIによる中央値や他月値では補完しない
- [ ] 月別時間を省略した月給者は、E列の代表所定時間の根拠と、その人の各省略月への適用を確認したか。173.33h・160h等の仮置きなら提出不可
- [ ] 在籍確認済みの資料不足と勤務時点・在籍不明を区別し、不明者を「データなし」として母数から落としていないか。「非在籍」は入退社日・名簿等で確認済みの月だけか
- [ ] 固定窓・②基準月・実申請前月の全指定年月を覆う疎明資料があるか。2冊固定にせず3期またぎも確認
- [ ] 医療・介護・社会福祉・学校教育系の法人名 → 賃上げ加点対象外の可能性を⚠️で明記

## 見積書（estimate）

- [ ] ツール/サービス名がヒアリング「申請ツール名」と一致するか
      （不一致は⚠️。事業内容255字でAIが別ツールを創作した実事故あり）
- [ ] 合計金額（税抜）が読めるか。**直近期売上の20%超なら申請不可要件** → ⚠️で明記
- [ ] 宛名が顧客名と一致するか（読めなければ❓）

## 本人確認資料（identity・個人のみ）

- [ ] 種別: 運転免許証/運転経歴証明書/住民票のいずれか
- [ ] 免許証: 交付申請日が有効期限内か／裏面変更履歴があれば裏面もあるか／全項目判読できるか
- [ ] 住民票: 発行日から3か月以内か（申請日基準）／マイナンバー非記載 or 黒塗りか
- [ ] 旧姓・外国籍: 納税証明書等と名前が異なる場合、両方の名前が分かる書類が併せてあるか

## 提出エビデンス（存在すれば中身も一目）

- [ ] IT戦略ナビwith: IT戦略マップのPDFか
- [ ] 成長加速マッチング: 「**掲載中**」の表示が見えるキャプチャか
- [ ] 賃金状況報告シート: 様式の種類・版・記入の有無
      - 版: B2 に「【第７次公募回以降用】」があるか。②は B4 が「令和8年6月の事業場内最低賃金+55円」か
        （旧版は「令和7年7月の事業場内最低賃金+63円」、①の旧版は「令和6年10月から令和7年9月」）。
        公募回7以上の案件で旧版なら❌（check_docs.py が `--call-round` 指定時に WAGE-REPORT-OLD-VERSION で
        機械判定。ファイル名に「賃金状況報告」が無い様式も、シート名で見つけて判定する）。第1〜6次（旧回）の
        訂正用の案件では旧版が正しい
      - 種類: 補助率引上げ・加点措置①用＝通常枠だけ、加点措置①用＝インボイス対応類型・電子取引類型・
        セキュリティ対策推進枠、加点措置②用＝全枠共通。枠と合わなければ❌
      - 中身の正しさ（母数・時間換算給与・判定）は katen-judge スキルの領域 → ここでは深追いしない
