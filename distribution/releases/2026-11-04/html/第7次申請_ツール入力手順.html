第7次申請：画面・ローカルCLIの入力手順

更新日：2026-11-04。配布案内は 変更点と使い方 を参照。この手順は改訂版のツール向けです。本番反映前の画面には新項目は表示されません。

画面で作成する場合

  1. 公募回、申請枠・法人格、実際の申請予定日を選びます。給与0年度目の開始・終了日は、その申請日を含む事業年度です。
  2. 申請額、実際の主たる事業場と申請画面用の地域別最低賃金額、交付決定歴を確認します。交付決定ありの場合は、年度・枠・類型をすべて入力します。曖昧な履歴を削って「なし」にしません。
  3. 適用除外と任意加点の希望を確認します。第7次以降は、賃上げ率の達成義務の有無と別に、全4原本で給与0〜3年度目の総額・対象人数（FTE）・算定根拠・担当者確認を入力します。表明の実施日・方法も事実に従います。
  4. 第7次以降の通常枠は、生産性1〜3年度目の営業利益・人件費・減価償却費・年間労働時間・根拠を別に入力します。計画1年度目は生産性も給与も申請翌事業年度です。基準だけが生産性は前期実績、給与は当期見込みと異なります。
  5. 生産性の基準として前事業年度の損益・年間労働時間を回収します。一部の人・月の時間しかない場合は提出用生成を停止します。労働時間が12か月揃っていても対象年月を確認できない場合は停止します。現行の決定論リーダーが年度情報を返せない台帳、在籍情報を確認できない短期入退社等は、個別確認へ回します。
  6. 不足表示を解消してから実行します。実行後に公募回・申請月・入力資料・計画値等を変えると、前の結果からダウンロードできなくなります。新しい条件で再実行してください。

加点判定には公募回に対応した専用台帳を使い、画面と台帳の申請月・事業場所在地をそろえます。所在地が食い違う場合も停止します。

ローカルCLIで作成する場合

開発リポジトリの run.py は、申請前提をUTF-8のJSONで受け取ります。配布プラグインのスキルを直接使う手順とは別です。

python -B run.py local --help

既存の入力フォルダ等の指定に、--application-context <確認済みJSONのパス> を加えます。対象は申請書作成を含む application / all です。管理表経由のDrive一括申請書作成は、新しい確認済み項目を管理表から取得できるまで停止します。

以下は未確認状態の雛形です。空欄・null・falseを実際に確認した内容へ置き換えます。このままでは提出用生成を通しません。第7次以降は forecast_years を0〜3年度目の4行入力します。賃上げ率の義務がないことだけを理由に空配列にしません。通常枠以外は productivity_forecast_years: [] を使えます。

  • 日付は YYYY-MM-DD、枠は 通常 / インボイス / セキュリティ。今回の4原本は通常・インボイスの法人／個人です。
  • past_grants: null は未確認、[] は交付決定なしと確認済み。交付決定ありは [{"year": 2024, "frame": "通常枠", "decided": true}] のように全履歴を記録します。曖昧な枠・類型は確定しません。
  • forecast_years は給与0〜3年度目の順です。人数変動がある場合も各年の確認値を入れます。自動の3%増額や前期実績の流用はしません。
  • productivity_forecast_years は生産性1〜3年度目の順です。生産性0年度目の前期実績は入力資料から取得し、3%／4%の初年度・3年平均を検算します。
  • source は算定根拠と確認記録です。数値を入れただけで confirmed: true にせず、対象範囲と年度も確認してください。
  • 複数県、算入範囲未確認等は manual_review_reasons に理由を入れ、解消するまで確定生成しません。

任意加点の最賃上乗せは通常150万円未満・インボイス・セキュリティの基本＋30円／更なる＋50円と、通常150万円以上の任意＋50円を分けて入力します。

不足・未確認はエラーとして表示し、申請前提の不備はAI抽出を始める前に停止します。前期の時間不足等は資料読取後に停止します。給与0年度目の見込み値と根拠は保存しますが、効果報告での比較基準は未確定のままです。
