第7次原本の改訂候補とDriveへの反映・再取込

更新日：2026-11-04。ここにあるものはローカル保有原本から作った改訂候補です。会社Driveの最新版との照合・書込みはまだ行っていません。

1. 用意したもの

  • ツール/第7次以降/：申請書4種類、ヒアリング4種類、加点専用台帳。第1〜6次用は元の場所に保存しています。
  • 補助金加点/第7次以降/：公式の第7次用3様式。取得した公式ファイルをそのまま保持しています。
  • scripts/build_round7_templates.py：旧原本からの改訂を再現する処理。入力セルの表示、関連リンク、最賃候補、制度版を限定して更新します。

社内原本の行・シート構成・図形等は維持しています。給与は0〜3年度目、FTEは確認済み入力とし、固定された過去年月を現役計画の年度表示に使いません。生産性の旧OK/NG判定は未確認表示に変え、申請書生成時に確認済み計画を検算します。表示文字だけでなく、クリック先も第7次公式様式へ変更しています。

2. 原本管理担当へ渡す改訂内容

  1. 加点①の期間と上限、加点②の基準月と55円、公式様式リンク、地域最賃候補を変更します。
  2. 給与0年度目を当期見込みと明示し、対象人数・根拠・確認状況を収集します。年度別FTEと詳細は生成物の「申請前提・給与見込」に保存します。
  3. 生産性の前事業年度実績と、申請翌事業年度から3年の計画を分けます。給与と生産性の計画1〜3年度目は同一期間です。
  4. 過去交付歴・表明方法・実施日・任意加点等は確認済みの事実だけを記録します。
  5. 回収資料は用途別の指定年月とし、2冊などの固定件数で依頼しません。

回収項目の案は公式入力に必要な情報から用意します。既存の調整済み票があれば共有してもらい整合させます。これは社内運用の調整で、事務局の定義が未公表という意味ではありません。

3. Driveへ反映する段階

会社アカウントと対象原本を確認し、既存原本をエクスポートしてバックアップします。今回の候補と最新版の差分を比較して、他担当者の変更を消さないようにします。

反映先と内容を確認してから、原本管理担当が新しい第7次版として反映します。旧版は元申請の訂正・効果報告用に残します。今回の修正作業だけではDriveへの反映は完了していません。

4. 更新後の再取込

この節のコマンドは管理者が開発リポジトリで実行します。プラグインだけを受け取った利用者に原本の上書きやパッチ実行を求めるものではありません。

  1. Driveの更新済み原本を、新しい作業フォルダへエクスポートし、取得日・対象版・ファイルのハッシュを記録します。既存ローカル原本に直接上書きしません。
  2. 通常枠個人の既存の機械修正が必要な場合は、次のように未使用の出力先を明示して実行します。--allow-new-input は内容確認を省く指定ではありません。想定セルが変わっていれば処理は停止します。

powershell python scripts/patch_genpon_tsujo_kojin_from_drive.py --input <新エクスポート.xlsx> --output <未使用の修正候補.xlsx> --allow-new-input

  1. 原本管理側で既に同じ修正が入っている場合、旧パッチを無理に適用しません。停止理由と差分を確認し、変更不要なセルを二重修正しないようにします。
  2. 行・設問に変更があれば、固定セルのマッピングとヒアリング判別を再測定します。旧版のマッピングを上書きして旧案件を壊さず、版別に検証します。行変更がない今回候補は既存の行配置を維持しています。
  3. 原本の制度版・4種類のラベル、給与と生産性の年度、リンク実体、プルダウン、数式、画像・保護を再読取で確認します。通常枠個人の既存構造検証と、新旧4原本の統合テストを行います。
  4. 配布元へ反映してコミット後、プラグインを再ビルドし検証します。Drive原本更新・本番反映・全員への配信は、それぞれ完了状態を分けて記録します。

5. 採用を止める条件

対象回が不明、旧版リンクが残る、ラベル・行の不一致、未確認の表明・交付歴、見込根拠不足、未確定の賃金・人数、意図しない数式や画像の欠落があれば、その候補を提出や配布に使いません。
