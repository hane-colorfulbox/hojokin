# 02 制度知識ベース（R215/R216・加点など）

補助金書類を作るうえで判断の根拠になる「制度ルール」を集約したファイル。R215/R216 や賃金台帳の扱いに迷ったら、まずここを読む。一次根拠は公募要領（末尾リンク）。本ファイルは社内ローカルの実務知識ベースを、配布できるよう個人情報・顧客情報を除いて再構成した版。

関連: 業務の全体像は [01](01_補助金とは_業務の全体像.md)、賃金台帳の実務手順は [04](04_賃金台帳の実務と落とし穴.md)、用語は [99 用語集](99_用語集.md)。

## 対象補助金

- 「デジタル化・AI導入補助金 2026（旧 IT導入補助金 2026）」の申請書類作成専用。
- 申請枠は3種：通常枠（法人） / インボイス対応類型（法人） / インボイス対応類型（個人事業主）。
- ヒアリングシート・申請書テンプレ・ツール・スキルすべてこの補助金を前提に作られている。
- 「中小企業省力化投資補助金」は別制度で対象外。R216 の定義はほぼ共通だが **R215 の算定方法が決定的に違う**（本補助金は FTE 換算の小数値、省力化補助金は頭数）。混同しない。

## R216「給与支給総額」の定義（最重要）

### 制度上の定義（公募要領 通常枠 p.10 原文）

> 算定対象となる給与等は、給料、賃金、賞与、各種手当（残業手当、休日出勤手当、職務手当、地域手当、家族（扶養）手当、住宅手当）等、**給与所得として課税対象となる経費**を指します。福利厚生費、法定福利費や退職金は除きます。

ここから導かれる実務ルール:

- **非課税の通勤手当（非課税限度内）は R216 に含めない**。「給与所得として課税対象」に当たらないため（国税庁 No.2585：通勤手当は限度額まで非課税）。限度超過で課税扱いになった分だけ含める。
- 実務上は賃金台帳の **「課税支給合計」列を採用するのが最も確実**。

### よくある間違い：通勤費込みの「支給合計」を使う

- 賃金台帳の「支給合計」列（通勤費込み）を R216 に転記するのは **過大計上で要領違反**。非課税通勤手当は税法上「給与所得」に含まれないので算定対象外。
- 別途「給与総額（通勤費込み）」シートを併走させる運用を見かけることがあるが、**R216 の転記元は「課税給与」シート一択**。「給与総額」シートを併走させる実務上の意味はない（申請書に転記する欄もない）。
- 口語の混同に注意：ポータル入力時に「差引給与額／課税対象額／総支給額」を言い直す場面があるが、採用すべきは一貫して **課税支給合計（給与所得として課税対象）**。非課税通勤手当が無い従業員では「総支給額」＝「課税支給合計」で一致するため口語で「総支給」と呼ぶことがあるが、通勤手当がある人では差が出る。「差引支給額（手取り）」は誤り。

### 役員の扱い（公募要領 p.10）

> 算定対象となる給与等は…**役員報酬…は除く**。
> ※ 従業員を雇用していない法人は、上記の従業員を役員と読み替え、役員報酬と役員数に応じて算出すること。

- 通常は **役員を除外**。
- 例外：**従業員を1人も雇用していない法人のみ**、役員を従業員として読み替えて算出。
- 個人事業主：事業主本人＝役員相当（除外）、専従者＝従業員相当（算入）。

交付申請マニュアル p.86 も同旨で、(a)「従業員を雇用していない」＝役員報酬・役員数 / (b)「従業員を雇用している」＝従業員ベース（役員報酬は算入しない）の二分。**(a)と(b)の中間（従業員はいるが全員が算定対象外）への明文はない**。

関連ルール（マニュアル p.86）：直近決算期の事業期間が1年に満たない場合は、事業期間を1年分に換算した数値を入力する。これは「全員が在籍12ヶ月未満」問題（設立間もない会社）への正規の対処になり得る（個人の在籍ではなく会社の決算期で判定する観点）。

> ⚠ 「従業員はいるが全員が在籍12ヶ月未満」のグレーケース：特例は文言上「従業員を雇用していない法人」限定。全員が中途扱いで除外され「対象従業員0名」になっても役員報酬ベースへ移行する明文はない。正規ルートは ①直近決算期が1年未満なら上記「年換算」、②それでも対象者が組成できなければ **事務局確認**。実務で役員報酬・役員数で算出した事例はあるが事務局確認推奨。ツールは自動で役員報酬を代入せず警告で人手判断を促す。
> なお「全月在籍だが支給日ベース台帳の窓が1ヶ月ズレて欠けた人」は**真の中途者ではない**ので、対象期間の窓を正せば全月そろい、役員報酬ベースに移る必要はない（下記「対象者範囲」参照）。

### 対象者範囲（公募要領 p.10）

> 対象となる従業員は…**全月分の給与等の支給を受けた従業員**とする。中途採用や退職等で全月分の給与等の支給を受けていない従業員については、…算出の対象から除く必要がある。
> 産前・産後休業、育児休業、介護休業など…時短勤務を行っている従業員は**算出対象から除くことができる**。

- 全月分支給を受けた従業員のみ算定対象（パート・非常勤含む）。中途入退社者は除外。産休・育休・介護休業の時短者は除外可（任意）。
- **真の中途者の按分（不足月を埋めて水増し）は不可**（要領に根拠なし）。
- **ただし「全月在籍だが台帳の窓が1ヶ月ズレて欠けた人」は別物**。支給日ベース台帳（「○月支給分」並び）では、対象期間の端で本来全月在籍の人の1ヶ月が窓から外れることがある。この人は本来「全月分支給を受けた従業員」＝算定対象。対応は ①対象期間の窓を事業年度に正しく合わせ直す（本筋）→ 記録が無いときのみ ②不足月を同額補完（次善策）。**この補完は全月在籍者に限り、真の中途者には使わない**。

### 給与支給0円・空欄の月がある従業員の扱い（運用で確定したルール）

- ルール最終形：**12ヶ月すべてが支給>0 の従業員のみ算定対象**。空欄（None）も 0円も負値も「支給を受けていない月」として同等に扱う。
- **賞与のみ受給者（全月0円＋賞与あり）も除外**（賞与も R216 に算入しない）。理由：対象従業員の定義が「**全月分の**給与等の支給を受けた従業員」であり、賞与が年1〜2回しかない人は「全月分」に非該当。
  - これは公募要領原文（通常枠 p.10・インボイス枠 p.11 同文）を確認のうえ社内判断で確定したルール（途中まで「賞与のみ受給者は算入」としていたが反転）。
- 根拠：公募要領 p.10「中途採用や退職等で全月分の給与等の支給を受けていない従業員は…除く必要がある」（除外義務）。休職は「除くことができる」（任意）。台帳上は中途と休職を判別できないため一律除外し、警告で手動修正経路を案内。
- 背景：不在月を0円で出力する処理があると、中途入社者が全月在籍扱いになり R215/R216 に誤算入される事故が起きる。ある個人インボイス案件では、これが原因で FTE と給与総額が過大計上され、担当者が手動で除外して是正した（このため自動除外ルールを整備した）。
- 手動修正の経路：休職等で算入したい場合は該当月を実支給額に修正。**0円月に賞与が支給されていた場合**は、テンプレの年間賞与列が支給月を持たず機械判定できないため、該当月に賞与額を記入し、年間賞与列から同額を差し引いて再実行（二重計上防止）。

### 採用すべき列（賃金台帳）

- 〇 **課税給与**（給与所得として課税対象の額）
- ✗ 給与総額（非課税通勤手当を含む場合がある）
- ✗ 差引支給額（社保・税控除後）

### 実務式

```
R216 = Σ(対象従業員ごとの12ヶ月分の課税給与) + Σ(対象従業員への課税賞与等)
       ただし役員除外、退職金・福利厚生費・法定福利費除外
```

### 関連する申請書フィールド（通常枠）

| 行 | フィールド | 内容 |
|---|---|---|
| R215 | 従業員数（FTE換算、役員除外） |  |
| R216 | 直近事業年度の給与支給総額 |  |
| R217 | 1年目計画（R216 × 1.03） |  |

### 未達のペナルティ

- 計画値未達は達成率に応じた**返還**。年平均成長率が0またはマイナスなら**全額返還**。
- R216 を低く見積もる（賞与漏れ等）と計画未達リスクが上がる。高く見積もる（役員報酬の混入等）と後年の効果報告で説明できなくなる。どちらにも倒さない。

## R215「従業員数」の算定方法

### 結論：パートタイムは正社員の就業時間に換算した人数（FTE換算、小数値）で記入する

申請書「申請内容」シートの R215「従業員数」には **FTE 換算後の小数値**を入力するのが公式仕様。公募要領 p.10 と交付申請マニュアル p.86 の両方で明示。

### 公募要領原文（通常枠 p.10）

> 1人当たり給与支給総額（非常勤を含む全従業員）とは、給与支給総額を従業員数で除したものをいう。…
> 対象となる従業員は…**全月分の給与等の支給を受けた従業員**とする。…
> また、**パートタイム従業員については、正社員の就業時間に換算して人数を算出すること。**

通常枠・インボイス対応類型・セキュリティ対策推進枠の3枠で同一規定。

### 交付申請マニュアル p.86 の算定例

> パートタイム・アルバイト従業員は、正社員の就業時間に換算した人数としてください。
> 例：週20時間勤務（正規雇用は週40時間労働）の場合 → **従業員数：20 ÷ 40 ＝ 0.5(人)**

### 算定式（実務）

```
R215 = Σ(対象従業員ごとのFTE換算後人数)

 対象従業員  = 全月分の給与等の支給を受けた従業員（パート・非常勤含む）
              − 中途採用や退職等で全月分支給を受けていない者（当該年度のみ除外）
              − 産前・産後・育児・介護休業による時短勤務者（除外可）
              − 役員（ただし従業員0名の法人は役員で代替算出）

 FTE換算後人数 = 正社員・契約社員 → 1.0
              パート/アルバイト → (実労働時間) ÷ (正社員の所定労働時間)
                例：週20h ÷ 週40h = 0.5人
              ツール実装では年間標準労働時間 2,080h を分母に使う
```

### 役員の扱い

- 通常：役員は R215 から除外。
- 例外：**従業員0名の法人**に限り役員を従業員として読み替えて算出。
- 個人事業主：事業主本人＝除外、専従者＝算入。

### 賃上げ「要件」との関連（公募要領 p.10-11）

R215・R216 から計算される **1人当たり給与支給総額**の年平均成長率が、申請枠と過去交付有無で異なる目標値の対象になる。

| 申請額・過去交付状況 | 年平均成長率の要件 | 賃金引上計画表明 |
|---|---|---|
| 150万円未満（過去 IT補助金2022〜2025 交付決定なし）| 3.5%以上 | 必須 |
| 150万円以上（過去交付決定なし）| 3%以上 + 事業場内最低賃金 ≧ 地域別最低賃金+30円 | 必須 |
| 過去 IT補助金2022〜2025 交付決定あり（150万未満）| 3.5%以上 | 必須 |
| 過去 IT補助金2022〜2025 交付決定あり（150万以上）| 3.5%以上 + 事業場内最低賃金+30円 | 必須 |
| 適用外（医療・介護・社会福祉・学校教育）| 要件適用外 | — |

### パート時間が取れないときの挙動（既知の運用）

- パート時間データが欠落すると、ツールは FTE=1.0 に昇格させる（安全側だが R215 過大・1人当たり給与過小になる）。
- 対応の優先順：①賃金台帳の段階でパートの時給と月平均労働時間を取り切る（顧客依頼時に明示・空欄なら再依頼） → ②取れない場合は現状の安全側挙動を維持しつつ画面に過大計上の可能性を警告 → ③会社全体平均で按分するのは母集団重複で数学的に不適切なので不採用。

## 加点措置・補助率引上げ（賃金台帳から判定する項目）

ツールが賃金台帳から判定するのは **加点項目14・15 の2項目のみ**。他の加点（クラウド/セキュリティ/インボイス対応/賃上げ計画/各種認定）は賃金台帳の外で確認する。

### 加点判定の2工程

加点判定は **専用の入力台帳が必要**（R215/R216 用の標準賃金台帳は不可）。標準台帳は月次「課税支給合計（総支給）」しか持たず、基本給・月別所定労働時間・従業員別都道府県が無いため、最賃比較の正式値を出せず正社員が判定からこぼれる。

1. **タスク「加点判定用賃金台帳の作成」**：生の賃金台帳/給与明細から基本給・所定労働時間を AI 抽出し、専用テンプレ（列は暦月固定 YYYY-MM＝令和6年10月〜令和7年9月＋交付申請直近月）に変換。基本給は **所定内賃金のみ**（残業・各種手当を含めない）。月別労働時間列（任意）があり、時給制等で月変動する人は月別値で換算、空欄の月は固定値にフォールバック。
2. **タスク「加点判定」**：専用台帳を決定論で直読みし、加点①②を判定して公式報告シートに転記。

> ★ 基本給/所定労働時間の抽出精度が補助率2/3 を左右する。出力台帳は提出前に必ず人手確認（最賃ギリギリ層は原本照合）。所定労働時間が取れない月給制正社員は固定値列が空欄になるため会社の月平均所定労働時間を手入力する運用。

最賃比較の正式値：**時間換算給与＝基本給 ÷ 月間所定労働時間**（残業・通勤・精皆勤・家族手当を除く所定内賃金）。

### 加点措置①（補助率引上げ・加点措置①＝加点項目14） ★補助率1/2→2/3 のトリガー

> （公募要領 p.18）令和6年10月から令和7年9月までの間で、「当該期間における地域別最低賃金以上〜令和7年度改定の地域別最低賃金未満」で雇用している従業員が全従業員の30%以上である月が3か月以上ある場合は、補助率 **2／3以内**。

> **【今年の事実＝要件】加点①「3か月」の自由度**
> - 3か月は **連続不要＝判定期間内で任意の通算3か月**でよい（公式①シート本文に「任意の３か月」と明記。2026年公募要領・公式様式とも「連続」「継続」の語は0件＝全文検索で確認済み）。
> - 判定期間 **令和6年10月〜令和7年9月は全社共通の固定窓**（暦の固定期間で、会社の事業年度・決算月とは無関係に動かない）。
> - 「連続3か月で・同一事業年度内で出す」のは自社の提出運用（見やすさ・事務局の原本照合のため）であって **要件ではない**。ツールも「任意3か月・固定窓」で判定するのでこの点のコード改修は不要。

- 提出物は **申請枠で1枚**（通常枠とインボイス/セキュリティ枠でデータ開始行が異なる＝補助率①用は19行目・①用は18行目始まり。ツールは申請枠に応じて1枚だけ出力する）。
- **判定下限は「>0」のみ**：公式シートの判定は `IF(AND(時間換算給与 < R7改定後, 時間換算給与 > 0), "対象", "対象外")`。文章では「改定前以上」とあるが、操作上の数式は **R7改定後 未満だけ**を見る（改定前は参考表示）。
- **役員は判定母数から除外**（最賃は労働者対象。R215/R216 と同じ役員定義）。
- **整数整合**：公式シートの時間換算給与列は整数（円）。ツールも `round(基本給÷所定時間)` で比較。
- 30%・3か月の閾値は公募要領どおり。対象3か月は既定で「30%達成月のうち比率が高い順」でシート出力する（連続とは限らない）。
- **決算月が9月以外だと判定期間が事業年度をまたぐ**：例）8月決算は「令和6年10月〜令和7年8月＝前期」＋「令和7年9月＝今期」。①シートは **1枚**で足り、前期・今期の賃金台帳を **2冊またいで**疎明資料に添付してよい（「年度ごとに2枚」は不要）。台帳1冊（1事業年度）に連続3か月を収めたいときは、前期台帳側に収まる連続3か月を選ぶ（窓の終端側＝今期台帳には窓内の月が1つしかないため「今期台帳だけで連続3か月」は作れない）。

### 加点措置②（加点項目15）

> （公募要領 p.26）交付申請の直近月における事業場内最低賃金を、令和7年7月の事業場内最低賃金＋**63円**以上の水準にしていること。

- 公式シートの判定：`差額 = 直近月の最低時給 − 令和7年7月の最低時給`、`IF(差額 < 63, "対象外", "対象")`。**事業場内最低賃金＝時間換算給与列の最小値（MIN）を公式シートが自動算出**する（D7＝基準月・D8＝直近月）。
- **直近月＝交付申請月の前月**（公式 `N14=EDATE(D5,-1)`、D5＝交付申請月）。ツールはサイドバーの「交付申請月」から直近月を確定する。申請月未入力だと②は判定不能。
- 役員除外・整数整合は①と同じ。

### 最低賃金マスタ・暦月マッピングの注意

- ツールの最低賃金マスタ（改定前・R7改定後）は公式シートのマスタと全47都道府県一致を確認済み。
- **地域別最低賃金は毎年10月に全国改定される**。加点①（改定前以上〜R7改定後未満）・加点②（令和7年7月＝前年度期 と 申請直近月＝当年度期 の比較）はこの最賃で判定するため、改定の取りこぼしは「古い値で資料を出す」事故に直結する。改定発効（10月）後の定期更新手順は [06 運用ルールと体制](06_運用ルールと体制.md) の年次更新節を参照。
- 加点①の対象期間（令和6年10月〜令和7年9月）と加点②の比較点（令和7年7月・申請直近月）は **暦月で固定**。Oct-Dec=令和6年・Jan-Sep=令和7年と年をまたぐため、R215/R216 用の「暦月12スロット配列」では表現できない。加点判定は (西暦年,月)→基本給 の辞書で扱い、専用台帳の列見出しを YYYY-MM 暦月固定にしている。
- 加点①は令和6年10月〜を見るため、**前事業年度を含む最大2事業年度分**の賃金台帳が入力に必要（R215/R216 の直近1期とは入力要件が異なる）。
- 対象暦月の基本給/所定労働時間が台帳に無い場合は、対象外に倒さず警告で明示（サイレント過少判定の禁止）。

### 加点・減点項目の全体像（公募要領 p.24-27）

- 加点項目：1)クラウド製品 2)サイバーセキュリティお助け隊 3)インボイス対応製品 4)デジタル化セカンドオピニオン 5)-8)賃上げ計画 9)IT戦略ナビwith 10)健康経営優良法人2026 11)えるぼし/くるみん 12)成長加速マッチング 13)省力化ナビ **14)加点措置①（補助率2/3トリガー） 15)加点措置②**。
- 減点項目：過去 IT/デジタル化補助金の交付決定、インボイス枠との機能重複申請、プロセス重複、賃上げ計画の未達歴 等。

### 賃上げの「要件」と「加点」を混同しない

- 申請額 **150万円以上**：賃上げ（給与総額成長率＋事業場内最低賃金+30円）は **必須要件**。未達なら返還。
- 申請額 **150万円未満**：賃上げは **加点項目扱い**（必須でない）。ただし IT補助金2022〜2025 で交付決定済みなら必須。
- 加点措置①②（項目14・15）は申請額に関わらず加点。①は補助率2/3 にも効く。

## 賃金台帳の構造解釈（制度的な読み方）

賃金台帳PDFが「従業員群を2ブロックに分けて印字」しているケースがある（給与計算ソフト出力の典型。1ファイル=1ヶ月分、横向きA3スキャン画像のことが多い）。

```
┌─────────────────────────────────┐
│ 第1ブロック: 一般従業員（=役員除く）          │
│   個別行 × N人                              │
│   「計」 ... 給与総額 / 課税給与 / 差引支給額  │
├─────────────────────────────────┤
│ 第2ブロック: 役員 + 特別職                   │
│   個別行 × 数人（例：理事長/監事 等）          │
│   「計」 ... 給与総額 / 課税給与 / 差引支給額  │
├─────────────────────────────────┤
│ 総計: 第1ブロック + 第2ブロック の合算        │
└─────────────────────────────────┘
```

R216 への変換（補助金定義に従う）：

- **第1ブロックの「計 課税給与」**＝役員除く一般従業員の課税給与 → R216 に算入。
- 第2ブロックは役員ブロック → **R216 から除外**。
- 総計は **使わない**（役員混入のため）。
- R215 と R216 は **同じ母集団**で揃える（段1=役員除くN名 と R215=N名）。

賞与シートの別建てに注意：

- 賞与は R216 に含める（公募要領で「賞与」明記）。給与シートとは別に「賞与シート」「ボーナスシート」がPDFに含まれることがある。別シートに「賞与」「ボーナス」表記があれば加算。賞与漏れは R216 過小評価＝計画未達リスク。
- **「段差が大きい月＝賞与」と短絡しない**。給与総額差 vs 課税給与差の比率で見分ける：本物の賞与なら課税給与側にもほぼ同等の増加が出る（比率 ≈ 1:1）。給与総額差が課税給与差の2倍以上に開く月は、別の現象（非課税通勤費の追加、読取ズレ、別ブロックの混入、役員臨時支給）を疑い、原本を確認する。

賃金台帳の読み取り手順・OCRの落とし穴は [04 賃金台帳の実務と落とし穴](04_賃金台帳の実務と落とし穴.md) に詳しい。

## ヒアリングシートと申請書の整合性

| ヒアリング項目 | 申請書欄 | チェックポイント |
|---|---|---|
| 正規雇用人数 | 従業員数（R215） | ヒアリングは役員を含む/含まない？ 賃金台帳の対象者数と一致するか |

## 非標準法人（医療法人・一般社団法人・NPO法人）の特殊処理

- **履歴事項全部証明書に役員情報がないケース**：商業登記でなく所管庁への届出で管理されるため、登記簿に理事・監事等が載らないことがある。事前に顧客へ個別ヒアリングで役職・氏名・役員数（複数の可能性）を確認する。
- **「資本金」概念がない法人**（一般社団・NPO等）：申請書の資本金欄には **資産合計（総資産）** を入力。対象事業年度（基準年度）の貸借対照表の数値を使う。

## AI抽出時の整合性チェック（データ品質）

- **決算書の括弧書き**：営業利益・損益で「（）」がマイナスを意味するケースとそうでないケースが混在する。単純な「括弧＝マイナス」では誤判別の可能性。会計式の内部整合でダブルチェックする（例：抽出した「粗利」と「売上高 − 原価」が一致するか）。不一致は人間目視へ。
- **損益計算書の異常値**（粗利マイナス等）：人間が見れば不自然な数値は AI 判定を信頼せず確認担当者が目視確認する。完全自動化はせずヒューマンチェックを挟む。
