# 07 ツールとローカルの役割分担

## 第7次以降の適用（2026-11-05 更新）

第7次（第7回公募）以降の案件は、まず [第7次申請 担当者向け要点](../docs/第7次申請_担当者向け要点.md) を読む。詳しい根拠は [変更点と使い方](../docs/第7次申請_変更点と使い方.md)、[公式資料で判断できることと確認の範囲](../docs/第7次申請_公式資料で判断できることと確認の範囲.md)、[確認待ち事項](../docs/第7次申請_確認待ち事項.md) にある。

- 給与の0年度目（交付申請日の属する事業年度）は見込み値で入力する。窓口担当が事務局に照会して確認済み。
- 給与0年度目の見込みと、労働生産性の基準になる前事業年度の実績は、別のデータとして集める。
- 過去の交付歴・従業員への表明・対象人数・根拠は、確認した事実だけを使う。分からないものはAIで埋めず、確認できるまでその数値を確定しない。
- 効果報告で何と比べるか（申請時の見込みか確定実績か）は未確定。今回の対応は申請までとする。

以下の加点条件は第7次以降用。第1〜6次（旧回）の訂正・再出力には旧版の様式とルールを使い、公募回・実際の申請月・原本の版を明記する。過去の検証日・会議での発言・実装の経緯は当時の記録で、第7次の要件の裏取りには使わない。

「ツール（Streamlit Cloud の書類作成ツール）」と「ローカル（Claude＋補助金プラグインのスキル。claude.ai のチャット・Cowork・Claude Code のどれでも使える）」のどちらで何をやるかの総覧です。迷ったらこの1枚を見てください（2026-07-21 の3次申請振り返りで確定した体制。2026-07-28 に現状に合わせて更新）。

## 基本の考え方

- **基本はローカル（Claude＋補助金プラグインのスキル）**。最も精度の高いモデルで PDF を読み、検算・感度チェックまで含めた丁寧な作業ができる。ツールにできない作業もある（PDF 台帳からの加点判定、案件フォルダの必要書類チェック、原本転記シート付きの台帳変換）。手書き・画像 PDF、100名超の台帳、判断の割れる案件は迷わずローカル。
- **ツールの利点は速さと手軽さ**。ブラウザだけで動くので、ローカル環境が無い人・ローカルに不慣れな人はこちらを使う。急ぎで定型の書類を出すときも速い。反面、複雑な判断・大規模な処理・PDF の丁寧な読み取りはできない。
- **ツールとローカルの情報・出力規格は常に一致させる**。同じテンプレ列・同じ補助金ルール（R215/R216・加点の定義）で動く。規格を変えたら必ず両方を同期する（正本ルール: 開発リポジトリの設定ファイル「賃金台帳の回収方針」（社内開発側の資料・配布対象外））。

## タスク×経路の総覧

| タスク | 標準経路 | もう一方の扱い |
|---|---|---|
| 申請書の作成（通常枠・インボイス枠 × 法人・個人事業主の4通り） | **ローカルでもツールでも作れる**（下の「申請書作成の経路」参照）。ローカルは [マニュアル_書類作成](../docs/マニュアル_書類作成.md) §2 の手順。**枠と法人格の両方でテンプレが変わる**ので取り違えに注意 | ツール「申請書作成」タスク。ブラウザだけで完結して速い。ローカル環境が無い/不慣れな人はこちら |
| R215/R216 の算定・検証 | **ツール**（「一人当たり給与支給総額」タスク）。ローカルには算定を回す実行入口が無い（判定エンジン `hojokin/wage_calculator.py` は同梱しているがスクリプト未整備） | ローカルは入力 Excel（賃金台帳）の作成と、出た数字の検算を担当 |
| 賃金台帳 PDF → 規格 Excel 変換 | **ローカル**（`wagebook-convert` スキル。標準・精度優先。出力に原本転記シート群＝PDF全ページ・全項目の転記付き） | ツール「賃金台帳の作成」は速さ優先・CC 環境が無い/不慣れな人向けの代替（原本転記シートは付かない。転記が要る案件はローカルへ） |
| 加点判定（賃上げ加点①②・補助率2/3） | **ローカル**（`katen-judge` スキル。PDF台帳→専用台帳→判定→公式様式①②まで完結） | ツールの「加点判定用賃金台帳の作成」「加点判定」タスクは Excel 入力用（PDF 未対応） |
| 案件フォルダの必要書類チェック | **ローカル**（`case-docs-check` スキル。Drive 読み取り専用） | ツールに同等機能なし |
| セカンドオピニオン加点の面談準備 | **ローカル/チャット**（プロンプト2本立て: 07B 確認メール → 06 予約フォーム入力文。07・06B は使わない） | ツールに同等機能なし |
| 台帳を出したくない顧客の総額提出 | 顧客が**総額提出用テンプレ**（`ツール/賃金台帳（総額提出用）テンプレート.xlsx`）に自己記入 | 記入結果の検算はローカル・ツールどちらでも可 |

## 申請書作成の経路（2026-07-28 時点の実際）

申請書だけは、他のタスクと違って**ローカル側の整備が途中**です。事実として次の3通りがあります。

1. **ローカル・Claude Code に直接やらせる**（[マニュアル_書類作成](../docs/マニュアル_書類作成.md) §2 のコピペ手順）。API キーは要らない。**専用スキルは無く、申請書テンプレ原本もプラグインには基本的に同梱していない**（Drive 上の原本を使う。例外は通常枠×個人の修正版原本で、hojokin-guide スキルの `ツール/` にある）。
2. **ツールの「申請書作成」タスク**。ブラウザだけで完結し、いちばん速い。テンプレ側の細かい是正（プルダウンのずれ・結合セル・計画値の切り上げ・事業内容255字への導入ツール注入など）が積み上がっているのはこの経路。v0.2.96 からは Drive 原本のツールマスタ連動（ツール名を選ぶと申請内容3項目が自動入力）・費用内訳マスタ（申請金額シートの内訳自動引当）もツール同梱テンプレに採用済み。マスタ未登録のツールでは3項目が空欄になり警告 `[W-TOOL-001]` が出る（[03 ツールの仕組みと使い方](03_ツールの仕組みと使い方.md) 参照）。
3. **ローカルでツールと同一コードを回す**（リポジトリがある環境のみ。`python run.py local --task application …`）。`CLAUDE_API_KEY` が要る。`--template` は4通り（`通常枠_2026` / `通常枠_個人_2026` / `インボイス枠_2026` / `インボイス枠_個人_2026`）から選ぶ。

迷ったら 1 か 2。**急ぎ・不慣れなら 2、資料の読み取りが難しい案件は 1**。どちらで作っても、出力後に人手で確認する前提は変わりません（空欄・金額・日付）。

## 補助金プラグイン（hojokin）の中身

- スキル4本：`hojokin-guide`（業務ガイド＝この引き継ぎ資料と社内マニュアル）・`wagebook-convert`（台帳変換）・`case-docs-check`（書類チェック）・`katen-judge`（加点判定）
- 判定エンジン：katen-judge スキルの中の `hojokin/`（ツール本番と**同一のコード**。プラグインを作るたびに開発リポジトリからコピーされるため、ローカルとツールで判定結果がズレない。**編集しない**）
- テンプレ・公式様式：katen-judge スキルの `ツール/加点判定用賃金台帳テンプレート.xlsx` と `補助金加点/`（加点の公式様式3枚）。**申請書テンプレ原本は通常枠×個人の修正版だけを同梱**している（hojokin-guide スキルの `ツール/`。他の3通りは Drive 上の原本を使う）。Drive には4通り（通常枠×法人／通常枠×個人／インボイス枠×法人／インボイス枠×個人）が置いてある
- チェックリスト：`docs/チェックリスト_加点判定.md`（加点判定の実行手順の正本。katen-judge と hojokin-guide の両方に入っている）
- 実行環境：Python 3.10+ ＋ openpyxl だけで動く（pandas 等は不要）。claude.ai のチャットではコード実行の環境で動く

## 出力規格の同期ルール（ズレると事故になる約束事）

1. **賃金台帳テンプレの列・補助金ルールを変えたら、ツールとスキルの両方を直す**（過去例: T列「年間賞与」追加時は両テンプレ＋配布物を同期）。
2. **原本転記シートの名前規約**：スキル出力の PDF 丸ごと転記シート群（表紙＋ページ別 `原本転記_pN`）は、シート名を「原本転記」で始める。ツールのリーダーはこの名前の可視シートを全経路で読み飛ばす（v0.2.91〜）。**どちらか片方だけ変えてはいけない**（リネームするとツールが表として誤読し R215/R216 を壊す）。転記の中身は**全ページ・全項目**が規格（集計行だけの転記は不可。2026-07-26〜）。
3. **加点判定用テンプレを変えたら両系統を同期**（考え方は標準台帳と同じ）。
4. 賃上げ計画値は**常に切り上げ**（2026-07-21 決定。四捨五入だとポータルの伸び率が 2.9% 表示になる1円事故があるため）。
