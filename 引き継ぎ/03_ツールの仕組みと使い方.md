# 03 ツールの仕組みと使い方

このパックの索引は [00 はじめに](00_はじめに.md) を参照。制度ルール（R215／R216・加点の意味）は [02 制度知識ベース](02_制度知識ベース.md)、賃金台帳の実務面は [04 賃金台帳の実務と落とし穴](04_賃金台帳の実務と落とし穴.md) にまとめてある。本章は「ツールが何をするものか」「どう動かすか」「どこを触れば安全に挙動を戻せるか」を扱う。

---

## 1. ツールの全体像

このツールは、デジタル化・AI導入補助金（旧IT導入補助金）の申請書類を、ヒアリングシート・PDF資料・Excel賃金台帳から AI で自動生成する仕組み。手作業の転記・計算を半自動化するのが目的。

- 本番はクラウド上（Streamlit Cloud）で常時動いている。URL: https://hojokin-uymden838zfglt9uahkapf.streamlit.app
  - Streamlit とは、Python のコードをそのまま Web 画面（ブラウザで使えるアプリ）にしてくれる仕組み。ファイルをアップロードして実行ボタンを押す、という普通の Web アプリとして使える。
- コード修正を本番に反映する手段は **`main` ブランチへの git push のみ**。push を検知してクラウドが自動的に作り直す（自動再デプロイ、通常1〜2分）。
- ローカルでの「再起動」「立ち上げ直し」「キャッシュ削除」といった作業は不要。本番アプリはクラウド側で動いており、手元では Streamlit を立てていない。
- ロールバック（不具合時に前の状態へ戻す）は、`git revert`（問題のコミットを打ち消す）か、後述の運用フラグの切り替えで行う。

> 操作の具体手順（VSCode での Claude Code の使い方、コピペ用プロンプトなど）は [マニュアル_書類作成](../docs/マニュアル_書類作成.md) にある。本章はその前提となる「仕組み」を説明する。

## 2. ツールの4つのタスク

ツールは大きく4つのタスクに分かれる。それぞれ「何を入力に、何を出すか」が決まっている。

### (a) 申請書作成

- 入力: ヒアリングシート、履歴事項全部証明書（登記簿）、損益計算書などの決算書、見積書 ほか
- 出力: 申請書テンプレートに各値を転記した Excel（`{顧客名}_{枠名}_AI版.xlsx`）
- 内容: 登記簿から法人名・所在地・代表者・設立日・資本金、決算書から売上高・利益・給料手当などを読み取り、申請書の各シートへ転記する。業種コード・経営状況の判定・地域別最低賃金など、AI 判断が要る項目も可能な範囲で埋める。
- **個人事業主の案件では登記簿（履歴事項全部証明書）が存在しない**。屋号・現住所・生年月日・事業開始年月日はヒアリングシートから取り、資本金は0・決算月は12月固定。決算書は所得税の青色申告決算書（白色申告なら収支内訳書）。「登記簿が無いから資料不足」と判断しないこと。
- 補足: テンプレート原本は変更しない（コピーを作って書き込む）。完了後に空欄が何件残ったかを報告する作りで、空欄は確認担当者がミーティングで詰める前提。
- 経路: 申請書はローカル（手元の Claude Code）でも作れる。手順は [マニュアル_書類作成](../docs/マニュアル_書類作成.md) §2、使い分けは [07 ツールとローカルの役割分担](07_ツールとローカルの役割分担.md)。ツール経路の利点はブラウザだけで完結する速さ。
- 事業内容（255字）の生成では、申請者が導入する ITツールの実機能をプロンプトに注入して精度を上げる仕組みがある（tool_catalog、v0.2.76〜）。画面に「導入ツール（255字の根拠）」プルダウンがあり、既定＝自動判定／手動上書き／該当なし＝汎用生成。ツールを引き当てられない・曖昧・素材未整備のときは注入なし＝従来どおりの生成に自動で倒す（後方互換）。
- 申請内容の3項目（業務プロセス改善・強化したい部門・期待効果。通常枠法人C179〜C181／**通常枠個人C151〜C153**／インボイス法人C164・C165）は、テンプレ内のツールマスタ連動で自動入力される（v0.2.96〜、Drive 原本の仕組みを採用）。テンプレのツール名セル（通常枠法人C71／**通常枠個人C74**／インボイスC61）をプルダウンで選ぶと、マスタシート（通常枠「シート9」／インボイス「ツールマスタ」）から VLOOKUP で引き当てる。**セル番地は枠だけでなく法人格でも変わる**ので、マスタシートの案内文（各テンプレ内に書いてある）を見ること。マスタに未登録のツール・登録行が未入力のツールでは3項目が空欄になり、ツールは警告 `[W-TOOL-001]` を出す。その場合はマスタシートに行を足すか、3項目を手動入力する。

### (b) 給与支給総額計算

- 入力: 賃金台帳（または月次の給与支給控除一覧PDF）、損益計算書
- 出力: 給与支給総額計算の Excel（`{顧客名}_給与支給総額計算.xlsx`）
- 内容: 賃金台帳・決算書から、補助金で言う **R215（FTE換算の従業員数）** と **R216（給与支給総額）** を算定する。役員報酬の控除、パート・アルバイトのFTE換算（フルタイム何人分か）、1人当たり給与支給総額まで出す。
- R215／R216 の制度的な意味は [02 制度知識ベース](02_制度知識ベース.md)、賃金台帳の読み取り上の注意は [04 賃金台帳の実務と落とし穴](04_賃金台帳の実務と落とし穴.md) を参照。

### (c) 加点判定用賃金台帳の作成

- 入力: 生の賃金台帳・給与明細（PDF/Excel/CSV）
- 出力: 加点判定専用の台帳 Excel（`{会社名}_加点判定用賃金台帳.xlsx`）
- 内容: 賃上げ加点の判定に必要な **基本給** と **月間所定労働時間** を、暦月固定（決まった年月の並び）で並べた専用台帳を作る。給与支給総額用の標準賃金台帳とは別物で、加点判定にはこの専用台帳が必須。
- 注意: AI が所定労働時間を取れなかった人は欄が空欄になる。その場合は会社の月平均所定労働時間を手入力して補完してから次の (d) に進む。

### (d) 加点判定

- 入力: (c) で作って人手確認した加点判定用台帳
- 出力: 加点判定結果の Excel（通常枠は補助率引上げ・加点措置①／インボイス・セキュリティ枠は加点措置①、および加点措置②）
- 内容: 「時間換算給与＝基本給 ÷ 月間所定労働時間」を最低賃金と比較し、補助率引き上げ・加点の対象になるかを判定する。
- コスト: 加点判定タスクは専用台帳を決定論（ルールベース）で直読みするだけで **AI（API）を呼ばない＝APIコスト0円**（v0.2.82）。
- 提出シート: 判定結果に加え、**事務局へ提出する公式様式シート（補助率引上げ・加点措置①用／加点措置②用）**まで生成する。以前は公式様式が本番に配備されておらず、判定は出るのに提出用シートが無警告でスキップされる不具合があった（v0.2.83 で様式を同梱し、欠落時は警告表示、DLボタンに「事務局提出用」と明記して是正）。
- 注意: **抽出精度が補助率2/3 を左右する**。最低賃金ぎりぎりの人は必ず原本と突き合わせる。役員は判定の母数から除外される。

> (c)(d) は「2工程」で1セット。①専用台帳を作る → ②その台帳で判定、の順で動かす。加点制度そのもの（何点で何が変わるか）は [02 制度知識ベース](02_制度知識ベース.md) を参照。

> 加点系タスク（(c)(d)）は暦月固定（令和6年10月〜）で判定し、決算月を使わない。そのため画面では **決算月セレクトが非表示**になり、資料の差し替えUIも賃金台帳だけに絞られる（v0.2.81）。R215/R216 用の (a)(b) とは入力の考え方が違う点に注意。

## 3. コアパッケージ `hojokin/` の各モジュールの役割

`hojokin/` フォルダに、ツールの中身が機能ごとのファイル（モジュール）に分かれて入っている。非エンジニア向けに、各ファイルが「業務上どんな仕事をしているか」を1行ずつ示す（実装の中身ではなく役割）。

| ファイル | 役割（業務上の意味） |
|---|---|
| `ai_extractor.py` | PDF や Excel から必要な情報を AI で読み取る（登記簿・決算書・見積書・賃金台帳の抽出担当） |
| `wage_reader.py` | 賃金台帳を読み取り、役員かどうか・全月在籍かどうかを判定する |
| `wage_calculator.py` | R215（FTE換算の従業員数）と R216（給与支給総額）を算定する計算担当 |
| `wage_ledger_writer.py` | 給与支給総額計算シートへ結果を書き込む |
| `bonus_wage_ledger_writer.py` | 加点判定用の専用台帳に結果を書き込む |
| `pipeline.py` | 上記の処理を順番に呼び出し、全体の流れを取りまとめる司令塔 |
| `template_filler.py` | 申請書テンプレートの所定のセルへ値を転記する |
| `pdf_reader.py` | PDF からテキストや画像を取り出す（AI に渡す前の下準備） |
| `config.py` | 最低賃金マスタや各種しきい値など、ツールが使う定数をまとめて持つ |
| `google_drive.py` | Google Drive と連携する（ファイルの保存・取得） |
| `google_sheets.py` | Google スプレッドシートと連携する（管理表の読み書き） |

> 上記以外にも `hojokin/` には補助的なファイルが複数ある（PDFのテキスト化、レイアウト解析、検証、警告カタログ、データ構造の定義、API記録など）。実際のファイル一覧は `hojokin/` フォルダで確認できる。ここでは引き継ぎで押さえるべき主要モジュールに絞った。

## 4. 安全に挙動を切り替えるフラグ（ロールバック）

不具合が出たときや、コストを抑えたいときに、コードを書き換えずに挙動を切り替えられる「フラグ」が用意されている。値は環境変数（本番では Streamlit Cloud の Secrets）で設定する。各フラグの意味は次のとおり。

| フラグ | デフォルト | 何のフラグか |
|---|---|---|
| `USE_AI_WAGE_EXTRACTION` | `true` | 賃金台帳をAIで抽出するか。`false` にすると旧経路（決定論パーサー＝ルールベースの読み取り）だけに戻す |
| `CLAUDE_MODEL` | `claude-sonnet-4-6` | 抽出（画像/PDF読み取り）に使うAIモデル |
| `WRITING_MODEL` | `claude-opus-4-8` | 文章生成（事業内容など）に使うAIモデル。`claude-sonnet-4-6` にすれば生成もSonnetに戻せる |
| `USE_STRUCTURED_PL_EXTRACTION` | `true` | 損益計算書（PL）の抽出を構造分解（複数回に分けて読む）方式にするか。`false` で旧1回呼び出し方式 |
| `USE_PL_PAGE_INVENTORY` | `true` | 構造分解PL抽出で、ページの多いPDFを先に分類し関連ページだけAIに送る（年度の混入防止・コスト削減）。3ページ以下はスキップ |
| `USE_PROMPT_CACHING` | `true` | 賃金台帳PDF抽出で、固定の指示部をキャッシュして入力トークン費用を下げる |
| `USE_PDF_TEXT_PREPROCESSING` | `false` | 賃金台帳PDFを画像でなくテキスト化してAIに渡す。コスト減を狙うが精度低下リスクがあり既定OFF（案件ごとに確認後に有効化） |

> 困ったときの最初の一手として覚えておくべきは `USE_AI_WAGE_EXTRACTION=false`（AI抽出を旧経路に戻す）。各フラグの一覧は上の表のとおり。

## 5. AIモデルの2系統

ツールは用途に応じてAIモデルを2系統に分けて使っている。

- 抽出（登記簿・決算書・見積書・賃金台帳など、書類からの読み取り）= Sonnet（画像/PDFを画像のまま見る方式を維持）。レイアウトが命の財務書類で実績があり、回帰（精度の後戻り）を避けるため。
- 文章生成（事業内容255字など、判断して文章を書く処理）= Opus。「文章を書く処理だけ Opus」という方針。

それぞれ第4節のフラグ（`CLAUDE_MODEL` / `WRITING_MODEL`）で差し替えられる。

## 6. テスト方針

- **テスト実行時に本番のAI（Anthropic API）は絶対に呼ばない**。API課金ゼロが原則。テスト用コードは代用品（スタブ／モック）で動くように作られている。
- 大規模な変更をしたあとは、`_debug/` フォルダのテストを回し、回帰（既存機能の壊れ）がないことを確認してから push する。
- モデルの既定（Sonnet/Opus）を変えても、テストはAPIを呼ばないため影響を受けない。

## 7. 警告番号（W-XXX）で困りごとを引く

ツールが出す警告は番号（`W-XXX` 形式）で管理されている。番号から意味と対処を引けるので、「この番号が出たらこれを見る」という運用ができる。分類の頭文字：`W-DESC`（事業内容）／`W-FISCAL`（決算期・事業年度）／`W-WAGE`（賃金台帳）／`W-PL`（損益計算書）／`W-DRIVE`（Drive 連携）。よく出るもの：

- `W-WAGE-002` … 0円・全月在籍でない従業員を算定から除外した（画面ではグレー表示）。休職等で本来算入したい場合は該当月を実支給額に直して再実行する。
- `W-DRIVE-001` … Drive への自動保存が権限不足（403）で失敗。保存先フォルダにサービスアカウントが「投稿者」権限で共有されているか確認する（年度フォルダ新設時に共有漏れが再発しやすい）。

番号と対処の一覧は [警告一覧](../docs/警告一覧.md)（配布物に同梱）にまとまっている。
