# 補助金業務ガイド

デジタル化・AI導入補助金（旧IT導入補助金）の申請支援業務について、社内で分かっていることをまとめた手引きです。補助金に関する質問・作業では、まずこのファイルを読み、下の「どこを読むか」に従って同梱の資料を読んでから答えます。

- 書類作成ツール（本番・Streamlit Cloud）: https://hojokin-uymden838zfglt9uahkapf.streamlit.app （スリープしていたら復帰ボタンを押して1分ほど待つ）
- このスキルは組織のプラグイン「hojokin」の一部で、管理者が直すと自動で最新になります（ダウンロードや展開は不要）。

<!-- skill-paths:begin -->
**パスの書き方**：この文書の `${CLAUDE_SKILL_DIR}` は、このスキルのフォルダ（この SKILL.md があるフォルダ）の絶対パス。Claude Code と Cowork では自動で置き換わる。claude.ai のチャットで `${CLAUDE_SKILL_DIR}` の文字がそのまま見えている場合は、この SKILL.md を読み込んだフォルダに読み替える。コマンドの `python` が見つからない環境では `python3` を使う。

## 2. いつも守るルール

1. 答える前に、上の振り分けで該当する資料を読む。資料に書いていないことは「資料に書いていない」と言い、推測で埋めない。
2. 制度の数値（R215/R216 の定義、最低賃金+63円、暦月固定など）は1文字違うと申請が狂う。02 と、必要なら 02 末尾の公募要領（一次資料）で裏を取る。
3. 🔴 案件を扱う前に「申請枠」と「法人／個人事業主」の2つを必ず確定する。当社が扱うのは 通常枠×法人 / 通常枠×個人事業主 / インボイス枠×法人 / インボイス枠×個人事業主 の4通りで、申請書テンプレもヒアリング様式も4通りそれぞれ別物。枠だけで決めると、法人用テンプレで個人事業主の申請書を作る事故になる（役員欄・資本金・決算月・計画年度が全部食い違い、しかも空欄の数には出ない）。対応表は [docs/弊社成果物と書式.md](docs/弊社成果物と書式.md) §3。
4. 通常枠も個人事業主が申請できる。古い資料の「通常枠は法人のみ」は誤り。個人事業主には履歴事項全部証明書が無く、決算書は所得税の青色申告決算書（白色なら収支内訳書）。
5. 賃金台帳の月列は「直近事業年度の12か月」（暦年ではない）。反対に、加点判定用の台帳は暦月固定（令和6年10月〜令和7年9月＋交付申請直近月）。取り違えやすいので毎回確かめる。
6. R215/R216 の対象は、12か月すべてに支給がある従業員だけ（役員は除外、中途入退社者は除外）。個人事業主は事業主本人を除外し、専従者は算入する。
7. 通勤手当は、課税・非課税を問わず給与支給総額（R216）から控除する（2026-07-27 の運用変更）。ただし引くのは「月列に採用した値に実際に含まれている分」だけ（04 の落とし穴(3)）。額が特定できないときは引かずに、そのことを報告に明記する。
8. 賃上げ計画値の要件は、過去に IT補助金2022〜2025 の交付決定を受けた事業者だと3.5%（ツールの計画値は3%固定なので、該当案件は手で3.5%に上げる）。詳細は 02 の賃上げ要件の節。
9. 加点判定は、標準の賃金台帳ではなく専用の加点判定用台帳で行う（katen-judge スキル）。判定エンジン（katen-judge スキル内の `hojokin/`）はツール本番と同じコードなので編集しない。
10. ★グレー（事務局に未確認の解釈）の論点は断定しない。案件で当たったら、判定を「暫定」と明示して窓口担当に確認する。

## 3. 顧客データの扱い

<!-- customer-data-rules:begin -->
**顧客データを扱うときのルール（チャット・Cowork・Claude Code 共通）**
- 1案件＝1会話で作業する（チャットは1チャット、Cowork は1タスク、Claude Code は1セッション）。別の案件の資料を同じ会話に混ぜない。
- claude.ai のチャットでは、シークレットチャットが使えるならそれを使う。
- 成果物をダウンロードするか Drive に保存したら、チャット・Cowork の会話は削除する。
- 会話の共有リンク、Project への添付、アーティファクトの公開はしない。
- 作業メモ・ログ・修正依頼には、顧客名・従業員名・金額を書かない（「顧客企業A」「従業員B」などに置き換える）。
<!-- customer-data-rules:end -->

<!-- chat-env:begin -->
**claude.ai のチャットで使うときの注意**
- 添付したファイルは、コード実行環境のアップロード用フォルダ（通常 `/mnt/user-data/uploads/`）にある。見つからなければ `find / -name "<ファイル名>" 2>/dev/null` で探す。
- 作った成果物は出力用フォルダ（通常 `/mnt/user-data/outputs/`）に保存すると、ユーザーがダウンロードできる。
- PDF は100ページ以下なら画像も含めて読める。101ページ以上は文字しか読めないので、画像PDF・手書きPDFは100ページ以下に分けて添付してもらう。
- 1チャットに添付できるのは20ファイル、1ファイル30MBまで。
- PyMuPDF（fitz）を使う手順は、先に `pip install pymupdf` を実行する。
<!-- chat-env:end -->

この資料集そのものは脱PII化してある（個人は役割表現、金額は構造だけ）。同じ方針を、作業ログ・メモにも当てはめる。

## 4. 困ったとき

- スキルが出てこない・古い気がする: claude.ai の「カスタマイズ」→「プラグイン」で hojokin がインストール済みか確認し、入っていなければインストールする。Claude Code は claude.ai のアカウントでログインしていれば起動時に同期され、画面に出る案内に従って `/reload-plugins` を実行すると反映される。§0.2 の selfcheck で版を確かめる。
- 資料の誤りに気づいた・追記したい: このスキルの中を直接書き換えても、次の更新で元に戻る。管理者（自動化ツール担当）にチャットで次の4点を送る。
  - スキル名とファイル名（例: hojokin-guide の 引き継ぎ/02_制度知識ベース.md）
  - どの見出し・箇所か
  - 現状の記述
  - こう直したいという案（顧客名・従業員名・金額は書かない）
- 管理者が直すと、全員のプラグインに自動で届く（チャットと Cowork は反映後に始めた会話から、Claude Code は次の起動時から）。

## 5. 手元の CLAUDE.md に書く場合
