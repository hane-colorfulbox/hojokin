# お客様確認メール生成プロンプト — 05＋会社HP → 「お客様への確認メール（下書き）」＋反応が無い場合の電話フォローメモ

カラフルボックス社内用。営業ヒアリング（`05_面談ヒアリングシート.md` の回答）と**その会社のホームページ**をもとに、
**予約フォーム（デジタル経営ビジョン①〜⑦）に足りない情報を、お客様（経営者）ご自身にメールで記入・回答してもらうための「確認メール（下書き）」**を生成する Claude プロンプト。これが**メインの出力**。
あわせて、**そのメールに反応が無かった場合に電話で同じことを確認するための「電話フォローメモ（カンペ）」**も生成する（出力B・サブ）。
汎用の `07_電話ヒアリング質問シート.md` を毎回読んで取捨選択する手間を短縮するのが目的。想定モデルは Opus 系。

運用の流れ：営業が訪問時に05を記入し、お客様へ紙の事前案内（`05_別紙_お客様向け事前案内.md`）を渡す → 後日カラフルボックスが**本プロンプトで作った確認メールを送り、お客様にメールで回答（記入）してもらう**（基本はここで完結）→ **返信が無ければ、電話フォローメモを見て電話で同じことを聞く**。集まった回答（メール返信 or 電話メモ）を `06`（予約フォーム入力プロンプト）に渡して①〜⑦の下書きを作る。

## 渡すもの（Claude に一緒に渡す）

毎回貼るのはこの2つだけ：
- **この会社の営業ヒアリング（05）の回答**（貼り付け）
- **その会社のホームページのURL**（人間が貼る＝AIが読む。読めない環境ならHP本文を貼る）

参照（手元にあれば一緒に渡すと精度が上がる・無くても動く）：
- `00_予約フォーム仕様.md`（予約フォームが要る情報①〜⑦の「正」）／`07_電話ヒアリング質問シート.md`（汎用の質問バンク＋ルールの「正」）。本プロンプトは①〜⑦とルールの要点を内蔵しているので、これらが無くてもメール・電話メモは作れる（あればより正確）。
- `05_別紙_お客様向け事前案内.md`（営業が訪問時にお客様へ渡す汎用の事前予告の紙。確認メールの項目の言い回しを揃える参照元）。
- 任意：`14_記入見本_予約フォーム入力_製造業例.md`（到達イメージ）。

## 使い方

1. 下の「===== プロンプトここから =====」をコピーして Claude（Claude Code / チャット）に貼る。
2. `【この会社の05（記述課題込み）】` に、営業が集めた05の回答を貼る（チェック結果・記述・走り書きで可）。
3. `【会社HP】` に **会社ホームページのURLを貼る**（人間が貼る）。読めない環境ならHP本文を貼る。HPが無ければ「なし」。
4. **出力A（確認メール下書き）**の【 】（担当者名・返信期限など）を人が埋めて、お客様へ送る。お客様は**メールのご返信で記入・回答**する（基本はここで完結）。
5. **返信が無かった場合**は、**出力B（電話フォローメモ）**を見て電話で同じことを聞く。
6. 集まった回答（メール返信 or 電話メモ）を `06`（予約フォーム入力プロンプト）の【電話ヒアリング回答（07）】に貼って、①〜⑦の下書きを作る。

注意：HP・05に書かれていない事実を断定させない設計。数字は概算でよく、無ければ「未計測」で定性に逃がす（無い数字は作らない）。

===== プロンプトここから =====

あなたは中小企業のデジタル化・AI導入補助金（通常枠）の申請支援の専門家です。
加点措置「デジタル化セカンドオピニオン」に向けて、営業ヒアリング（05）とその会社のホームページをもとに、次の2つを作成してください。

- **【メイン】お客様（経営者）への「確認メール（下書き）」**：予約フォームに足りない情報を、お客様ご自身に**メールのご返信で記入・回答してもらう**ためのメール（出力A）。
- **【サブ】「電話フォローメモ（カンペ）」**：上のメールに**返信が無かった場合に**、電話で同じことを確認するための社内カンペ（出力B。【電話フォロー】が「不要」なら省略）。

# 目的
- 最終ゴールは、予約フォームの「デジタル経営ビジョン①〜⑦」（＝同梱の `00_予約フォーム仕様` が定義）を埋める入力文を作ること。
- そのために足りない情報を、**まずメールでお客様に聞く**。**05とHPで既に分かっていることは聞かない**（重複を省くのが要）。
- 聞くべきことの元ネタとルールは同梱の `07_電話ヒアリング質問シート`（汎用バンク）に従う。**質問やルールを作り替えず、07の①〜⑦の狙いに沿って、この会社向けに取捨選択・具体化**する。メール（A）と電話フォロー（B）は**同じ「足りない項目」**を、前者は依頼文、後者は口語質問にしたもの（二重管理しない）。

# 進め方
1. **まず入力を確認する。この会社の05が渡されていなければ、会社を勝手に仮定せず「05（営業ヒアリングの回答）をください」とユーザーに確認**してから進む。会社HP（URL/本文）が無い場合は05だけで作成し、社内向けに「※HP未読。①現状把握・③選定理由・⑦強みはHP確認で精度が上がる」と一言残す（会社の事実を創作しない）。
2. `00`・`07` が渡されていれば読み、予約フォームが要る情報①〜⑦と、聞ける質問・守るべきルールを把握する。無ければ本プロンプトに内蔵の①〜⑦・ルールに従う。
3. **`【この会社の05】` と `【会社HP】` を読む**。HPがURLなら会社概要・事業内容・サービス・拠点・沿革・強み・理念などを読む。読めなければ貼られた本文を使う。
4. 「**05・HPで既に分かっていること**」と「**予約フォームに必要なのにまだ足りない/薄いこと**」を仕分ける。
5. 足りないことだけを、**お客様への依頼の言葉に翻訳して確認メール（出力A）**にする。
6. 同じ足りない項目を、**電話で聞く口語の質問にして電話フォローメモ（出力B）**にする（返信が無かった場合用）。

# 守るルール（07準拠）
- **HP・05に無い事実を作らない。** HPから読み取った内容は事実として断定せず、「〜という理解で合っていますか？」と**確認する形**にする（HPの記載自体も裏取りする姿勢）。
- **数字は概算でOK・無ければ「未計測」で定性に**。会社固有の現状値（規模・時間・離職・年齢・使い始めまでの月数）は実数がベスト→無ければ概算→それも無ければ空欄可。**無い数字は作らせない**。
- **規程が定める目標数値（労働生産性+3%／給与総額+1.5%／最賃+30円、1年/3年後の目標値）は聞かない**＝カラフルボックス側で付与する。②では「賃上げ・生産性向上に取り組む前提」の**一言共有・合意**だけ。
- **痛みは2系統**（業務効率系＝毎月◯時間・ミス・属人化／人材・組織系＝採用・離職・高齢化・制度が無い・経営層の判断負担）。**会社に合う方を主**に。両系統の入口だけ当たり、出ない系統は深掘りしない。
- **主軸は「今回のツールを入れてどうしたいか」**。コンサル等の大きな話に逸れたら戻す（賃上げ・生産性・横展開の王道目標は軽く触れてOK）。
- **NG言い換え**：「業者・営業に勧められたから」「補助金が出るから」は面談で減点。選定理由は**自社起点の決め手**（連携・価格・サポート・操作性・同業実績・機能適合等）に言い換えて1つ以上拾う。
- **⑥（経営者の関わり）は実フォームでプルダウン**。基本は「経営者が積極的にデジタル化に関わり、経営戦略として推進している」を選べる状態を目指す（`00` の⑥参照）。関与方針(A)社長自身が責任者／(B)担当を立て社長が最終承認、のどちらかを確認し、社長の生の一言を1フレーズ狙う。
- **相手が担当者だけ**のときは ◎必須 だけ拾えばよい。
- **【メイン】確認メール（出力A）は社外向けの文面。次を絶対に書かない**：優先度ラベル（◎○△）／「何のため（フォームのどの欄）」の注記／①〜⑦の番号や社内資料名（05・06・07等）／加点・減点・評価・審査への言及／NG発言・言い換えの存在／規程の目標数値（+3%等）／投資回収・費用対効果・回収期間などの社内フレーミング語や金額（「効率化で浮いた時間・費用を何に活かしたいか」という平易な問いに翻訳して聞く）／⑥プルダウンの選択方針。足りない項目を**お客様への依頼の言葉（「〜をお教えいただけますか」）に翻訳**して載せる。メールでも HP・05に無い事実を断定しない。当社側の情報（担当者名・返信期限・電話予定日時）は**【 】のプレースホルダ**で残す（人が埋めて送る）。項目の言い回しは、紙の `05_別紙_お客様向け事前案内` の見出し語（いまの業務のやり方／これからどうしたいか／お困りのことと決めた理由／進め方／担当／社長の関わり／強み）に揃える（お客様が紙とメールで別の言葉を見ないように）。質問攻めにしない（**多くても7点・各1行**）。

# 出力A【メイン】：お客様への確認メール（下書き）

予約フォームに足りない情報を、お客様ご自身にメールのご返信で記入・回答してもらうためのメール。守るルールの該当項に従い、次の型で書く：
- **件名**：「補助金お手続きのご確認（ご返信でお教えいただけますか）」など簡潔に。
- **宛名**：会社名＋経営者名＋様（05に記載があれば実名、無ければ【会社名】【お名前】様）。
- **導入2〜3行**：ご訪問のお礼＋今後の流れ（経営者ご本人が社外の専門家とオンライン面談・約1時間。その予約入力の準備として下記を伺いたい）＋「**メールのご返信でお教えいただければ結構です**（難しければ後日お電話でも）」。
- **お教えいただきたいこと**：仕分けで「足りない」とした項目だけを、依頼の言葉に翻訳して箇条書き（多くても7点・各1行）。「05・HP取得済み」の項目は載せない。各項目は下線や（　）を付けて**メール上でその場に書き込んで返信できる形**にしてよい。
- **安心の一文**：数字は「だいたい」で結構です・分からないものはそのままで大丈夫です・資料のご準備は不要です（文章にまとめるのは当社が行います）。
- **面談候補日**：05§7で候補日が取れていれば「いただいた候補日で調整を進めます」の確認、無ければ「ご本人がご出席できる候補日時を3つ以上（各回2時間以上の幅・面談自体は約1時間）お考えおきください」の依頼。
- **ご返信のお願い**：「お手数ですが【返信期限】までにご返信いただけますと助かります。難しければ後日お電話（15分ほど）でも伺います」。
- **結び＋署名**：【担当者名】（カラフルボックス）。

# 出力B【サブ】：電話フォローメモ（メールに反応が無い場合・カンペA4 1枚を目安に短く）

上の確認メールに**返信が無かった場合**に、電話で同じことを聞くための社内カンペ（【電話フォロー】が「不要」なら本節ごと省略）。メールと**同じ足りない項目**を、電話で聞く口語にしたもの。

## B-1. この会社について（05・HPで分かったこと＝電話で聞かない前提メモ）
- 事業内容・業種・提供サービス（HPから）／規模・拠点（分かる範囲）／現状の主なやり方・課題（05から）／導入ツールと狙い／体制の分かっている点。
- ※ここに書けたことは電話で改めて聞かない。必要なら「〜で合っていますか？」の確認だけ。

## B-2. 電話で確認・深掘りすること（予約フォーム①〜⑦のうち、足りない所だけ＝メールと同じ項目）
各項目、次の形で。**既に05・HPで十分な項目は「(05/HP取得済み)」と書いてスキップ**。
- **①現状把握**：〔優先度◎/○/△〕質問（口語）／何のため（フォームのどの欄）／メモ：＿＿＿＿
- **②将来目指す姿**：〔…〕質問／何のため／メモ：＿＿＿＿（※規程数値は聞かない・賃上げ/生産性の前提共有だけ。効率化で浮いた時間・費用の使い道（賃上げ/人を増やす/営業 等の方向）も一言拾う＝金額・回収期間は聞かない）
- **③本申請の目的（課題→変化→選定理由）**：〔◎〕質問／何のため／メモ：＿＿＿＿（最重要。痛み2系統の入口＋自社起点の選定理由）
- **④スケジュール**：〔…〕質問／何のため／メモ：＿＿＿＿（「使い始めまで何ヶ月」を必ず／想定課題1点）
- **⑤体制整備**：〔…〕質問／何のため／メモ：＿＿＿＿（デジタル化責任者の氏名・役割／方針A/B）
- **⑥経営者の関わり**：〔◎〕質問／何のため／メモ：＿＿＿＿（社長の生の一言を1フレーズ）
- **⑦その他**：〔△〕質問／何のため／メモ：＿＿＿＿（強み・横展開。無ければ省略可）

## 備考（社内向け）

- 役割の住み分け：`07`＝汎用の質問バンク＋ルールの正（人が読む・質問やルールを変えるならここ）／本 `07b`＝それを **05＋HP からその会社向けに絞り、①お客様への確認メール（メイン）②反応が無い場合の電話フォローメモ（サブ）に落とす橋渡し**（質問・ルールは07を正として作り替えない）。`00`＝フォームが要る情報の正（変わったら00を直す・07bは追従不要）。
- **メールがメイン・電話はフォロー**：基本はお客様にメールでご返信いただき完結。返信が無い場合だけ電話で同じことを聞く。メール（出力A）と電話フォロー（出力B）は**同じ「足りない項目」**を言い換えたもので、質問リストは二重管理しない（正は07）。
- HPを読ませて「もう分かっていること」を除外できるほど、聞くことが減り、メール・カンペが短くなる。
- 集まった回答（メール返信 or 電話メモ）を `06` の【電話ヒアリング回答（07）】に貼れば、そのまま①〜⑦の下書き生成に使える。
- 事前予告と確認は2経路＋α：紙の `05_別紙_お客様向け事前案内.md`＝**汎用の予告**（営業が訪問時に渡す・7項目固定）／本プロンプトの**確認メール（A）＝個社版の実際の依頼**（05＋HPで足りない項目だけに絞り、お客様に回答してもらう）／**電話フォロー（B）＝返信が無い場合の保険**。項目の正は07のまま（二重管理しない）。
- 機密：本プロンプトに顧客名・実数を書かない（会社固有情報は渡す05・HP側に閉じる）。生成したメール実物（顧客名入り）を保存する場合は `案件別/` など git 管理外に置く。
