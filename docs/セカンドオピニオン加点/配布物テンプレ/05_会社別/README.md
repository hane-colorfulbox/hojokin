# 05 面談ヒアリングシート — 会社別（ツール提供元別）

営業ヒアリングシート（05）を、導入するツールの提供元ごとに特化させたもの。案件の会社が決まった段階で、この中の1枚を営業（代理店・ベンダーの担当者）に渡す。

決定の経緯: [2026-09-02 セカンドオピニオンのヒアリングシート会社別化](<../../../../社内資料/会議用/議事/2026-09-02_山田さん_セカンドオピニオンのヒアリングシート会社別化.md>)

## なぜ会社別か

汎用版（[05_面談ヒアリングシート.md](<../05_面談ヒアリングシート.md>)）は業務の選択肢が一般的なため、扱うツールによっては当てはまる項目がなく「その他」でしか書けない。実際に Scale（人事評価）案件で、人事評価に当たる選択肢がなく顧客から質問が出た。

会社別にする狙いは3つ。

1. 営業・経営者が、自社の業務そのままの言葉でチェックできる（関係のない質問が減る）
2. 予約フォーム（デジタル経営ビジョン）の①〜⑦を埋めるのに必要な粒度で最初から集まる
3. その結果、後日のメール・電話で聞き直す量が減る

## 配布物の形式（1社5点）

営業・お客様の環境に合わせて選べるよう、1社につき5形式そろえてある。中身（設問・選択肢）は同一。

| 形式 | ファイル | 用途 |
|---|---|---|
| 印刷用PDF | `05_面談ヒアリングシート_〇〇.pdf` | 紙に刷って手書き。訪問・対面 |
| 入力できるPDF | `05_面談ヒアリングシート_〇〇_入力用.pdf` | iPad・PCでタップ入力（AcroForm）。その場で埋めて送り返せる |
| Word | `05_面談ヒアリングシート_〇〇.docx` | 営業側で文言を足したい・自社書式に貼りたいとき。□はWordでクリックすると☒になる |
| スプレッドシート | `05_面談ヒアリングシート_〇〇_オンライン入力用.xlsx` | オンライン商談で画面共有しながらチェック。Drive上でそのままスプレッドシートとして編集でき、Excelでも開ける |
| Markdown | `05_面談ヒアリングシート_〇〇.md` | 正本そのもの。Drive へ上げると Google ドキュメントに変換され、ブラウザで読む・コメントする用になる |

## 作り直し方（md を直したら必ず回す）

設問の**単一の真実は各社の Markdown**。残る4形式（PDF2種・Word・xlsx）は md から機械生成する。

```
python docs/セカンドオピニオン加点/_scripts/build_company_sheets.py
```

- 出力先は `_配布/<会社名（ツール名）>/`（Drive の会社フォルダと1対1で対応）
- 生成前に md の記法崩れを自動検知する（元 md と生成物の文字が一致しない場合は生成を中止）
- 記法チェックだけしたいときは `python _scripts/md_form_parser.py <md>`
- 生成物（pdf/docx/xlsx）は git 管理しない。**md を直したら Drive 側も差し替える**

## Drive の配置先

共有ドライブ「10_補助金サポート」→ 00_共通・テンプレート → セカンドオピニオン → **05_営業ヒアリングシート各種 の下に会社ごとのフォルダ**

- 会社フォルダ名は `会社名（ツール名）`。営業がどちらの名前でも探せる形にしている
- 各フォルダに上の5形式が入っている。営業に渡すときはフォルダを開いて必要な形式を選ぶ
- 汎用版一式と別紙は同じ `05_営業ヒアリングシート各種` に残してある（会社・ツール未定の案件用）
- 旧「会社別」フォルダ（2026-09-04 に置いた Google ドキュメント6本＋README）は廃止。中身は各会社フォルダの md に置き換わるので、上げ終わったらフォルダごと削除する

### Drive へ上げる操作は手でやる

Drive の新規アップロードは File System Access API 経由のため、Claude Code のブラウザ操作からは掴めない（実測: 合成 drop も `webkitGetAsEntry` が null で無視され、`ファイルのアップロード` はファイル選択ダイアログを Puppeteer が検知できない）。Drive コネクタ（MCP）も**自分が作ったファイルしか触れない**スコープで、既存ファイルの移動・改名・内容差し替えができない。

したがって配置は次の分担になる。

- CC ができる: 会社フォルダの新規作成、生成物のローカル出力、フォルダ構成の確認
- 人がやる: Drive の会社フォルダを開き、`_配布/<会社名（ツール名）>/` の**中のファイル5点をドラッグ&ドロップ**

⚠️ フォルダごとドラッグすると、Drive は同名フォルダをマージせず**もう1つ作る**（Drive は同名フォルダを許す）。会社フォルダが既にある場合は、フォルダではなく中のファイルを入れる。

将来まとめて自動化したい場合は、サービスアカウント（鍵ファイル `credentials/service_account.json` の `client_email`）を共有ドライブ「10_補助金サポート」のコンテンツ管理者に追加すれば、`hojokin/google_drive.py` の `DriveClient.upload_file` でスクリプトから上げられる（2026-09-07 時点では未追加＝404）。

## 渡し方

1. 案件の会社に対応するフォルダから、営業の環境に合う1形式を渡す
2. あわせて [別紙 お客様向け事前案内](<../05_別紙_お客様向け事前案内.md>) を経営者に渡してもらう（営業側が質問の狙いを知りたい場合は [別紙 営業向けカンペ](<../05_別紙_営業向けカンペ.md>) も。7章の構成は会社別版でも同じなので、カンペは共通で使える）
3. 記入後のシートを回収し、足りない部分だけメールで追加ヒアリング
4. シートの回答＋メールの回答を Claude Code に渡して予約フォーム入力文を作る（[00 予約フォーム仕様](<../00_予約フォーム仕様.md>) 参照。プロンプトは会社別に分かれていない）

作業時のモデルは Opus・エフォート高めを推奨（2026-09-02 決定）。読み込む資料が多く、Sonnet・低エフォートだと「この回答で予約フォームが埋まるか」まで考えずに出力してしまう。

## 全社共通の前提（どのシートにも効く）

- 対象は**通常枠のみ**。インボイス枠・セキュリティ枠・複数社連携枠は加点の対象外
- 面談に出るのは**経営者ご本人**（代理不可）。ITベンダー・代理店は同席できない
- 候補日は各回2時間以上の幅で3つ以上（面談自体は1時間・Zoom・カメラON・録画あり）
- 確認者が見るのは「話のスジが通っているか」と「社長が自分の言葉で語れるか」の2点
- 社内SLA は締切 D-21 までに予約フォーム送信

## 新しい会社を追加するとき

1. [docs/ツール情報](<../../../ツール情報/INDEX.md>) に該当ツールの情報があるか確認する（なければ IT補助金コンソールの登録概要・提供元の機能説明資料から作る）
2. 既存の1枚をコピーし、次の4か所をそのツール・業界に差し替える
   - 1章の業務名（その業界に実在する業務に。5つ以上チェックできることがゲート）
   - 3章の困りごと（そのツールが実際に解決する課題を選択肢化）
   - 3章の選んだ理由（そのツールの特徴＝価格・サポート・専門特化・連携 等）
   - 4章の導入の進め方（そのツールの実際の導入ステップ＝マスタ登録・データ移行・研修 等）
3. 2〜7章の骨格（将来像・体制・社長の関わり・段取り）は共通のまま変えない。予約フォーム①〜⑦との対応が崩れるため
4. `_scripts/build_company_sheets.py` の `COMPANY_FOLDERS` に「ツール名 → 会社フォルダ名」を追記する（未登録だと警告を出して飛ばす）
5. `build_company_sheets.py` を回して5形式を作り、Drive に会社フォルダを作って上げる

記法の約束（生成物が壊れないための最低ライン）:

- 選択肢は `□ラベル`。記入欄は全角スペースだけの括弧 `（　　　）`。括弧の中に文字を入れると記入欄にならない
- 見出しは `##`（章）と `###`（章内の小見出し）。`###` は xlsx で設問名として使われる
- 地の文に単独の `□`（例:「あてはまる□にチェック」）を書いても設問行と誤認しない作りにしてあるが、`：□` の形は設問扱いになる
