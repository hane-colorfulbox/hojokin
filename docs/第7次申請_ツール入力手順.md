# 第7次申請：ツール入力手順

対象読者：前半「画面で作成する場合」は申請担当者。後半「ローカルCLIで作成する場合」は管理者・開発者向けで、申請担当者は読まなくてかまいません。

更新日：2026-11-05。変更点の全体は [担当者向け要点](第7次申請_担当者向け要点.md) と [変更点と使い方](第7次申請_変更点と使い方.md) を参照してください。

この手順は、7次に対応した版のツール（画面のいちばん下のフッターが v0.2.100 以上）で使います。それより前の版（いまの本番の v0.2.97 など）は7次の判定・入力に対応していないので、7次の申請書・加点判定には使いません。

## 画面で作成する場合（申請担当者向け）

1. 公募回、申請枠・法人格、実際の申請予定日を選びます。給与0年度目の開始日・終了日は、その申請日を含む事業年度です。
2. 申請額、主たる事業場と申請画面に入れる地域別最低賃金額、交付決定歴を確認します。交付決定歴は、補助金名の年度（「IT導入補助金2024」なら2024）と枠・類型を、すべての履歴について入力します。交付決定日の年（暦年）ではありません。給与の3.5%の判定に使うのは2022〜2025、労働生産性の4%の判定に使うのは2023〜2025の指定枠です。はっきりしない履歴は顧客に確認してから入力します。
3. 適用除外と任意加点の希望を確認します。賃上げ率の達成義務があるかどうかに関係なく、全4原本で給与0〜3年度目の総額・対象人数（FTE）・算定根拠・担当者の確認を入力します。表明の実施日と方法も、顧客に確認した事実を入力します。
4. 通常枠では、労働生産性の1〜3年度目の営業利益・人件費・減価償却費・年間労働時間・根拠を入力します。計画1年度目は、生産性も給与も申請日の翌事業年度です。基準は、生産性が前事業年度の実績、給与が当期の見込みです。
5. 生産性の基準として、前事業年度の損益と年間労働時間を回収します。通常枠では、賃金台帳の月の見出しに年が入っていない台帳（「1月」「2月」だけ）は、前事業年度の労働時間を確認できないため停止します。見出しを「令和7年1月」「2025年1月」のように年付きにした台帳を使います。2つの事業年度の分が混ざった台帳や、年月が連続した12か月になっていない台帳も停止します。一部の人・月の労働時間しかない場合も停止するので、足りない月の労働時間を回収します。役員以外は全員、月間平均時間（E列）か月別の時間を入れます（正社員も空欄にしません。ツールの「賃金台帳の作成」は正社員・役員のE列を書かないので、作成後に入れます）。前事業年度の途中に入社・退社した人は、名簿・入退社日などで在籍していないと確認できた月（入社前・退職後）の月の欄に「非在籍」と書きます。非在籍の月は総労働時間から除かれ、在籍している月はE列の月間平均時間で数えます。空欄・0円の月は非在籍とみなさず、停止します。休職など在籍していて給与のない月がある場合は、管理者に相談して個別に対応します。「非在籍」と書いた月に給与や労働時間がある台帳も停止します。ツールの「賃金台帳の作成」は、台帳に印字された入社日・退職日から「非在籍」を書き、変換メモシートに根拠を残すので、原本と照合します。
6. 不足の表示をすべて解消してから実行します。実行後に公募回・申請月・入力資料・計画値などを変えると、前の結果はダウンロードできなくなります。新しい条件でもう一度実行してください。

加点判定には、公募回に合った専用台帳を使い、画面と台帳の申請月・事業場の所在地をそろえます。所在地が食い違う場合も停止します。7次以降版の専用台帳は、F〜R列に基本給、AH〜AT列に時間換算の対象月額（基本給＋職務手当などの通常の手当）を入れます。公式様式の【基本給】欄はF〜R列から、【時間換算給与】欄はAH〜AT列を労働時間で割って作ります。対象月額が空欄の月があると判定は未確定になります。

本ツールと当社の申請原本は、通常枠とインボイス枠の法人・個人事業主の4種類が対象です。セキュリティ枠は対象外です（労働生産性の年平均1%以上などの別要件があります）。

## ローカルCLIで作成する場合（管理者・開発者向け）

申請担当者はこの節を使いません。開発リポジトリの `run.py` は、申請の前提をUTF-8のJSONで受け取ります。配布プラグインのスキルを直接使う手順とは別です。

```powershell
python -B run.py local --help
```

既存の入力フォルダなどの指定に、`--application-context <確認済みJSONのパス>` を加えます。対象は申請書作成を含む `application` / `all` です。管理表経由のDrive一括申請書作成は、新しい確認済みの項目を管理表から取得できるまで停止します。

以下は未確認状態の雛形です。空欄・null・falseを、実際に確認した内容に置き換えます。このままでは提出用の生成は通りません。7次以降は `forecast_years` に0〜3年度目の4行を入力します。賃上げ率の義務がないことだけを理由に空の配列にしません。通常枠以外は `productivity_forecast_years: []` を使えます。

```json
{
  "call_round": 7,
  "application_date": "",
  "fiscal_year_start": "",
  "fiscal_year_end": "",
  "frame": "通常",
  "subsidy_amount": null,
  "workplace_prefecture": "",
  "workplace_confirmed": false,
  "regional_min_wage_yen": null,
  "past_grants": null,
  "wage_exempt": null,
  "wage_exemption_reason": "",
  "optional_wage_bonus": null,
  "planned_min_wage_increase": null,
  "payroll_scope_confirmed": false,
  "declaration_confirmed": null,
  "declaration_method": "",
  "declaration_date": null,
  "forecast_years": [
    {"total_salary": null, "employee_count_fte": null, "source": "", "confirmed": false},
    {"total_salary": null, "employee_count_fte": null, "source": "", "confirmed": false},
    {"total_salary": null, "employee_count_fte": null, "source": "", "confirmed": false},
    {"total_salary": null, "employee_count_fte": null, "source": "", "confirmed": false}
  ],
  "productivity_forecast_years": [
    {"operating_profit": null, "personnel_cost": null, "depreciation": null, "total_annual_hours": null, "source": "", "confirmed": false},
    {"operating_profit": null, "personnel_cost": null, "depreciation": null, "total_annual_hours": null, "source": "", "confirmed": false},
    {"operating_profit": null, "personnel_cost": null, "depreciation": null, "total_annual_hours": null, "source": "", "confirmed": false}
  ],
  "manual_review_reasons": []
}
```

- 日付は `YYYY-MM-DD`。枠は `通常` / `インボイス` を使います（`セキュリティ` の値もありますが、当社の4原本は通常・インボイスの法人／個人だけで、セキュリティ枠は対象外です）。
- `past_grants: null` は未確認、`[]` は交付決定なしと確認済みです。交付決定ありは `[{"year": 2024, "frame": "通常枠", "decided": true}]` のように全履歴を記録します。`year` は補助金名の年度（IT導入補助金2024なら2024）で、交付決定日の年（暦年）ではありません。2022〜2025以外の年は、給与3.5%の判定にも生産性4%の判定にも使われません。曖昧な枠・類型は確定しません。
- `forecast_years` は給与0〜3年度目の順です。人数が変わる場合も各年の確認値を入れます。自動の3%増額や前期実績の流用はしません。
- `productivity_forecast_years` は生産性1〜3年度目の順です。基準となる前事業年度の実績は入力資料から取得し、3%／4%の初年度・3年平均を検算します。通常枠では、賃金台帳の月の見出しに年が入っていないと、前事業年度の労働時間を確認できず停止します。
- `source` は算定根拠と確認の記録です。数値を入れただけで `confirmed: true` にせず、対象範囲と年度も確認してください。
- 複数県、算入範囲の未確認などは `manual_review_reasons` に理由を入れ、解消するまで確定の生成をしません。

任意加点の事業場内最賃の上乗せは、通常枠150万円未満・インボイス枠の基本＋30円／更なる＋50円と、通常枠150万円以上の＋50円を分けて入力します。

不足・未確認はエラーとして表示し、申請の前提の不備はAI抽出を始める前に停止します。前事業年度の労働時間の不足や月の見出しに年がない台帳は、賃金台帳を読み取った段階で停止します。給与0年度目の見込み値と根拠は保存しますが、効果報告での比較基準は未確定のままです。
