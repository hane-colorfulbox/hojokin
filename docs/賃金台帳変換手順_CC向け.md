# 賃金台帳変換手順（CC＝Claude Code 向け）

PDF・紙資料の賃金台帳を、補助金書類作成ツール（Streamlit Cloud 版）が読み込める Excel に変換する手順書。
**読者：CC（Claude Code）を使って変換作業を行う担当者。**

---

## 0. なぜこの作業が必要か

書類作成ツールは賃金台帳をパースして R215（従業員数）/ R216（給与支給総額）を算出する。
入力ファイルが Excel（または Excel化された CSV）なら、ツール側は **AI API を使わずに決定論パーサーで処理** できる。

- PDF（特に画像PDF）のままだと AI 抽出経路（Claude API 課金あり）に流れる
- AI 経路は精度ブレ・コスト発生・実行時間長
- **顧客には原則 Excel/CSV で回収依頼。PDF しか無い場合のみローカルで変換**（[`CLAUDE.md`](../CLAUDE.md#L33-L36) 参照）

変換結果は案件の Drive フォルダにアップロードしておけば、Streamlit Cloud の「Google Drive」モードから自動取得される。

## 1. 変換先テンプレート

**ファイル**: [`ツール/賃金台帳テンプレート.xlsx`](../ツール/賃金台帳テンプレート.xlsx)

### シート構成

| シート | 役割 |
|---|---|
| 従業員別明細 | データ本体（1行=1名、12月分の課税支給合計） |
| 記入ルール | 顧客向けの記入ガイド |

### ヘッダー仕様（従業員別明細シート）

| 列 | セル | 項目 | 必須 | 値の例 |
|---|---|---|---|---|
| B | B5 | No | ◯ | 1, 2, 3, ... |
| C | C5 | 氏名 | ◯ | 山田太郎 |
| D | D5 | 雇用形態 | ◯ | 正社員 / パート・アルバイト / 役員 |
| E | E5 | 月間平均時間 | △ | 160（年間平均、月給制なら空欄でも可） |
| F | F5 | 時給 | △ | 1200（月給制は空欄可、ツールが月給÷時間で補完） |
| G〜R | G5〜R5 | 1月〜12月 | ◯ | 各月の **課税支給合計**（円、整数） |
| S | S5 | 年間通勤手当 | △ | 36000（非課税通勤手当の年間合計。詳細は §3.1） |

### データ行（B6 以降）

- B6〜B15 がデフォルト10行（No=1〜10は罫線あり）。**11名以上いる場合は単純にセルを追加して問題ない**（罫線は無くてもツールは読む）
- 支給がない月は **空欄**（0 を入れない。「中途入社/退社」を意味する）
- 金額は **税込・課税支給合計**（通勤費は非課税分を除外、賞与は含める）

## 2. 雇用形態ラベルの正規化（**最重要・落とし穴**）

ツール側（[`hojokin/wage_reader.py:1582`](../hojokin/wage_reader.py#L1582)）の役員判定は：

```python
def _is_excluded_from_wage_total(emp):
    if '役員' in (emp.employment_type or ''):
        return True   # R216 集計から除外
    if not emp.is_full_year:
        return True   # 中途入退社（全月支給でない）も除外
    return False
```

**「役員」という文字列を含むかどうか** で判定している。
よって以下の表記は **役員除外されない**（一般従業員として R216 に算入されてしまう）：

| 元PDFの表記 | そのまま転記 | 正しく転記 |
|---|---|---|
| 代表取締役 | ❌ R216 に算入される | ✅ **役員** に置換 |
| 取締役 | ❌ 算入される | ✅ **役員** に置換 |
| 監査役 | ❌ 算入される | ✅ **役員** に置換 |
| 理事長 / 理事 / 監事（医療法人等） | ❌ 算入される | ✅ **役員** に置換 |

### 正規化ルール（CC で変換するときの規約）

```
元の雇用形態が以下のキーワードを含む → 「役員」に置換
  代表取締役 / 取締役 / 監査役 / 監事 / 理事長 / 理事

「パート」「アルバイト」「非常勤」を含む → 「パート・アルバイト」
それ以外（正社員 / 現場代理人 / 主任 / 係長 など） → 「正社員」
```

「現場代理人」「営業」のような **職位名** はそのまま書かず「正社員」に正規化する（雇用形態列なので）。職位を残したい場合は別途メモ列を作る（ツールは読まないが目視確認用）。

## 3. 採用する金額（公募要領準拠）

詳細は [`docs/補助金_実務知識ベース.md`](補助金_実務知識ベース.md#L30-L65) 参照。

| 採否 | 列名 | 理由 |
|---|---|---|
| ✅ | **課税支給合計**（または「課税給与」） | 公募要領 p.10「給与所得として課税対象」 |
| ❌ | 支給合計（通勤費込み） | 非課税通勤費が混入する。**過大計上は公募要領違反** |
| ❌ | 差引支給額 | 社保・税控除後なので過小計上 |

賃金台帳の列に「課税支給合計」が無い場合は「**支給合計 − 通勤手当（非課税分）**」を手計算する。通勤手当が月15万円以下なら全額非課税なので、概ね支給合計から通勤手当を引けば良い。

### 3.1 通勤手当の扱い（S列「年間通勤手当」）

賃金台帳に「課税支給合計」列が無く「合計（通勤費込み）」しか無いケース（後藤造園系の給与計算ソフト出力など）への対応：

| ケース | G〜R列に入れる値 | S列「年間通勤手当」 |
|---|---|---|
| 台帳に「課税支給合計」列がある | その値をそのまま転記 | **空欄**（補正不要） |
| 「合計（通勤費込み）」列しか無い | 合計列をそのまま転記してOK | **非課税通勤手当の年間合計**を入れる → ツールが在籍月数で均等割して各月から自動減算 |

#### S列を使うメリット
- 月別に「合計 − 通勤手当」を手計算する手間が消える（22名×12ヶ月=264セルの計算が1値で済む）
- 中途者は **在籍月数で均等割** されるので、年間総額を入れるだけで月別に正しく分散される

#### 注意
- 入れる値は **「非課税分のみ」**。月15万円超で課税扱いになった通勤手当があれば、その分は引かない
- 賃金台帳の「通勤手当」列を年間で合計するのが基本
- 通勤手当が変動する場合（電車通勤の運賃改定等）も、年間合計値で十分（厳密な月別控除が必要な案件はまずない）

#### 動作例
- 山田次郎：12ヶ月在籍、年間通勤手当 36,000円 → 各月から 3,000円ずつ減算
- 佐藤三郎：6ヶ月在籍（中途）、年間通勤手当 18,000円 → 在籍6ヶ月から 3,000円ずつ減算
- 通勤手当列空欄 → 減算なし（既存動作と同じ）

### 賞与の扱い

- 賞与は **R216 に含める**（公募要領 p.10 で「賞与」明記）
- 賞与シートが別 PDF/ シートで分かれている場合は、該当月の金額に加算する
- 例：6月給与 25万 + 6月賞与 30万 → G列の6月セルに **55万** と記入

## 4. 抽出方法（CC でやるとき）

### 推奨：CC 本体の multimodal PDF Read

1. 対象 PDF を `Read` ツールで直接読む（画像PDFでもページ画像として認識される）
2. ページごとに「氏名・雇用形態・各月の課税支給合計」を抽出
3. openpyxl でテンプレに転記
4. 全件転記後に **年間合計を逆算してOCR誤読チェック**

### 非推奨：サブエージェント並列抽出

過去事例 (`feedback_subagent_extraction_limit.md`)：
- サブエージェントへ「PDFを抽出して」と渡すと、Read経由のループ抽出になり **本番（messages.create 直送）より精度が落ちる**
- 同じ案件で本番経路と差分が出る
- 大量PDFの一括抽出は速いが、最終的に CC 本体で目視照合が必要

→ **5名以下なら CC 本体で全件 Read。10名以上の大規模なら、過去JSON流用＋抜き取り目視で検証する**。

### 既存 JSON を流用するとき

`_backups/test_wage_ledgers/<案件名>/_extract/path_b_subagent_v3.json` が残っている案件は、過去にサブエージェント抽出した結果。流用する場合は：

1. JSON を読み込んで、雇用形態を `2.` のルールで正規化
2. 全員分の年間合計を表示して、ユーザーに **「最大3名の数値が原本と合うか目視確認」** を依頼
3. 12月分が `None` の社員は「中途入退社」扱いで R216 から自動除外される（仕様）

### OCR テキストキャッシュ

`_backups/test_wage_ledgers/<案件名>/_ocr/*.txt` に Document AI の OCR 結果がある案件は、それを補助情報に使える（ただしレイアウト崩れあり、構造化は困難）。

## 6. Drive アップロード手順

### Drive 階層

```
[補助金 親フォルダ]
└── 01_クラフトバンク（顧客フォルダ）
    └── 04.株式会社後藤造園（案件フォルダ）  ← ここに置く
        ├── ヒアリングシート2026_インボイス法人.xlsx
        ├── 履歴事項全部証明書_*.pdf
        ├── 令和7年決算書.pdf
        ├── 納税証明書*.pdf
        └── 株式会社後藤造園_賃金台帳一覧.xlsx  ← 追加するファイル
```

### アップロード方法（2択）

#### A. ブラウザで手動アップ（推奨・確実）

1. Drive で対象の案件フォルダを開く
2. 変換した Excel をドラッグ＆ドロップ
3. Streamlit を再読み込み → 「ファイル判別結果」で「賃金台帳」が緑になることを確認

#### B. スクリプト経由（既存 `hojokin.google_drive.DriveClient` を使う）

```python
from pathlib import Path
from dotenv import load_dotenv
load_dotenv()
from hojokin.google_drive import DriveClient

cli = DriveClient('credentials/service_account.json')
# 案件フォルダ ID を Streamlit の URL 等から取得 or list_files で探索
folder_id = '<案件フォルダID>'
cli.upload_file(Path('株式会社後藤造園_賃金台帳一覧.xlsx'), folder_id)
```

ローカルから Drive 操作するときは [`credentials/service_account.json`](../credentials/) と `.env` の `GOOGLE_CREDENTIALS_PATH` / `DRIVE_PARENT_FOLDER_ID` が必要。
**サービスアカウントに対象フォルダの編集権限が付与されていないとアップロードできない**（権限不足のときは無言で 0 件になることがある）。

## 7. 変換後の検証

### 7.1 セルフチェック

| チェック項目 | 方法 |
|---|---|
| 氏名の漢字が原本と一致 | サンプル3名を目視 |
| 役員に「役員」ラベルが付いている | 雇用形態列をフィルタ |
| 全員12ヶ月の値が入っている（中途者を除く） | 各行の合計を出して 0 がある月を確認 |
| 年間合計が決算書の販管費＋製造原価の人件費と概ね一致 | 大幅乖離なら抽出ミス疑い |
| 賞与月（6月/12月など）の金額が他月の2倍以上 | 賞与漏れの逆チェック |

### 7.2 ツールに通して検算

ローカルで run.py を回す or Streamlit Cloud にアップして「給与計算のみ」モードで実行 → 出力 `{会社名}_給与支給総額計算.xlsx` を確認：

- シート1「給与支給総額計算」の R216 値（販管費＋製造原価の人件費 内訳付き）
- シート2「従業員別明細」の人数・氏名・年間合計が転記元と一致
- 「算定根拠」シートで役員除外の対象人数が想定通り

## 8. トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| Streamlit で「必須ファイルが不足しています: 賃金台帳」 | Drive 上にファイル無し or 命名がマーカーから外れた | ファイル名末尾を `_賃金台帳.xlsx` または `賃金台帳一覧.xlsx` に |
| 役員が R216 に算入されている | 雇用形態が「代表取締役」等のまま | `2.` の正規化ルールで「役員」に置換 |
| 中途者まで R216 に算入された | 退社月以降に 0 を入れた | 0 ではなく **空欄** にする |
| ヘッダーが認識されない | 「氏名」「1月」等の表記揺れ | 半角全角・スペース注意。テンプレを **コピーして使う** |
| 数字が文字列扱いになる | セル書式が「文字列」 | セル書式を「標準」または「数値」に |

ヘッダー別名辞書は [`hojokin/wage_reader.py:122-133`](../hojokin/wage_reader.py#L122) で定義。新フォーマットを足したくなったらここを編集。

## 9. 案件ごとの典型パターン

過去サンプル（`_backups/test_wage_ledgers/` 配下）で観測したPDFパターン：

| パターン | 例 | 抽出難易度 |
|---|---|---|
| **1人1ページの個人台帳型** | 後藤造園 R5/R6/R7 給与.pdf | 中（ページ数=人数。CC本体で1ページずつ）|
| **全社員1表型（月別大判）** | クリーンニイガタ | 低（テキストPDF）〜高（スキャン画像） |
| **2ブロック印字型**（一般＋役員別） | 医療法人系 | 中（ブロック判定が必要、知識ベース参照）|
| **従業員別Excel/CSV分割** | 黒石歯科医院 | 低（既に構造化済み、転記のみ） |
| **テキストPDF年度別** | Kデザイン | 低（PyMuPDFで普通に抽出可） |

判断材料：
- PDFが画像か否か → `python -c "import fitz; doc=fitz.open('x.pdf'); print(len(doc[0].get_text('text')))"`
- 0 や数十文字なら画像PDF → CC の Read（multimodal）で対応

## 付録：サンプル変換結果の構成例

リポジトリ外の `_backups/test_wage_ledgers/<案件名>/<会社名>_賃金台帳一覧.xlsx`（gitignore 配下）に、過去案件のサンプル変換結果を残している場合がある。新規案件で似たレイアウトの賃金台帳を変換するときの参考になる。

典型構成（造園・建設業の同族会社の例）：
- 22名（役員5名 + 一般従業員17名）
- 元データ：`_extract/path_b_subagent_v3.json`（過去サブエージェント抽出を流用）
- 役員ラベル正規化済（「代表取締役」「取締役」→「役員」）
- **数値の正確性は未検証**：本格運用前に PDF 原本と3名分は目視照合する
- 暦年（1〜12月）で集計されたデータをそのまま転記しているので、**決算月が暦年区切りでない場合は対象12ヶ月を再合成する必要あり**（例：8月決算なら前年9月〜当年8月の組み合わせ）
