## 0. このファイルの読み方（出典ラベル）

補助金の知識は「人から聞いた話」と「一次資料に書いてある話」が混ざりやすい。混ざると、聞き覚えを根拠に顧客へ案内して事故る。そこで**全項目にラベルを付ける**。

| ラベル | 意味 | 使い方 |
|---|---|---|
| `[公式]` | 一次資料（公募要領・交付規程・公式マニュアル・公式サイト）で確認済み | 資料名と該当箇所、確認日を併記する |
| `[帰結]` | 一次資料の複数の記述から論理的に導かれるが、その言葉では書かれていない | 何と何から導いたかを書く |
| `[運用]` | 社内の運用・SLA。制度ではない | 決めた会議へリンクする |
| `[経験則]` | 社内の経験・伝聞。一次根拠なし | 誰が・いつ言ったかを書く。**顧客案内の根拠にしない** |
| `[要確認]` | 裏取り待ち | 何を見れば確定するかを書く |

### 昇格ルール（会議で聞いた話をどう扱うか）

1. 会議で出た制度の話は、まず**議事録に `[経験則]` として残す**（誰の発言かとセットで）。
2. 一次資料で裏が取れたものだけ、このファイルに `[公式]` として昇格させ、出典と確認日を書く。
3. 裏が取れなかったが実務上重要なものは、このファイルに `[経験則]` または `[要確認]` のまま載せる。**消さない**。消すと同じ話が次の会議でまた出る。
4. 一次資料と食い違ったものは、**食い違いごと記録する**（[§16](#16-会議発言と一次情報の突合ログ)）。「誰が間違えたか」ではなく「どこが間違えやすいか」の記録として使う。

## 5. 賃上げの「要件」と「加点」

`[公式]` 出典: 通常枠公募要領（第7回〜版）印刷p.9〜12（テ）（ト）（ナ）（ニ）【補足１】、p.23〜24（加点5〜8）、p.30（辞退）。インボイス対応類型は同（第7回〜版）印刷p.8〜9（ツ）（テ）。

第7次以降の全4原本では給与0〜3年度目の計画入力が必要。率の達成義務・表明義務・任意加点の有無とは別に確認する。通常枠は公式FAQ No.39、他枠は申請マニュアルp.89・91の入力指示に基づく。0年度目は交付申請日を含む事業年度、1〜3年度目はその翌事業年度からの3年（交付申請マニュアル 11/2版 p.86）。

| 通常枠・過去交付 | 1年後給与 | 年平均給与 | その他 |
|---|---|---|---|
| 150万円未満・過去なし | 必須追加なし | 必須なし | 任意の賃上げ加点を希望する場合は別条件 |
| 150万円未満・過去あり | 3.5%以上 | 3.5%以上 | 表明（最賃の要件はない） |
| 150万円以上・過去なし | 3%以上 | 3%以上 | 最賃＋30円等、表明 |
| 150万円以上・過去あり | 3.5%以上 | 3.5%以上 | 最賃＋30円等、表明 |

給与の過去交付は2022〜2025、生産性4%の判定は2023〜2025の指定枠で別。任意賃上げ加点は通常枠150万円未満・インボイス・セキュリティでは最賃＋30円が基本で＋50円が更なる加点、通常枠150万円以上では＋50円。申請必須の最賃要件とは区別する。インボイス・セキュリティも過去交付ありの層が原則1年後・年平均3.5%。電子取引の中小企業以外の5%層は現行4原本の対象外。

給与0年度目は当期見込み。1年後・年平均は1人当たりで検査し、全件3%固定や全件3.5%化をしない。過去歴・表明・適用除外を推測で埋めない。適用除外は法人名ではなく要領の法令上の事業内容で判断する。

### 未達の場合の返還

- 新設の給与1年後要件は達成判定があるが、その未達だけによる返還は除外される。申請要件・報告義務は残る。
- 給与の年平均要件は3年度目で判定し、全額返還となる場合がある。免除は付加価値額非増加かつ3年の過半数が営業赤字の場合、天災等で確認する。
- 事業場内最低賃金の要件（地域別最低賃金＋30円以上）が**申請の必須要件なのは通常枠150万円以上（（ト）（ナ））だけ**。通常枠150万円未満（過去交付ありを含む）、インボイス枠、セキュリティ枠の申請要件には最賃の要件がなく、最賃未達による返還もない。任意の賃上げ加点で最賃の条件を選んで達成できなかった場合は、返還ではなく減点（[§4](#4-減点項目)【補足４】）。
- 通常枠150万円以上の最賃要件の未達は、効果報告時の直近月で判定し、未達となった年度により全額／2/3／1/3を返還（判定に使う地域別最低賃金は効果報告期間の開始時のもの）。一度返還すると、翌年度以降の効果報告と未達の返還は求められない。付加価値額の年平均成長率が1.5%に達しない場合や天災等は免除で、給与の免除条件とは別（印刷p.10〜11）。
- 賃上げ要件の未達による返還額は補助金交付額が上限で、加算金・延滞金は含まない（印刷p.10）。
- 未表明・虚偽・未報告・未利用等は取消・返還の別経路。1年後要件の返還除外を免責として案内しない。
- **効果報告前・賃上げ要件の達成判定前に辞退した場合**（ITツールの解約・利用停止、廃業・倒産・事業譲渡など）、賃上げが必須要件の事業者（適用除外（ニ）を除く）は賃上げ要件が未達成とみなされ**全額返還**となる。辞退に伴う返還では、補助金受領日から納付日までの日数に応じた加算金（交付規程第29条、年10.95%）がかかる場合がある（印刷p.30、[§12](#12-事業承継廃業解約後年手続き)）。
- 0年度目の見込みと効果報告時の比較基準の関係は未確定。申請値・確定実績・人数・根拠・方式を別に保存し、後年判定は今回は保留する。

## 6. 補助対象者／対象外

### 中小企業・小規模事業者の定義 `[公式]` 公式サイト「申請対象者」

業種別に「資本金」または「従業員数」のいずれかを満たせば対象（両方満たす必要はない）。

| 業種 | 資本金 | 従業員数 |
|---|---|---|
| 製造業・建設業・運輸業 | 3億円以下 | 300人以下 |
| 卸売業 | 1億円以下 | 100人以下 |
| サービス業（ソフトウェア業・情報処理サービス業を除く） | 5,000万円以下 | 100人以下 |
| 小売業 | 5,000万円以下 | 50人以下 |
| ソフトウェア業・情報処理サービス業 | 3億円以下 | 300人以下 |

- 小規模事業者: 商業・サービス業（宿泊業・娯楽業を除く）は従業員5人以下、その他は20人以下。
- 医療法人・社会福祉法人・学校法人・商工会等の特定法人は、業種分類の従業員規模以下の場合のみ対象（小規模事業者には該当しない）。
- `[公式]` 財団法人（一般・公益）、社団法人（一般・公益）、特定非営利活動法人も、主たる業種の従業員規模以下なら対象。

### 申請の対象外となる事業者（＝いわゆる「みなし大企業」） `[公式]` 通常枠公募要領（第7回〜版）印刷p.12「２－１－２」

**「みなし大企業」という語は公募要領には無い**。該当するのは以下。

1. 発行済株式の総数または出資価格の総額の **1/2以上を同一の大企業**が所有
2. 発行済株式の総数または出資価格の総額の **2/3以上を大企業**（複数可）が所有
3. **大企業の役員または職員を兼ねている者が役員総数の1/2以上**を占める
4. 発行済株式の総数または出資価格の総額を、1〜3に該当する中小企業が所有
5. 1〜3に該当する中小企業の役員または職員を兼ねている者が役員の全てを占める
6. 確定している（申告済みの）**直近過去3年分の各年・各事業年度の課税所得の年平均額が15億円超**

※「大企業」＝上記の中小企業・小規模事業者等の定義に当てはまらない、事業を営む者。ただし中小企業投資育成株式会社・投資事業有限責任組合は大企業として扱わない。

### みなし同一法人（グループで1社しか申請できない） `[公式]` 同 印刷p.12〜13

以下は「みなし同一法人」と認定され、**1社のみでしか申請が認められない**。補助金目的で主要株主や出資比率を変更して申請することも認められない。

1. 親会社が議決権の50%超を有する子会社が存在する場合（孫会社・ひ孫会社も同じ考え方）
2. **個人が複数の会社のそれぞれの議決権を50%超保有**する場合
   - ※配偶者・親子およびその他生計を同一にする者は全て同一の個人として扱う。**過去に交付決定を受けた個人事業主が設立した法人も同様の扱い**
3. 代表者および住所が同じ法人、主要株主および住所が同じ法人、実質的支配者が同じ法人

⚠️ 1.「対象外」と 2.「みなし同一法人」は**別のルール**。前者は申請できない、後者はグループで1社だけ申請できる。口語で「みなし大企業」と言うとき、どちらの話かを確認する。

### その他の対象外 `[公式]` 同 印刷p.13

IT導入支援事業者（構成員を含む）に登録している／しようとする事業者（**補助事業者との重複不可**。代表者・役員の重複も不可。昨年度以前のIT導入補助金での登録は除く）／補助金交付等停止措置中／風俗営業（旅館業法の許可を受けた旅館業を除く）／過去1年に労働関係法令違反で送検処分／反社／**宗教法人**／法人格のない任意団体／他の補助金で不正行為／事務局が不適当と判断する者。

## 7. 交付申請に必要な書類 `[公式]` 通常枠公募要領（第7回〜版）印刷p.18〜19

**代替書類は一切認められない。**

法人（3種）:

| 用途 | 書類 |
|---|---|
| 実在を証明 | 履歴事項全部証明書（**発行から3か月以内**） |
| 事業実態を確認 | 税務署で発行された**直近分の法人税の納税証明書（「その1」または「その2」）** |
| 財務状況を確認 | **直近分の貸借対照表および損益計算書** |

個人事業主（4種）:

| 用途 | 書類 |
|---|---|
| 本人を確認 | 運転免許証（有効期限内）／運転経歴証明書／住民票（発行から3か月以内） |
| 事業実態を確認 | ① 直近分の所得税の納税証明書（「その1」または「その2」）　② 税務署が受領した直近分の確定申告書の控え |
| 財務状況を確認 | 所得税の青色申告決算書または収支内訳書 |

注意点:

- 納税証明書は**領収書ではなく**「その1」「その2」。税目は法人税（個人は所得税）。
- 確定申告書は**令和7年（2025年）分**。やむを得ない事情がある場合は令和6年分も可。
- 確定申告書は税務署が受領したことが分かるもののみ。①第一表の控えに受付番号と受付日時が印字、②第一表の控え＋受信通知（メール詳細）、のいずれか。**税理士の印のみ**が押された書類は不可。
- 上記で受領確認できない場合は「第一表の控え」＋「同一年度の納税証明書（その2 所得金額用）」で充足できる。
- マイナンバー・保険者番号等が記載されている場合は黒塗りにする。
- 補助率2/3の適用・加点①を受ける場合は「賃金状況報告シート（補助率引上げ・加点措置①用）」、加点②を受ける場合は「賃金状況報告シート（加点措置②用）」、IT戦略ナビwithの加点を受ける場合はIT戦略マップのPDFを追加で提出する（いずれも第7回〜用の様式を使う）。

### 法人成り（個人事業主→法人）1年目は申請できるか `[帰結]`

**実質できない。** 公募要領に「法人化後1年目は申請不可」という明文は無いが、法人には**直近分の法人税の納税証明書**と**直近分の貸借対照表・損益計算書**が必須で、代替書類は認められない。設立して1期も決算を迎えていない法人はこれらを用意できない。

→ 実務上の帰結: **法人成りを予定している顧客は、個人事業主のうちに申請したほうがよい。** ただし [§6](#みなし同一法人グループで1社しか申請できない) のとおり「過去に交付決定を受けた個人事業主が設立した法人」はみなし同一法人として扱われる点に注意。

## 8. 補助対象経費とITツールの分類 `[公式]` 通常枠公募要領（第7回〜版）印刷p.14〜15

- 補助対象経費は、IT導入支援事業者が提供し**あらかじめ事務局に登録されたITツール**の導入費用。
- 大分類Ⅰ「ソフトウェア」／Ⅱ「オプション」／Ⅲ「役務」の3分類。
- **カテゴリー1（ソフトウェア）は、買取形式および月額・年額（サブスク等）とも最大2年分の費用が補助対象。**
- 補助対象外: 補助事業者の顧客が実質負担する費用がITツール代金に含まれるもの（＝補助事業者にとっての売上原価に相当すると事務局が判断するもの）等。

### 業務プロセスと「汎用プロセス」 `[公式]` 同 印刷p.15

| 区分 | Pコード | プロセス名 |
|---|---|---|
| 共通プロセス | 共P-01〜05 | 顧客対応・販売支援／決済・債権債務・資金回収管理／供給・在庫・物流／会計・財務・経営／総務・人事・給与・労務・教育訓練・法務・情シス・統合業務 |
| 業種特化型プロセス | 各業種P-06 | 業種固有プロセス |
| 汎用プロセス | 汎P-07 | 汎用・自動化・分析ツール |

> `[公式]` 「汎用プロセス」のみを保有するITツールは、**単独では交付申請不可**だが、「共P-01」〜「各業種P-06」と組み合わせて交付申請することで、**1プロセスとしてカウントされ**交付申請が可能となる。

→ 汎P-07 の例: 文書作成ワープロソフト、表計算、簡易DB、プレゼンツール、メールソフト、文書証憑管理、OCR、PDF、ペーパーレス化ツール等。

### 契約年数と申請額 `[運用]` / `[帰結]`

- クラウド利用費・サービス利用料は**最大2年分**まで。
- 申請ポータルでは、**登録されたITツールの契約年数を超える入力ができない**。本体1年・オプション2年のような見積が来ると入力エラーになる。
  - `[経験則]` 対処は「オプションを個数として計上する」など。見積段階で年数をそろえてもらうのが本筋。
  - `[運用]` 見積を受け取った時点で「本体とオプションの契約年数が一致しているか」を確認する（2026-07-27 MTG）。

## 9. IT導入支援事業者とコンソーシアム `[公式]` IT導入支援事業者 登録要領 p.6-7

登録形態は「法人（単独）」と「コンソーシアム」の2種類。

- **コンソーシアム** ＝ 幹事社1社＋構成員1者以上。幹事社に登録できるのは**法人のみ**。個人事業主は**構成員としてのみ**登録できる。
- > `[公式]` 補助事業において、補助対象となるITツールの**契約、導入、代金の請求・受領について複数の事業者が関与する場合は、コンソーシアムを形成する必要がある**。

  → これが「別々の請求書でも1つの申請として扱える」の根拠。逆に言うと、複数事業者が関与するなら**コンソーシアム形成は任意ではなく必須**。
- 料金収納代行事業者（クレジットカード決済を除く）を介して代金を受け取る場合は、その事業者を構成員として登録する必要がある。
- > `[公式]` セキュリティ対策推進枠において「サイバーセキュリティお助け隊サービス」をコンソーシアムで取り扱う場合、**幹事社または構成員が「サイバーセキュリティお助け隊サービスリスト」に掲載された提供事業者または再販協力会社である必要がある**。

  → 再販契約を持たない代理店は、このサービスを売れない。**リストに載っている提供事業者か再販協力会社を、幹事社か構成員としてコンソーシアムに入れる**必要がある。
- 登録解除・登録取消でコンソーシアムの要件を満たさなくなった場合、幹事社・構成員の登録やITツールの登録が取り消される場合がある。

## 10. サイバーセキュリティお助け隊サービスと加点

- `[公式]` 対象サービスは、独立行政法人情報処理推進機構（IPA）が制定した「サイバーセキュリティお助け隊サービス基準」を充足することを審査登録機関が確認済みの **「サイバーセキュリティお助け隊サービスリスト」掲載サービス**に限る。かつ IT導入支援事業者により登録されたものであること。
- `[公式]` 加点になるのは **通常枠とインボイス対応類型のみ**（[§3](#3-加点項目マトリクス)）。公募要領の審査項目にも「国の推進するセキュリティサービスを選定しているか」が政策面の審査項目として明記されている。
- `[公式]` **申請枠は変わらない。** 通常枠・インボイス枠として申請したうえで、ITツールとしてセキュリティサービスを追加する形。「セキュリティ対策推進枠で申請する」のはその枠単独で申請する場合の話。
- `[経験則]` 加点を取りに行くだけなら**1台分の契約でよい**（本来は全PCに入れないと防御としては意味がない）。実質負担は補助率1/2なら半額。「あと一息」の案件で後押しに使う。加点を付けても不採択になる例はある（2026-07-27 MTG）。
- `[要確認]` 申請上の最低台数要件が制度側にあるかは未確認。公募要領に台数の定めは見つかっていない。

## 11. デジタル化セカンドオピニオン `[公式]` セカンドオピニオンマニュアル（申請者向け・2026/6/12策定、2026/9/29改訂）、通常枠公募要領（第7回〜版）印刷p.23 項目4

**対象は通常枠のみ。** 第3回公募回より加点措置を実施。

### 加点条件（全て満たすこと）

- 「通常枠」の申請者であること
- 事務局が定める第三者である「確認者」と面談を実施すること
- **経営者（代表取締役、個人事業主の場合は本人）が対応すること**
  - ※ IT導入支援事業者、ITベンダー等の**面談同席は認められていない**
  - ※ デジタル化の責任者等、**社内関係者の同席は可能**
- 面談中は**カメラを有効化**していること
- 面談の**録画について承諾**していること

### 注意事項

- 通常枠以外の申請枠・類型は加点対象外
- 事務局が定める所定のシステム外で確認者と面談した場合は加点対象外
- 経営者が面談に出席できない場合、面談はキャンセル扱いとなり加点対象外
- カメラ未有効化・録画未承諾は加点対象外
- **確認者からの評価は申請者に通知されない**
- **採択／不採択理由の開示は行っていない**（公募要領 第7回〜版 印刷p.21 では「不採択理由については、事務局から通知する事項以外は開示しない」）

### 実施期限と提出の順番

- `[公式]` **確認者との面談が完了してから交付申請を提出する**。公募要領の加点条件は「交付申請時点までに、デジタル化セカンドオピニオンの取組みを実施していること。※確認者との面談が完了したうえで交付申請を提出すること。」（通常枠公募要領 第7回〜版 印刷p.23 項目4）。面談の前に交付申請を出すと、加点を受けられない。
- `[公式]` マニュアル p.7 は「申請する募集回の申請締め切りまでに面談を実施することが要件」と書いているが、同 p.8 の流れも「面談実施完了 → 交付申請へ」の順。締切までに面談すればよいという意味ではなく、面談を終えてから交付申請を出す。
- `[公式]` **面談日程の確定後のキャンセルは原則不可**。やむを得ずキャンセルする場合は、日程調整結果のメールに記載の連絡先から必ず事務局に連絡する（マニュアル p.25・27・29）。確認者に直接キャンセルを打診しない。
- `[公式]` 交付申請の締切2週間前は予約が混みあうおそれがある（マニュアル p.18）。社内の予約送信の目安は締切 D-21（`[運用]`。[業務フロー全体マップ §5](補助金_業務フロー全体マップ.md)）。

### 評価軸（確認者の評価観点）

**評価軸1：取組内容の整合性・論理性**

- 現状課題と導入ツールがつながっているか／導入目的が明確か／将来目指す姿と今回の申請内容が矛盾していないか／スケジュールや体制に現実性があるか／自社に適した取り組みか考えられているか／説明内容に大きな矛盾がないか
- ※ **大枠の説明は経営者が行うこと。確認者からの追加質問や詳細な内容説明は、社内の担当者等が説明しても構わない。**

**評価軸2：経営者の理解度・意欲**

- 経営者が自らの言葉で説明できているか／計画内容を理解しているか／**現場任せ・ベンダー任せになっていないか**／導入後も継続的に関与する意思があるか
- **（あれば望ましい）組織としてAIも積極的に活用していく姿勢が見られたか**

> 最後の「AIも積極的に活用していく姿勢」は、マニュアルの初版（2026/6/12策定）からある観点。改訂履歴（p.32）では、7/22はキャンセルに関する記載の修正、9/29は画面イメージと日程確定メールの修正で、評価軸の変更はない（以前この欄に「7/22改訂で追加」と書いていたのは誤り）。配布物テンプレには 2026-08-10 に反映済み（`06_入力整理プロンプト.md` の評価観点、`08`/`09` の面談回答例）。

社内の運用フロー・配布物・プロンプト体系は [業務フロー全体マップ §5](補助金_業務フロー全体マップ.md) と `docs/セカンドオピニオン加点/` を参照。

## 12. 事業承継・廃業・解約（後年手続き） `[公式]` 後年手続きマニュアル（2026/7/24策定、9/4・11/5改訂）

「後年手続き」＝ 以下の場合に**事務局宛に辞退届を提出**する手続き。

- 補助金交付後に、導入したITツールを**一部でも解約・利用停止**した場合
  - 販売形態が「買取」: 交付規程第31条第3項に規定する期間未満での解約・利用中止
  - 販売形態が「サブスク」: **利用期間満了前**での解約・利用中止
  - ※ サブスクで利用期間を満了し、その後継続して利用しない場合は**辞退届不要**（ただし効果報告は必要）
- **廃業・倒産・事業廃止・事業譲渡・吸収合併等**により、補助事業を取りやめた場合

辞退届の提出後は、事由に応じて「交付決定の取消し」「財産処分」「経緯報告」「賃上げ目標未達」に伴う手続きが発生する。交付規程第27条・第28条・第31条に基づき、交付された補助金の**全額あるいは一部の返還**が発生しうる。

- `[公式]` **賃上げが必須要件の申請で、効果報告前・賃上げ要件の達成判定前に辞退すると、賃上げ要件が未達成とみなされ全額返還**（後年手続きマニュアル p.6、通常枠公募要領 第7回〜版 印刷p.30）。1年後要件の未達だけでは返還されないこととは別の話なので、解約・廃業の相談では必ず伝える。
- `[公式]` 交付規程第27条に基づく返還では、補助金受領日から納付日までの日数に応じた加算金（第29条、年10.95%）が必要になる場合があり、納付が遅れると延滞金（第30条）も発生する（後年手続きマニュアル p.6）。
- `[公式]` ITツールの導入日から1年未満、または実績報告で提出した利用期間未満で解約・利用中止すると、複数ツールの一部であっても交付決定の取消しとなる場合がある（同 p.6）。
- 11/5改訂は処分予定対価額の記入方法、9/4改訂は辞退証憑の説明の修正で、上記の扱いは変わっていない（改訂履歴 p.59）。

- `[経験則]` 事業承継（会社ごと承継・売却）の場合は補助金もそのまま承継できる可能性があるが、**事業だけの売却＝会社がなくなる形**は承継できず辞退が必要。いずれも**個別対応なので事務局へ照会する**（2026-07-27 MTG）。
- `[運用]` 事務局照会は窓口担当に一本化する。

## 17. このファイルの更新のしかた

### 回すタイミング

- 各申請回の頭
- 地域別最低賃金の改定時（改定額と発効日は都道府県ごとに異なり、秋から翌年春に分かれる。詳細は [業務フロー全体マップ §7](補助金_業務フロー全体マップ.md)）

### 手順

（管理者が開発リポジトリで行う。配布版にはスクリプトが入っていないので、気づいた点は管理者に伝える）

```bash
python scripts/check_seido_freshness.py
```

1. 公式ダウンロードページの「資料名 → 更新日」を取得し、[制度一次情報/sources.json](制度一次情報/sources.json) と突合して**変わった資料だけ**を出す。差分があれば exit 1。
2. 変わった資料について、`depends` に挙がっている自社ドキュメントの該当節を読み直して直す。
3. 直したら sources.json の `official_updated` と `last_verified` を更新する（`--update` で一括更新できる）。ただし `--update` は台帳を公式ページの一覧から作り直すため、手で書いた確認記録（`verified`・`sha256`・`applicable_rounds`・`verification_note` など）と、ダウンロードページ以外で管理している資料（FAQ）の記録が消える。実行前に控えを取り、実行後に戻す。
4. このファイルの「最終更新」と [§15](#15-出典鮮度表) の一次確認日を上げる。
