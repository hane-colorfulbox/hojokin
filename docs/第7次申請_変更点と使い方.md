# 第7次以降の申請：変更点と使い方

更新日：2026-11-04（公式資料の再照合・訂正版）。デジタル化・AI導入補助金2026の社内申請支援用。

この案内は第7次以降を扱う現役の入口です。第1〜6次の提出済み案件を訂正・再出力するときは旧版を保持します。新旧の資料を同名上書きで入れ替えず、公募回と申請IDを確認してください。

公式で判断できる定義と、個別事実・社内調整・保留を分けた配布用資料は [公式資料で判断できることと確認の範囲](第7次申請_公式資料で判断できることと確認の範囲.md) を参照してください。一般的な制度定義の一括再照会は不要です。

## 1. 最初に確定すること

- 公募回、元申請の訂正か新規再申請か、実際の申請予定日・月、法人／個人、枠・類型。
- 過去の交付決定の年度・枠、今回の申請額、賃上げ加点の希望、適用除外の根拠。
- 給与の0年度目と、労働生産性の基準となる前事業年度。
- 事業場所在地、従業員ごとの勤務地の違い、見込み値の根拠・確認者・確認日。

申請月は締切月ではありません。7次でも11月に提出すれば直近月は10月、12月1日に提出すれば直近月は11月です。申請月を変えたら台帳・判定・様式も見直します。

## 2. 新旧の変更点

| 項目 | 第1〜6次 | 第7次以降 |
|---|---|---|
| 加点①・通常枠補助率引上げの判定期間 | 2024/10〜2025/9 | 2025/10〜2026/9 |
| 加点①の上限 | 令和7年度改定の地域別最賃未満 | 令和8年度改定の地域別最賃未満 |
| 加点①の人数・月数 | 30%以上の月が3か月以上 | 同じ。3か月は連続でなくてよい |
| 加点② | 2025/7の事業場内最賃から直近月まで63円以上 | 2026/6から直近月まで55円以上 |
| 給与の入力年度 | 旧版の申請・算定方式を維持 | 申請日の属する事業年度を0年度目とし、0〜3年度目の計画値 |
| 給与0年度目の性質 | 元申請の根拠を維持 | 見込み値。窓口担当による事務局照会回答をユーザーが提示済み |
| 給与の1年後要件 | 旧版の条件 | 賃上げ必須対象に3%／過去交付あり3.5%が追加 |

地域別最賃の法定発効日は都道府県ごとに異なります。加点①の固定上限、過去月の法定下限、申請画面の表示額を同じ「最新値」で処理しないでください。東京・神奈川・大阪の令和8年度改定差は54円のため、法定最賃に合わせただけでは加点②の55円に届きません。

## 3. 給与0年度目は見込み値として扱う

0年度目が見込み値であることは確認済みです。前期確定実績のラベルだけを当期へ変える処理や、未到来月を0円にする処理はしません。

入力するものは、対象年度、確認済みの見込み給与総額、同じ範囲の対象人数（FTE）、算定根拠、確認状況です。0〜3年度目で人数が変わる計画は、各年の給与総額とFTEを入力して1人当たりで検算します。担当者が人数一定を確認した計画に限り、必要率に応じた計画案を作れます。

実績月・残期間予算・賞与・昇給等は根拠を残し、不明な将来値をAIが創作しません。対象者・人数換算の一般定義は公募要領p.7〜8と申請マニュアルp.86等に従います。支給月・就業時間など案件の事実が不明な場合だけ確認し、その数値の確定を保留します。回収票・ヒアリングの最終形は社内運用の調整です。

### 労働生産性と給与の年度を分ける

| 2026年11月申請の例 | 給与0年度目 | 生産性の基準となる前事業年度 |
|---|---|---|
| 12月決算 | 2026/1〜12 | 2025/1〜12 |
| 3月決算 | 2026/4〜2027/3 | 2025/4〜2026/3 |
| 9月決算 | 2026/10〜2027/9 | 2025/10〜2026/9 |

| 指標 | 0年度目 | 1年度目 | 2年度目 | 3年度目 |
|---|---|---|---|---|
| 生産性 | 前事業年度の実績 | 翌事業年度の計画 | 翌々事業年度の計画 | 申請当年度から3期後の計画 |
| 給与 | 申請当年度の見込み | 翌事業年度の計画 | 翌々事業年度の計画 | 申請当年度から3期後の計画 |

生産性の基準は前事業年度実績、給与0年度目は申請当年度見込みです。計画1〜3年度目は両方とも申請翌事業年度からの同じ期間です。前版の「生産性1年度目＝申請当年度」「給与と計画年度が1年ずれる」は誤りで、公式マニュアルp.88に基づき訂正しました。

給与の対象期を変えても、生産性の損益・年間労働時間を当期へずらしません。R215/R216は既存集計値・セルの呼称で、給与0年度目計画と自動的に同じ値にはなりません。

第7次以降の通常枠では、生産性の前事業年度実績に加え、生産性1年度目＝申請翌事業年度から3年度目＝申請当年度から3期後までの確認済み計画も必要です。各年の営業利益・人件費・減価償却費・総労働時間、算定根拠、確認状態を回収します。過去2023〜2025の指定枠の交付歴を確認し、初年度と3年間の年平均の要件が3%か4%かを分岐します。給与0年度目の見込みとは別に確認してください。

生産性計画は、任意の賃上げ加点を使わない通常枠150万円未満でも必要です。未確認の計画を自動補完して提出用数値にしません。旧原本の生産性B42には「初年度3%かつ3年目の前年比9%」をOKにする誤式があるため、そのOK表示だけを根拠にしません。第7次用では未確認のOK表示を無効化し、確認済み入力から初年度・3年平均を検算した結果を使います。旧案件への修正が必要なら、元成果物を保存して差分と理由を記録します。

0年度目の見込み値を、後日の効果報告でそのまま基準として扱うかは未確定です。この版は申請向けの入力・根拠保存に対応し、後年の達成判定方法は実装・断定しません。

## 4. 必須要件と任意加点を分ける

| 通常枠の条件 | 給与1年後 | 給与年平均 | その他の主な申請要件 |
|---|---|---|---|
| 150万円未満・過去交付なし | 申請必須の率の追加なし | 必須の率なし | 給与0〜3年度目の計画入力は必要。任意加点は別条件 |
| 150万円未満・過去交付あり | 3.5%以上 | 3.5%以上 | 従業員への表明 |
| 150万円以上・過去交付なし | 3%以上 | 3%以上 | 事業場内最賃＋30円等、表明 |
| 150万円以上・過去交付あり | 3.5%以上 | 3.5%以上 | 事業場内最賃＋30円等、表明 |

150万円ちょうどは「以上」です。給与要件の過去交付はIT導入補助金2022〜2025。労働生産性4%の対象は2023〜2025の指定枠なので、同じ有無フラグを使いません。

インボイス2類型・セキュリティは、原則として過去交付ありの層に1年後・年平均3.5%と表明が必要です。電子取引類型の中小企業・小規模事業者以外には5%の別条件があり、当社の4種類の申請原本の対象外です。医療・介護・福祉・学校等の適用除外は法人名だけで決めず、要領で指定された法令上の事業内容を確認します。

賃上げ計画加点は、通常150万円未満・インボイス・セキュリティでは最賃＋30円の基本加点と＋50円の更なる加点を区別します。通常150万円以上の任意加点は＋50円等です。加点①・②とも別条件です。任意加点を全枠必須にしません。IT戦略ナビwith、成長加速マッチング等も申請要件と任意加点を取り違えないでください。

通常枠FAQ No.39は、賃上げ要件適用外でも給与計画入力が必要と明記しています。インボイス・セキュリティも申請マニュアルp.89・91の入力指示に従い給与0〜3年度目の計画を準備します。率・表明・最賃の義務を全件に追加する意味ではありません。

## 5. 必要な資料を用途別に依頼する

| 用途 | 必要な範囲 |
|---|---|
| 給与0〜3年度目 | 当期見込みと申請翌期から3年の計画総額・同じ範囲の人数・根拠。回収票は社内運用案とし、既存票があれば重複を避ける |
| 労働生産性（通常枠） | 前事業年度の損益・人件費・減価償却費・年間労働時間に加え、生産性1年度目＝申請翌事業年度から3年度目＝申請当年度から3期後までの確認済み計画（営業利益・人件費・減価償却費・総労働時間・根拠・確認状態）。給与要件の有無と別に回収 |
| 加点① | 2025/10〜2026/9。月ごとの在籍者・基本給等の入力定義・所定労働時間 |
| 加点② | 2026/6と、実際の申請月の前月 |

「直近2期分」「最大2冊」だけでは範囲が特定できません。必要年月をすべて覆う資料を依頼してください。10月決算で12/1に申請する場合、2025/10〜2026/9と2026/11は3事業年度に分かれます。重複月は一度の回収でよいですが用途は残します。

## 6. 人数・賃金・申告事実の確認

- 給与指標の全月支給者FTE、小規模判定の「常時使用する従業員」の頭数、加点判定の月別在籍者は別の定義です。
- 役員は通常の給与指標では除外しますが、従業員を雇用していない法人には役員報酬・役員数へ読み替える例外があります。従業員ゼロを自動免除・0除算にしません。
- 基本給・所定労働時間・在籍が不明な人を、母数から黙って落としません。空欄を非在籍や0円と見なさず、必要な確認が残る間は判定を未確定にします。
- 加点の月別時間を省略できるのは、代表の所定労働時間が根拠付きで確認済みで、その人の各省略月に適用できる場合だけです。時給制・日給制・月変動者は各月の確認値を使います。173.33h・160h等の仮定値や、AIが計算した月次時間の中央値・平均値・他月値で欠損を補完して提出用判定を確定しません。
- 過去交付歴を一律「なし」、表明を一律「はい・口頭」と出力しません。確認済みの実施日・方法・対象計画を使います。
- 給与の課税対象経費と通常手当の定義は公式に記載済みです。課税通勤手当の算入は一般定義からの解釈と明示し、旧社内全額控除方式との不一致を制度未公表と混同しません。給与・法定最賃・公式加点様式の賃金定義は用途別に確認し、旧方式を新規申請へ無条件に流用しません。
- 複数県の事業場、派遣先と所在地の違い、月途中の法定発効、短期決算等を一つの県・一年の仮定で確定しません。対応範囲外はその案件だけ個別確認へ回します。

## 7. 加点台帳・公式様式の使い方

1. 公募回を指定し、旧版と第7次以降版の専用台帳・公式様式を選びます。専用台帳の基本給列と月別時間列の年月を照合します。
2. 台帳C3と指定した実申請月を一致させます。制度版AG2は第7次以降 `2026_rounds_7_plus`、公募回AG3は実際の回（8次なら8）にし、ドライバの公募回指定と照合します。申請月を延期したら直近月のデータを回収し直します。
3. ロスターと原本全ページを照合し、在籍確認済みの資料不足、勤務時点・在籍自体が不明、非在籍確認済みを区別します。勤務時点不明を「データなし」として母数から外しません。名簿・入退社日等で非在籍と確認した月だけ、基本給セルへ文字列「非在籍」を記入します。空欄や0円を非在籍と推定しません。未確定の母数や時給がある間は提出用確定出力をしません。
4. ①の選定3か月と申請月、②の基準月・直近月、全従業員・所在地を証憑と照合します。
5. 公式原本は保存し、出力側の入力欄だけを編集します。氏名欄の残存サンプルを空欄化したら、再読取でも空であることを確かめます。数式・マスタを独自に修正しません。
6. 画像・図形・保護・数式を保持したことを確認します。Excelの数式再計算と「すべて更新」による外部・元データ更新は別です。

第7次②の最賃表示等には原本由来の不整合があります。法定発効日は厚労省・各労働局の確定一覧で確認します（R7の福島2026/1/1、秋田2026/3/31、広島2025/11/1等が様式の表示と不一致）。判定の55円と表示用最賃を混同せず、疑義がある提出物は確認事項を明示してください。

## 8. 返還・取消しは条件別に案内する

| 条件 | 扱い |
|---|---|
| 新設の給与1年後要件未達 | 達成判定はあるが、その未達だけによる返還は除外。申請要件・報告義務は残る |
| 給与の年平均要件未達 | 3年度目で判定し全額返還となる場合がある。免除は付加価値額が増加せず、かつ3年の過半数が営業赤字の場合等で確認 |
| 事業場内最賃要件未達 | 未達年次により全額／2/3／1/3。免除は付加価値額年平均増加率1.5%未満等で、給与とは条件が異なる |
| 未表明・虚偽・未報告・未利用等 | 取消・返還の別経路がある。給与1年後の返還除外による免責ではない |

根拠は各枠の公募要領・交付規程です。通常枠では第7回以降公募要領の印刷p.10〜11・31、交付規程第27〜29条を参照してください。

## 9. 関連する案内の更新

- IT経営サポートセンターは第6回からの通常枠の任意加点。IT戦略ナビwithと同一項目の選択肢で、両方利用しても二重加点ではありません。申込・利用日と名義等の一致を確認します。
- セカンドオピニオンは要領に合わせ面談完了後に提出します。確定後のキャンセルは原則不可、やむを得ない連絡先は事務局です。確認者へキャンセルを打診する旧案内を使いません。
- 面談の予約文・回答例・給与計画・従業員表明は同じ年度・指標・率にします。「給与年率＋1.5%」や「年率3%＝3年9%」を一律の要件として使いません。
- 実績報告の従業員一覧は小規模判定用で、給与指標のFTEとは別です。
- 新設スマートレジ／POS類型は既存枠の年度更新と別の受付・事前着手・重複制限です。詳細確認前に既存4原本へ追加しません。

## 10. 更新版の確認と旧案件

- プラグインの版・元コミット・各スキルのビルド情報を確認します。開発版を直しただけで配布済みとは扱いません。
- 第7次版の案内・台帳・公式3様式と、必要なコード・参照資料が同じ配布物にあることを確認します。
- 元申請の訂正か新規再申請かを記録し、旧成果物・入力資料・算定方式を保存します。版不明のまま旧台帳を新窓として読み替えません。
- 実装・テスト済みと、本番反映・Drive原本更新・全員配信済みを分けて管理します。配布pushは管理者本人の既存運用です。

未確定事項は [確認待ち事項](第7次申請_確認待ち事項.md) に集約します。窓口・事務局への連絡は自動で行わず、必要な部分を担当者に渡します。

改訂版の画面・ローカルCLIを使う場合は [ツール入力手順](第7次申請_ツール入力手順.md)、原本管理者への引き渡しは [改訂内容と再取込手順](第7次原本_改訂内容と再取込手順.md) を参照してください。

回収情報・根拠保存の案内は社内の確認手順です。事務局がすべてを追加添付資料として指定したという意味ではありません。
